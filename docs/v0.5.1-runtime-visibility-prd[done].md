# v0.5.1 运行时可见集收窄 PRD

> 2026-11-25 · 状态：**已实现并验证（v0.5.1）**
> 上游：v0.5.0（`e31bac3f0145c4b4a6d68e938edd4ada5b7d459e`）
> 关联：GitHub #104，PR #105
> 定位：只在选档 `fits=false` 时，把已经算好的工具可见集接到真正发出的系统提示词和工具 schema。不改选档、不改窗口探测、不改预算比例。

功能提交：`39320ac`、`0086255`（PR #105 快进合入 `0086255`）。本文件只记录已落地的约定，不另开设计。

## 1. 为什么做

小窗口下的溢出不是因为没退到 `mini`（已经退了）。`mini` 核心大约 300 token，其余来自各档共用的动态块和全套工具 schema。v0.4.72 起 `visibleToolNames()` 只在 `/context` 做 dry-run，请求仍按全量发出，于是 `formatOverBudgetNotice` 按未收窄的开销提示「放不下」。

触发对照是窗口 116,000（来源 `models_api`），预算 `floor(116000 × 0.125) = 14,500`。本版把可见集接到运行时，让收窄后落入预算的请求不再按收窄前的估计报警。

## 2. 本版做了什么

只在 `selectPromptTier` 返回 `fits=false` 时收窄。`fits=true` 与今日相同。

1. **工具 schema**：请求只发送当前预算下最大可放下的优先级前缀。优先级表仍是 `TOOL_VISIBILITY_PRIORITY`，本版不改表。未入表的第一方工具排在已知之后、MCP 之前，按名字排序。MCP 永远在最后。
2. **动态块三项成组裁**：技能索引、记忆库（wiki）索引、目录树要么全留要么全裁。保留这三项仍能放下同一工具前缀时全留；只有裁掉它们才能多放工具、或才能让该前缀落入预算时，才三项一起裁。
3. **「## 工具」与可见集同构**：同步「可用工具：」名单，去掉已隐藏工具的说明行。
4. **超预算警告**：收窄后已落入预算则不再按收窄前的开销提示「放不下」。仍超预算则保留警告，文案不再建议在 settings 手写 `context_window`。

运行时硬底线：候选集里的 `read_file`、`edit_file`、`shell`、`shell_output` 不得拿掉。dry-run 的 `visibleToolNames()` 在「连 0 个工具都放不下」时仍可返回空集；运行时不把这一分支变成「四个也不发」。四个加上已裁的动态块仍超预算时，仍然发送这四个，并保留已改文案的警告。

目录树成组裁同时认「工作目录结构」和「工作根目录结构」。裁树停在仓库地图之前；仓库地图不随目录树消失。`/add-dir` 的额外工作根说明行本来就在目录树之前，继续保留。

`/context` 在运行时已收窄时展示实际发出的可见集，不再写「收窄尚未启用」。未收窄时仍是 dry-run。规划态套同一层 schema 过滤，并留下已经在候选集里的 `submit_plan` / `exit_plan_mode`。

## 3. 验收（受控夹具，不是现场 15,893 那次会话的回放）

窗口 116,000（`models_api`），预算 14,500。夹具关掉环境探测，带项目技能、记忆库索引、多根目录树和仓库地图。

- 收窄前 mini 全量估计 **16,397**。
- 收窄后估计 **11,400**，已落入 14,500，不再发出「系统提示词放不下预算」。
- 技能索引、记忆库索引、目录树（含「工作根目录结构」）三项都裁了。仓库地图与额外工作根仍在。
- 可见前缀是全部 21 个候选工具（裁动态块之后全套 schema 放得下）：`read_file`，`edit_file`，`shell`，`shell_output`，`list_dir`，`glob`，`grep`，`write_file`，`compact_ctx`，`web_fetch`，`web_search`，`use_skill`，`task`，`wiki_search`，`todo_write`，`remember`，`wiki_write`，`ask_user`，`send_message`，`list_peers`，`monitor`。
- 预算连 0 个工具都放不下时，请求仍含上述四个工具；「## 工具」名单与 schema 一致。
- `fits=true` 不收窄。
- `bash scripts/verify.sh` 为 `ALL GREEN`。

## 4. 本版没有做

- 不改三档核心提示词，不改 `selectPromptTier`，不改 `systemBudgetRatio`（仍是 0.125）。
- 不改上下文窗口探测优先级（`models_api` 覆盖手写 `context_window`）。不改 Magpie / 网关。不伪造更大的 `context_window`。
- 不把第一方工具改成 `tool_search` 式目录加按需装入。不改技能 / wiki / MCP「先索引、用时再加载」。MCP 目录短节不在三项成组裁里，本轮不裁。
- 不纳入新的裁剪面：output style、项目记忆文件、仓库地图、`/add-dir` 额外工作根说明行、`## 跨会话消息` 规则正文、自定义子代理索引、MCP 目录短节。超预算时它们仍计入开销。
- `## 交付物与提问` 整节保留。`## 环境` 只裁目录树，不裁整节。
- 条件工具何时进入请求维持现状：`lsp` 仍需 settings 打开；`run_js` 仍需 Code Mode，且非交互入口不进请求；`tool_search` 与 MCP schema 仍走延迟装入；`submit_plan` / `exit_plan_mode` 仍只在规划态出现。
- 不做 sandbox。不暗默改动已签点 #100 / #101 / #102 / #80。不做 Neon 重写。
- v0.5.0 的 Option B 与 S-A8 仍未做。状态条上的用量比例与 `max_output_tokens` 口径不是本版。
