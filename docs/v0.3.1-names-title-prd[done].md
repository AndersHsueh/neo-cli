## 0. 前置事实（已核实并已落地）

`--resume` 真续接已在 `eb19481` 完成：

- `--resume si-123` 沿用 si-123 的 session-id / 会话文件 / 信箱身份；
- running = `.alive` + pid 存活 + 心跳 ≤ `deadAfterMs`（默认 120s）；pid 死或心跳超时 → 立即回收残留锁并允许恢复；
- 运行中的会话：`--resume`/`/resume` 拒绝；`--resume last` 跳过；`/resume`/`--sessions` 不列出；
- 交互 `/resume` 通过 `mailbox.adopt()` 保留目标名字/inbox；当前身份退役。

因此本版可以假设：**启动时若 resume 命中，`session-id` 与 profile.name 就是旧会话的**；名字池只需要处理「新会话 + 无旧名」这一条路径。

## 1. 需求 A：随机会话代号

### A1 角色池

```ts
export const NEO_ROLE_POOL = [
  "neo", "Trinity", "Morpheus", "Cypher", "Niobe", "Seraph",
  "Oracle", "Switch", "Tank", "Link", "Ghost", "Keymaker",
] as const;
```

顺序即候选序；大小写按池面显示（`Agent: Trinity`），`neo` 小写。

### A2 选择规则

交互 TTY 启动、mailbox 可用时：

| 优先级 | 输入 | 行为 |
|---|---|---|
| 1 | `--name X`（显式） | 用 X；撞名走现有 `pickUniqueName` 后缀（行为不变） |
| 2 | resume 命中的旧 profile.name | 保留旧名，绝不随机；若与其它存活会话撞名（异常态）走 `pickUniqueName` 后缀，仍不是随机 |
| 3 | 无显式 / 无旧名 | 从池中随机取「未被存活会话占用」的名字；撞名不后缀，换下一个随机候选 |
| 4 | 池内 12 个全被存活会话占用 | 随机挑一个角色 + `pickUniqueName` 后缀（如 `Trinity-2`） |

- 随机源注入（`rng: () => number`），单测固定序列；
- 名字写入 profile/state（createIdentity 现有路径）；
- `neo` 就是普通名字：寻址、send_message、list_peers 都用 `neo`，无特殊分支。

### A3 mailbox 初始化失败

- `new Mailbox` 成功但 `createIdentity` 失败（双开/权限）：本地仍选一个池内随机名，**只用于 TUI 标题显示**；不落盘、不参与寻址。
- 若连 mailbox root 都拿不到：退化为池内随机（不知道占用情况，仅显示）。
- resume 场景下 mailbox 失败：能读 root 时保留旧名用于显示；读不到则本地随机。

### A4 `/rename` 不变，但要同步标题

- `renameSession` 语义不变（撞名后缀、excludeSession）；
- 改名成功后更新内存里的 `sessionLabel` + `TitleAnimator.setName(newName)`；
- 交互 `/resume` adopt 成功后同样更新。

### A5 必须先修的旁路：死会话名字会遮蔽活名字

`resolvePeer()` 当前按名字命中**所有 profile**，`byName.length > 1` 就 `ambiguous_target`（store.ts:381-386），不区分 dead/alive。池随机只看 alive，因此可能出现：

- dead 会话（未到 TTL）名字 `Trinity` + 新会话随机到 `Trinity` → `send_message target "Trinity"` 变 ambiguous。

本版随名字池一起修：按名字匹配到多个时，**优先存活/running 的候选**；恰好一个 running → 用它；多个 running → 仍 ambiguous；没有 running → 保持原语义（dead 继续交给 requireAlive 报 not alive）。附单测。

### A6 名字清理（轻量）

- 干净的退出路径可以在 `closeMailbox()` 时把 profile/state 的 `name` 清空（死人不占名），
  但这会改变 `/peers` 历史可读性；**本版先不做**，用 A5 的寻址优先规则兜底，避免行为面扩大。

## 2. 需求 B：标题显示 + Neo 动画

### B1 标题格式

`getTitle` 从 `neo · <cwd>` 改为结构化标题：

```ts
interface TitleView { prefix: "Agent"; text: string; matrix: boolean; }
```

- 普通名：`Agent: Trinity`（dim）；
- 名字 `neo`：在 `Agent: Mr.Anderson`（dim）与 `Agent: N E O`（Matrix 绿）之间切换；
- busy：统一追加 ` · 运行中`（dim），即 `Agent: Trinity · 运行中` / `Agent: N E O · 运行中`；
- `Agent: ` 前缀固定 dim；`matrix` 只作用于名字部分；
- 顶线依旧是「横线 + 右侧 label」，`topRule` 的宽度/截断逻辑不变；ANSI 用 `truncateAnsi`，宽度用 grapheme 级 `displayWidth`。

### B2 动画节奏

- 仅 `name === "neo"`（含 `/rename neo`、`--name neo`）启用；
- 初始态：`Mr.Anderson`（dim）；
- 每 10–20 秒随机切换一次（每次重新 `rng`），两态往复；
- 切到目标前 3 帧字符雨（80ms/帧，总 240ms）：
  - 目标 `N E O`：每帧 5 列，空格位保留，其余位随机片假名/数字，逐帧收敛；
  - 目标 `Mr.Anderson`：每帧 11 列，字母/数字随机，逐帧收敛；
  - 每帧显示宽度 == 目标文本宽度，避免顶线抖动；
- timer 全部 `unref`；`TitleAnimator.stop()` 清理；由 `Composer.start/stop` 统一启停；
- 只重画帧：复用 composer 现有 public `rerender()`，不动 buffer/cursor。

### B3 与 busy / 模态的关系

- busy 后缀由 composer 统一拼接，动画只提供名字部分；
- `选择`/`确认` 模态顶线替换为固定标题，动画可在后台继续，退出模态后显示当前帧；
- 非 TTY / `-p`：没有标题，也不启动 animator。

```

     │                      │

```

## 7. 风险与待确认

### 7.1 已确认的 4 个默认值（用户 2026-10-26 拍板）

1. **初始态**：`Mr.Anderson`（dim）→ 10–20s 后闪到 `N E O`。✅ 已确认
2. **字符雨**：现在做（3 帧 ×80ms，宽度锁定）。✅ 已确认
3. **池全占 fallback**：随机角色 + `pickUniqueName` 后缀（如 `Trinity-2`）。✅ 已确认
4. **`--name neo` 是否触发动画**：按「名字 = neo」统一触发（含 `/rename neo`）。✅ 已确认

### 7.2 风险

- **PTY 顶线 finder**：`neo ·` 改为 `Agent:` 后，S12/S13/S15 及测试 helper 要同步；busy 判定仍靠「运行中」，不受影响。
- **timer 生命周期**：animator 的 fake scheduler 必须与 composer stop 成对；泄漏会让进程退出被拖住（unref + stop 双保险）。
- **颜色断言**：Screen 会忽略 SGR，PTY 只能断言文本；绿色由单测检查 ANSI 序列。
- **死会话名字残影**：A5 寻址优先规则是名字池可用的前提；若不做，随机名命中 dead 名字时会 ambiguous。
- **`/rename` 与动画竞态**：改名到 `neo` 立即起动画；改名离开 `neo` 立即停 timer 并回落 dim 名字。
