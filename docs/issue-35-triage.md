## 2. 第 0 批：现存 bug（已核验，优先修）

### 2.1 `/rewind` 在 `/compact` 之后对话回滚不可信 → issue #39

- 轮次表里记的是**绝对消息下标**（`src/rewind.ts` 的 `messagesBefore`）；压缩会把较早历史换成 1 条摘要（`src/agent/compact.ts` 的 `applyCompaction`），总长度变短。
- 回滚时直接用旧下标截断（`src/rewind.ts` `rewind()` + `src/index.ts` 的 `truncate`），压缩后要么截错位置，要么 `boundary >= current` 直接不生效（静默失败）。
- 后果：`/rewind both` 只退了代码、对话没退，模型仍记得旧决策，会再跑回同一条错路。
- 修法：压缩时通知宿主，把轮次表下标按「头段被删条数」平移；落在被压缩区间里的轮次 clamp 到摘要或明确拒绝（口径写进 PRD）。旧会话按「无压缩记录 = 恒等」兼容。

### 2.2 `-p` 一次性模式不回收后台资源 → issue #40

- `-p` 分支只 `mcpManager.closeAll()` + persist（`src/index.ts:1201-1290`），**不走** `shutdown()`（`src/index.ts:1453-1479`）。
- 于是 `backgroundShells.killAll()`、`backgroundTasks.cancelAll()`、`lspServers.closeAll()` 都不执行：`-p` 里起过的后台 shell / 语言服务器可能变成孤儿进程，信箱也不关。
- 修法：抽一个两处共用的清理函数；补一条集成测试（fake LLM 触发 `shell background:true`，退出后断言子进程已死）。

### 2.3 `-p` 下 `/drive` 与 PRD 不一致 → issue #41

- PRD 写「`-p` 不提供 `/drive`（命令会明确提示不可用）」，但 `-p` 根本不解析斜杠命令：`neo -p "/drive …"` 会把整串当 prompt 发给模型。
- 影响小，顺手补齐或改 PRD 二选一。

### 2.4 `/rewind` 列表混入跨会话消息与自动轮次 → issue #42（维护者实测）

- drain 里 `rewindLog.beginTurn(...)` 无条件记账，不看队列项的 `origin`/`loop`；而同一处 `agent.send` 已经按 `origin === "user"` 区分「ESC 回滚」语义。
- 结果：列表里混着跨会话信箱帧文本（`<跨会话消息…>`）、状态通知、`/loop` 与 `/drive` 自动注入的轮次，编号也跟着乱。
- 正确口径（已与维护者确认）：**列表与编号只算用户轮次**；内部记账保留全部轮次——按用户轮次回滚时 `doomed` 必须包含其后的所有自动轮，否则自动轮产生的文件检查点退不干净。
- 修法：`RewindTurn` 增加来源字段（human / auto）；列表与目标解析只对 human；旧会话无来源字段按 human 兼容。

## 3. 各项是什么、能带来什么（人话版）

- **#23 LSP 三件套**：让模型在配了语言服务器的项目里，能列出全仓符号（找东西不用全仓 grep）、看调用链（谁调了谁）、拿到补全候选。日常写代码最直接提效的一项，基础设施已经齐。
- **#29 旧 SSE 传输**：让 2024 版老协议的 MCP server 也能连。现在主流是 streamable HTTP，所以收益低；但代码便宜、风险小。
- **#16 后台任务落盘 / 续聊**：neo 后台跑的子代理任务现在只活在本进程内存，退出就没了。落盘 = 崩溃/退出后能看到「当时派了什么、结果是什么」；续聊 = 还能接着追问。
- **#27 定点 compact**：长会话里只压缩「从某一轮往后」的那段，而不是整段历史都压。
- **#27 交互式菜单**：输入框空闲时连按两下 Esc 弹出轮次列表，用方向键选要退到哪一轮，不用记命令和编号。
- **#15 仓库地图引用图**：现在地图按路径字母序给符号，改为按「被引用多的文件优先」排序，大仓首轮探索更快。不引 tree-sitter 也能做（纯文本解析 import）。
- **#28 Ctrl+B**：前台命令跑太久时按一下转到后台继续跑。真正难点是终端当时已让给子进程、neo 收不到按键——要么引 pty 做代理，要么改终端所有权。
- **#28 PTY / attach**：把后台命令的实时输出接回屏幕并接管输入，等于内置一个简易终端。工程量大、依赖 pty、与 v0.3 supervisor 计划重叠。
- **#24 `-p` 无人值守长跑**：`neo -p` 现在跑一轮就退。长跑 = 循环跑直到检查命令通过。对 CI/编排有真需求，但要先解决权限审批死锁（没人点确认）、经费上限、退出码。
- **#24 LLM 评估**：现在「做完没」只认检查命令退出码 0；这一项想让模型来判断。风险是模型自述不可验证，会把「完了」的标准放软。
- **#29 OAuth**：让需要浏览器登录的 MCP server（Notion/Sentry 一类）能接入。仓库现在没有临时 HTTP 服务、没有凭据落盘的先例，要从零建。
