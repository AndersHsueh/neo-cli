# `/` 渐进式命令菜单 PRD（issue #31）

> 状态：实现中（待审查）
> 关联：GitHub #31。维护者口径：**替换**旧的 Tab 循环单行 hint，不是叠加。

## 1 背景

旧 UX：输入 `/` 后要按 Tab 才触发 `completeLine`，靠单行 hint「N 个命令候选：/a /b（继续按 Tab 循环）」
轮换名字。命令说明（`COMMANDS[].description`）已有数据却从不进 UI，用户只能靠记忆。

## 2 需求

1. **触发**：行首输入 `/` 自动打开菜单（不必先 Tab）；继续输入按 `rankCommands`（既有确定性模糊排序）过滤；
   无匹配显示空态 `无匹配 "/xxx"`，不静默。
2. **呈现**：纵向列表，每行 **左 `/name`、右短说明**（取 `COMMANDS[].description`，不用长 help 文案）；
   当前高亮 `❯`；最多 8 行，超出滚动并提示 `… 还有 N 项`；窄终端优先保住名称、说明截断。
3. **选择与提交**（二选一，本版写死：**Tab 接受不执行 / Enter 接受并执行**）：
   - ↑/↓（PageUp/PageDown 一次 5 项）移动高亮，菜单打开时不让位给历史；
   - **Tab**：把高亮项写进输入框（`/name`），**不执行**，菜单关闭；
   - **Enter**：接受高亮项并**立即执行**（与 Claude Code 直觉一致；想先编辑就按 Tab）；
   - **Esc**：关闭菜单、保留已输入文本（按 Esc 时的缓冲文本被记住，再按 Esc 前不会自动重开）。
4. **移除旧 UX**：命令路径不再出现「N 个命令候选：…（继续按 Tab 循环）」；Tab 对命令不再做名字串轮换。
   `formatCandidateHint("command", …)` 只保留给 **没有 composer 的 readline 降级模式**。
   `@` 文件补全的 Tab 循环 + 单行 hint **保持不变**。
5. 命令带空格（进入参数区）后菜单关闭；`/memory` 这类子命令仍由命令自身处理。

## 3 验收

1. 行首 `/` 即出菜单（左名/右说明），继续输入实时过滤，无匹配有明确空态；
2. ↑↓ 移动高亮、Tab 接受不执行、Enter 执行、Esc 关闭且保留文本；
3. 菜单高度受限并有剩余提示；窄终端名称优先；
4. 正常 TUI 里键入 `/`/`/ti` 再 Tab **不再**出现「N 个命令候选」字样；`@` 文件补全行为不变；
5. `bun x tsc --noEmit` 零错误、`bun test` 全绿（含 PTY）、`bash scripts/verify.sh` 为 `ALL GREEN`。

## 4 非目标

- 不做命令分组/分区页签；不引入新的选择器交互范式（复用现有高亮视觉口径）；
- 不改 `COMMANDS` 声明表与 `cli/commands.ts` 的漂移守卫。
