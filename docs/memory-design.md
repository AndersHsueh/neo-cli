# neo 记忆系统设计（v0.2）

> 状态：方向已拍板，待实施。
> 日期：2026-10-15
> 依据：v0.1 提案（已读全部源码 6866 行 + 实测 32 份真实会话）+ 2026-10-15 社长讨论决议（见 §8）
> 与 v0.1 的关系：主架构更换为「两级 karpathy-wiki + 指针召回」。v0.1 的注入式方案降级为附录 B 备选，其条目粒度 / ADD-only / 信号体系被本版吸收。

---

## 1. 现状盘点（已验证，沿用 v0.1）

代码里与「记忆」沾边的东西共三处，彼此独立，没有统一抽象：

| 位置 | 机制 | 实际行为 | 缺口 |
|---|---|---|---|
| `src/session.ts` | 会话 JSON 落盘 `~/.neo/sessions/` | 完整消息数组，32 份实测存在 | **只用于 `--resume`，从不参与记忆提取**。信息量最大的一处完全闲置 |
| `src/index.ts:326-334` | `AGENTS.md` 注入 | 在 cwd 找第一个命中的文件，全文无截断拼到 system prompt 尾部 | 无检索、无容量上限、无冲突处理。只认 cwd 根目录 |
| `src/agent.ts:126-172` | `compact()` | 超阈值把历史压成一条 user 消息 | 会话内摘要，进程退出即丢，不回写磁盘 |

三个结构性问题（v0.1 已述，结论沿用）：

1. `noteModelChange()` 用正则 `/- 模型：[^\n]*/` 改 system prompt，与尾部拼接的记忆会互相干扰。
2. 会话恢复（`index.ts:317-321`）后再注入一次记忆，会重复叠加。
3. `/init` 生成的记忆文件纯人工维护；实测 `~/.neo/` 下不存在任何 AGENTS.md，该路径完全空转。

## 2. 架构总览：两级 wiki + 指针召回

**核心思想：记忆不是「注入上下文的内容」，而是「模型用工具按需查询的资产」。**

上下文里只常驻两样东西：AGENTS.md（使用规则）与 profile.md（用户画像，≤500 tokens）。
其余全部按需查询。这消掉了 v0.1 注入方案的三个问题：token 预算、注入位置冲突、prompt 缓存失效。

### 2.1 项目级（每个工作目录）

```
<cwd>/.neo/
├── wiki/
│   ├── raw/       # 不可变源（约定，见 §3.2）
│   ├── wiki/      # LLM 编译层（ingest 产物）
│   └── outputs/   # 对外产出
└── skills/        # 符号链接：karpathy-wiki-new / -ingest / -lint / -query
AGENTS.md          # wiki 使用规则 + 技能路由说明（/init 生成）
```

### 2.2 用户级（跨项目）

```
~/.neo/memorys/
├── raw/           # 项目索引条目，一个项目一条 markdown
├── wiki/          # 编译层
├── outputs/
└── profile.md     # 常驻注入的用户画像（≤500 tokens，见 §4.2）
```

索引条目格式（`raw/` 下，一条一文件）：

```markdown
---
date: 2026-10-15
cwd: /Users/xueyuheng/research/000-alice-new
topic: neo 记忆系统设计        # 可选
---
一句话概要：讨论并拍板两级 wiki 记忆架构。
```

- `date` + `cwd` 为必填，客观事实，自动写入。
- 概要默认值 = **该目录首个会话的第一条用户输入**；用户可事后改（改 wiki 层，不动 raw）。

### 2.3 回忆路径（不失忆的原理）

用户问「X 年 X 月做过 XX」时：

1. 查询用户级 wiki（索引已编译，可按日期 / 主题检索）；
2. 命中索引条目 → 取出 `cwd` 路径；
3. 沿路径读项目级 wiki；
4. 组织回答。

用户级条目是**指针式记忆**：日期与路径是客观元数据，写错概率接近零，以最小成本覆盖最常见的失忆场景。

## 3. 写入规则

### 3.1 懒创建

触发条件 = 「首次产生值得记的内容」（首次写索引 / 经验条目）或用户显式 `/init`。
**不因为「进入了一个新目录」就落骨架** —— 一次性目录（`/tmp` 等）不应留痕。

### 3.2 raw 约定：可增、可删、不可改

- **约束对象是 neo 自己**：规则写进 AGENTS.md，neo 不改写 raw 下已有文件。
- **不强制用户**：用户手动修改是其自由；neo 读到什么以什么为准，不做校验、不做防护。
- 实现含义：工具层**不需要**为 raw 加任何硬编码限制。

### 3.3 两类条目，两种写入门槛

| 类别 | 内容 | 写入方式 |
|---|---|---|
| 客观索引 | 日期、工作目录、会话 id、概要（首条输入） | **自动写，零确认** |
| 主观经验 | 「这个项目用 bun 不用 npm」「回答不要收尾语」 | 规则筛信号 → LLM 精炼 → **人工确认**（沿用 v0.1 §4 四类信号 + ADD-only） |

分界理由：客观元数据不含推断，自动写无风险；主观提炼一旦错误会持续误导未来会话且用户无感知 —— 与 config 里「静默套用模板密钥」是同类风险，静默的错误比显式的错误贵得多。

## 4. 读取与召回

### 4.1 主路径：按需查询，不注入

模型通过 karpathy-wiki-query 技能查询 wiki（read_file / shell 即可承载）。
记忆量增长不占上下文，只在需要时花一次工具调用。

### 4.2 例外：profile.md 常驻注入层

动机：「不要收尾语」「我用 zsh」这类偏好，**模型不知道自己不知道**，不会主动去查 wiki。
wiki 适合「我知道我要找什么」，不适合「我不知道有这个规矩」。

- 位置：`~/.neo/memorys/profile.md`，启动时注入；
- 上限 **500 tokens**，只收确认过的偏好条目；超限时截断并显式告警（静默裁剪等于让用户以为记忆还在）；
- 注入方式：独立的第二条 system 消息（messages[1]），不与主 system prompt 拼接 —— 避开 `noteModelChange()` 的正则改写；
- **compact 语义（v0.1 未定义，本版补上）**：压缩只作用于对话消息（messages[2..]），profile 注入块必须原样保留。

### 4.3 ingest 时机

- **当前（守护进程未上线）：写入时同步 ingest。**
- 未来：守护进程跑 fast-model 小循环，专职 ingest / lint / query 应答。
- 接口要求：ingest 与 query 做成可替换实现（沿用 `TierClassifier` 的接口 + `build()` 注册表结构）。守护进程上线时只换实现，不改调用方。

---

## 5. skills 集成

- `./.neo/skills/` 内为符号链接，指向用户级技能仓库（karpathy-wiki-new / -ingest / -lint / -query 四个技能）。
- skills 加载机制由**并行开发中的 claude-code 式技能系统**提供；本设计不依赖其内部细节，只依赖外部契约：「AGENTS.md 路由说明 + 技能文件可读」。
- AGENTS.md 由 `/init` 生成，内容 = wiki 使用规则 + 四个技能的触发路由。

---

## 6. 保留自 v0.1 的资产

1. **条目粒度 + ADD-only 语义**：wiki 页面内的经验条目按「一条一事实 + 标签 + 来源 + 置信」组织；覆盖时新增一条并标记被替代者，不原地改写。
2. **四类抽取信号 + 人工确认**（P2 沿用）：显式偏好 / 纠正 / 重复失败 / 环境事实。「重复失败」零成本可先做，复用 `agent.ts` 已有的 `consecutiveFailures` 计数器。
3. **noteModelChange() 正则冲突教训**：任何注入块必须独立，不与 system prompt 主体拼接。
4. **抽取 LLM 固定绑 `classifier_provider`**（零成本网关），绝不用抽取结果决定自己跑在哪。

## 7. 分期实施

| 期 | 内容 | 风险 |
|---|---|---|
| P0 | 用户级骨架：`~/.neo/memorys/` 结构 + 索引自动写 + profile.md 注入 + 写入时同步 ingest | 低（索引是客观数据） |

**明确不做（v1）：** 向量库 / embedding、知识图谱、记忆自修改、对用户文件系统的强制性保护。

## 附录 B：v0.1 注入式方案（备选，已降级）

原方案：检索后注入为 messages[1]，2000 token 硬上限，按「显式写入 > 标签相关 > 最近命中」三级裁剪。

降级原因：

1. 每轮动态检索注入导致 prompt 缓存失效、同会话内上下文不一致；
2. 2000 token 预算未经实测，且 P0「永不丢」与硬上限之间存在未定义行为；
3. 标签无受控词表，几十条后同义标签分裂，检索召回劣化。

其条目粒度、ADD-only 语义、四类抽取信号、固定 provider 绑定四项资产已被本版主架构吸收（见 §6）。
