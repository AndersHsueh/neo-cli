# v0.4.71 — `/context` 档位行反映当前 cfg 而非上次渲染（issue #20）

## 背景

v0.4.70 之后出现一个自相矛盾的窗口期：探针回写窗口后、下一轮边界前，`/context` 的 window 行（读 cfg）已是新值，档位行（读 lastSelection）还是旧值——两行打架。本版修掉。

## 改动

- `src/prompt/manager.ts`：新增 `currentSelection(cfg)`——按当前 cfg **现算**选档，只算不写：不碰 `messages[0]`，提示词何时生效仍由请求边界决定（v0.4.70 在途护栏不变）
- `src/cli/commands.ts`：`/context` 档位行改读现算值；调用处 try/catch 兜底——取档要读目录树/技能/wiki 索引可能抛错，失败就省略档位行，不让整条命令崩
- 语义定义：档位行展示「**下一次请求会用哪一档**」——旧值已是死档（下一轮必然重选），且与同命令的 window 行天然矛盾；两者一致时只显示一个值
- 附带：修正 8 页 wiki 共 26 处因 v0.4.70/71 而漂移的 `路径:行号`（改用内容匹配逐条重定位——原「行存在即有效」的核对法会放过语义漂移）

## 验证
