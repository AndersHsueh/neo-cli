# v0.2.1

> 2026-10-20 · 补丁版本：**跨会话消息 hotfix** —— 主代理工具可见性 + 长 turn 心跳 / watchdog 误报
> 规格：`docs/cross-session-messaging-prd[done].md`（v1.2）；上游版本 v0.2.0

## 背景

v0.2.0 推送后，用两个真实 neo 会话（tom ↔ jacky）做问候链路验证，暴露出两个必须修的问题：

1. **`send_message` / `list_peers` 没有出现在模型可调用的工具列表里**：两个模型都只能翻源码、
   用 shell 写临时脚本绕过；系统提示里写着有工具，实际调不到。
2. **watchdog 把正在长 turn 的活进程误报成 dead**：jacky 处理第一个 turn 时心跳停止刷新，
   tom 侧收到 `kind=dead`；实际进程存活、`phase: "working"`，一轮 150s 的 LLM 调用还没结束。

## 修复

### 1. 主代理工具可见性（阻断级）

根因：`Agent.toolSpecsFor()` 把 `TOOL_NAMES_EXCLUDED_FOR_SUBAGENT`
（task / compact_ctx / remember / send_message / list_peers）套在了**所有** Agent 上。
这些工具在 v0.2.0 之前就已经被主代理悄悄过滤，只是跨会话功能把它显性暴露了。

- `AgentOptions` 新增 `isSubagent?: boolean`；只有 `isSubagent=true` 才应用排除表。
- `runSubagent()` 构造子代理时传 `isSubagent: true`；主代理拿全量工具。
- 回归测试：主代理 `toolSpecsFor()` 含 `compact_ctx`/`send_message`/`list_peers`；
  `isSubagent=true` 时全部排除（`tests/compact-ctx.test.ts`、`tests/mailbox-agent.test.ts`）。

### 2. 心跳独立于空闲 tick + pid 存活兜底

根因：15s 心跳只挂在 REPL 的空闲 tick 上，turn 进行中 tick 被 `draining` 挡住不跑；
长 LLM 调用 >120s 时别的会话 watchdog 就会误判 dead。

- 心跳改为独立 `setInterval(cfg.mailbox.heartbeatMs)`，**turn 中照常刷新**。
- 流式输出（text/reasoning）也计入进展：节流 30s 刷 `last_progress_at`，
  避免 5 分钟长生成被判 `stuck`。
- `PeerObservation` 增加 `pid_alive`；`observePeer()` 用心跳超时但 `process.kill(pid,0)` 存活时
  降级为 `stale`，不再报 `dead`；watchdog 判定同步使用该信号。
- 回归测试：心跳超时 + pid 活 → `stale`/healthy；pid 死 → `dead`。

### 3. 启动横幅 / 系统提示的工具清单

- `banner()` 的 tools 行改为组合根传入 `toolNames()`，不再写死 8 个静态工具。
- 运行时工具全部注册完后重建一次 system prompt，`可用工具` 行包含
  task/wiki_*/remember/send_message/list_peers。

## 验证

- 全量 **523 pass / 0 fail（26 文件）**，`bunx tsc --noEmit` 零错误。
- fake-LLM E2E（不触网）：
  - 请求 `tools` 数组 16 个，含 `send_message` / `list_peers`；
  - 3s 长 LLM turn 中读取 `state.json`：`phase=working`、`heartbeat_at > turn.started_at`
    （心跳独立刷新生效）；
  - 启动横幅 tools 行同步显示 16 个工具。
- 真实双会话验证（v0.2.0 链路）本身已通过：投递 → 消费 → 回信 → reply_to/exec 对账；
  v0.2.1 修复的是过程中暴露的工具可见性与 watchdog 误报。
