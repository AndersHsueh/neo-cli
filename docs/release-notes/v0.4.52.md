# v0.4.52 — 撞墙与首次使用时的能力探测写回（issue #5 P3）

## 背景

P1/P2 解决了「声明了的能力」，但很多网关的 `/models` 不吐能力字段，settings 也没填——neo 对模型上限一无所知。本版（P3）补上**运行时探测**：撞墙或首次使用时主动探测，并把结果写回 settings.json，下次启动就不用再撞。

## 改动

- 新增 `src/env/modelCaps.ts`（299 行）：探测与写回逻辑
- 两个触发时机：
  - **撞墙**：请求碰到上下文/输出上限（wall）时，探测并把空字段写回
  - **首次使用**：能力位未声明但实际用到（如发了图才发现模型不支持视觉）时，探测补齐
- 口径：**只填空字段，绝不覆盖用户手工填写的值**；`max_tokens`（请求预算）与 `max_output_tokens`（模型输出上限）保持分离，不混写
- `src/agent/loop.ts` / `src/index.ts`：接入工具循环与启动流程

## 验证

- `tests/model-caps-writeback.test.ts`：新增 495 行，覆盖两种触发时机与「不覆盖用户值」口径
