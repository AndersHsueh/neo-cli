# v0.4.11 —— glob 字符类取反 `[!...]` 语义修正

> 证据：`bash scripts/verify.sh` → `docs/evidence/v0.4.11-{tsc,tests,pty}.txt`（目录 gitignore）

## 为什么

`globToRegExp` 遇到 `[...]` 时把字符类**原样**塞进 RegExp。glob 的 `[!abc]` 表示
「非 a/b/c」，但 JS 正则里 `[!abc]` 读作「`!` 或 `a` 或 `b` 或 `c`」——语义正好相反：

| 模式 | 目标 | 修复前 | 修复后 |
|---|---|---|---|
| `[!abc].ts` | `d.ts` | 漏掉 | 命中 |
| `[!abc].ts` | `a.ts` | 命中（错） | 漏掉 |

影响面：`glob` 工具与 `grep` 的 `glob` 过滤参数共用这个函数，用户/模型写取反字符类时
拿到的是**反向结果**，且不会报错——属于静默错答案，比抛错更危险。

## 改了什么

`src/tools/index.ts` 新增 `charClass()`，字符类分支改为调用它：

1. `!` / `^` 开头的类统一转成 JS 的 `[^...]`（`[^...]` 不是 glob 标准写法，但按取反处理，
   避免误写时静默反义）；
2. 类内 `\` 与 `]` 转义，避免生成非法正则；
3. 取反后类内为空（`[!]`）退化为 `(?!)`——不匹配任何字符，而不是让整条正则抛 SyntaxError。

普通字符类与区间（`[a-c]`、`*.[ch]`）行为不变。
