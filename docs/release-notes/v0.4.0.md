## 一句话

neo 之前只在 macOS（zsh）上可用：`shell` 工具与 `!cmd` 都写死 `["/bin/zsh","-lc",cmd]`，
在 Ubuntu（默认无 zsh）上每条命令都 `ENOENT` —— 不是个别命令失败，是**命令执行层全灭**。
本版把「平台」抽成一层基础设施：跨平台 shell 解析 + PATH 保真 + 纯脚本环境探测 +
主/子代理环境注入 + `~/.neo/wiki/环境.md` 派生记录；并顺带修掉 3 个只在非 macOS 环境暴露的测试移植性缺陷。

## 新增

### 1. 跨平台 shell 解析器 `src/shell.ts`

- 探测顺序：`settings.shell.path` → `NEO_SHELL` → `$SHELL` → 平台默认
  （darwin `/bin/zsh`、linux `/bin/bash`）→ `which zsh/bash/sh` → `/bin/sh`。
- 参数分开传：登录 POSIX `["-l","-c"]`、非登录 `["-c"]`；未知 shell 只给 `-c`；
  `shell.args` 可整体覆盖。
- Windows：`pwsh` → `powershell` → `ComSpec(cmd)`；参数分别为
  `["-NoProfile","-NoLogo","-Command"]` 与 `["/d","/s","/c"]`（未实机验证）。
- **PATH 保真**：登录 shell 会重置 PATH（macOS path_helper / Ubuntu `/etc/profile`），
  现在 spawn 时注入 `NEO_INHERITED_PATH`，命令前把父进程 PATH 前置 ——
  修掉「neo 自己能调 `bun`，shell 工具里却 not found」的隐性 bug。
- 解析失败/配置不可执行时给出可操作告警（启动横幅后可见），spawn 失败信息带候选与配置建议。
- 两处写死调用点收敛：`src/tools/index.ts`（shell 工具）、`src/index.ts`（`!cmd`）。

### 2. 纯脚本环境探测 `src/env/*`

- **不需要模型**：OS/内核/架构、shell（路径/家族/登录/版本）、CPU、内存、磁盘、
  工具链存在性与版本、容器/WSL/SSH、终端、locale/时区、权限、GUI —— 约 10ms，零 token。
- 事实源：`~/.neo/env/<machineKey>.json`（schema v1，静态部分 TTL 12h，原子写，0600）；
  `machineKey = hostname-platform-arch-<hash8>`，为将来 `~/.neo-team` 多机同步预留。
- 动态值（可用内存/磁盘）每次现算，**不进系统提示词**（会话中途会过期），只进 `/env` 与 wiki 页。
- shell 字段永远以本次运行解析结果为准：改配置后不必等 TTL，prompt 不会说错 shell。

### 3. 双层注入

- 主代理：系统提示词 `## 环境` 增加平台/shell/资源/工具/约束 5 行（约 100–200 token），
  shell 行明确「命令必须兼容该 shell」。
- 子代理：`task` 的 `subSystemPrompt` 注入紧凑版（平台/shell/工具/约束）——
  子代理同样会执行命令，之前完全不知道自己在哪台机器上。
- 约束由事实规则生成：容器内 / WSL / 远程 SSH / 无 GUI / root / 非 root+sudo。

### 4. `~/.neo/wiki/wiki/环境.md` 派生页

- 单页 + 生成块所有权：`<!-- neo:env:start -->…<!-- neo:env:end -->` 由脚本整块重写，
  块外（`## 人工补充`）永不触碰；INDEX 摘要同步；log 只在首次创建或机器/OS/shell 变化时记一条。
- 交互式启动自动落盘；`-p`/非交互**只注入不落盘**（尊重 scopeMode=project 的服务器场景约定）。
- 新增 `/env`（查看）与 `/env refresh`（重采 + 写页）命令。

### 5. 配置

```json
"shell": { "path": null, "login": true, "args": null },
"env":   { "enabled": true, "probe_ttl_hours": 12, "prompt": true, "wiki_page": true }
```

- 全部可选，缺省即推荐值；`NEO_SHELL` 覆盖 shell 路径，`NEO_ENV_DISABLE=1` 关闭探测/注入。
- `settings.example.json` 已同步。

### 6. Windows 实验性支持

- `src/config.ts` 的 `new URL(import.meta.url).pathname` → `fileURLToPath`
  （Windows 上原写法会拼出 `/C:/...` 错误路径）。
- 新增 `neo.cmd` 启动器（`bun run "%~dp0src\index.ts" %*`）。
- 剪贴板：darwin 保留 JXA；win32 新增 PowerShell `Get-Clipboard -Format Image` 分支
  （`-STA` 优先 Windows PowerShell，缺失退 pwsh 7）；Linux 明确降级提示。
- **限制（必须明说）**：Windows 未实机验证；TUI 假设 Windows Terminal（VT 序列）；
  PowerShell 编码/转义/ConPTY 行为待 PD-1 实机验收。

## 顺带修掉的跨平台测试缺陷

这三个都是**旧代码在 Ubuntu 上必红**、但被「开发机状态」掩盖的问题：

1. `tests/memory-layout.test.ts` D5：跨进程锁测试写死
   `projectRoot = "/Users/xueyuheng/…/neo"`，Ubuntu 上子进程 import 失败 → 改为 `import.meta.dir`。
2. `tests/gitignore-rules.test.ts` K4.1：断言 git 英文报错 `beyond a symbolic link`，
   Ubuntu 中文 locale 输出「位于符号链接中」→ spawn git 时固定 `LC_ALL=C, LANG=C`。
3. `scripts/pty-e2e.ts` S16：断言菜单里的 `glm-5.3-flash` 来自**开发机根目录的 settings.json**；
   Ubuntu/CI 检出没有该文件（gitignore）→ 回落到 example 模板必红。
   改为在临时 cwd 写一份确定性 settings.json，PTY 套件从此与开发机配置解耦。

另：`scripts/verify.sh` 的 tsc 阶段从 `bunx` 改为 `bun x`（部分 bun 安装只有 `bun` 单入口）。

## 升级注意

- 旧配置无需改动；新增 `shell`/`env` 段都是可选的。
- 启动横幅后多一行 `shell <path>（<kind>，登录 shell）`；若配置的 shell 不可执行会给出告警并回退。
- 首次启动会在 `~/.neo/env/` 写快照（交互式），交互式还会生成/更新
  `~/.neo/wiki/wiki/环境.md`；`-p` 模式不写盘。
- `!cmd` 与 `shell` 工具现在**共用同一 shell 解析**，不存在两套行为。
