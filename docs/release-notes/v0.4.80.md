## 为什么发这一版

v0.4.78 补回了闸门（自 v0.4.5 起本机就没再跑过 verify.sh），但补回闸门只解决了「不再漏」，没解决「绿灯到底意味着什么」。

同日对 `tests/` 的只读审计结论是：**盲区不在断言层，而在豁免层**。断言层是干净的 —— 无空断言、无永真断言、无「expect 全被包在条件分支」、无整块注释掉的测试、`test.only` / `test.todo` 零命中。问题出在别处：

- `scripts/verify.sh` 的 tests 阶段**只看退出码**，而 `bun test` 存在 skip 时退出码仍是 0 ⇒ **`ALL GREEN` 不代表覆盖完整**；
- 2 处 `skipIf`（其中 `prompt-tiers` 的 3 条**只在有源文件的机器上跑**，其余 worktree 布局恒 skip）；
- 1 处 `if (!git) return;` —— 环境缺 git 时用例**静默通过、报告显示 pass、没有跳过标记**，与本仓「环境坏了必须 fail，不能 skip」的纪律直接冲突。

静默跳过会随版本悄悄累积，而闸门对此毫无反应。这就是本版要补的缺口。

## 变更

### 1. `scripts/verify.sh`：tests 阶段加 skip 数守卫

解析 bun test 输出里的 skip 数：

- **skip > 0**：⚠ 告警，并逐条列出 skip 所在文件（从 `(skip)` 明细行向上找最近的 `…test.ts:` 标题行；遇末尾「N tests skipped:」回顾段即停 —— 该段会原样重复明细行，不停会把条目错记到前一个文件名下，这个坑实测踩到并已修）；
- **`NEO_STRICT_SKIPS=1`**：告警后直接 `FAILED: tests (strict skips)` 并退出 1，用于要求零跳过的严格验收；
- **skip = 0**：静默（主仓默认路径不受影响，仍是干净的 ALL GREEN）；
- tsc / pty 阶段无 skip 汇总行，天然静默。

### 2. `tests/file-index.test.ts`：静默通过 → 显式跳过

`if (!git) return;` 改为 `test.skipIf(!git)`。前者让环境缺 git 时用例**静默通过、报告显示 pass**，与 `tests/gitignore-rules.test.ts` 里明确的纪律（「环境坏了必须 fail，不能 skip」）冲突；改后跳过在报告里**看得见**。（`skipIf` 后 `Bun.which` 的类型收窄消失，用 `?? ""` 兜底；git 存在但损坏时仍走真实路径并 fail。）

### 3. `tests/prompt-tiers.test.ts`：源目录可注入

`SOURCE_DIR` 原指向**仓库父目录**的 `bot-comments`，导致 skip 数依赖仓库在文件系统里的物理位置 —— 主仓 3 条跑、任何 worktree 3 条 skip，即「提示词与源文件逐字一致」这条最重要的契约在 worktree 下**从未被验证**。

现支持 `NEO_BOT_COMMENTS_DIR` 注入。取舍：**未指定且找不到 → 仍 skip**（源文件在仓库外，CI/他人机器物理上就没有，fail 会把闸门变成「只在作者机器绿」）；**显式指定却找不到 → 直接 throw fail**（配置错误必须被看见，不能让拼错的环境变量把契约悄悄关掉）。断言未弱化（仍是逐字 `toBe`）。

### 4. `tests/README.md`：基线与清单补真

- §1 基线更新到实测值（v0.4.80：1704 pass / 0 fail / 93 文件），历史基线不再逐版罗列；
- §4 文件清单改为**以 `ls tests/*.test.ts` 为准，README 只记约定与纪律** —— 旧表停在 46 个（v0.4.3）、基线数字停在 v0.4.12，正是逐版维护不可持续的证据；新增测试文件的覆盖说明写在**文件头部注释**里；
- §2 补**实际执行历史**：本机 v0.4.5–v0.4.77 未跑 verify.sh（本地 `docs/evidence/` 一度止于 v0.4.4；`docs/evidence/` 在 `.gitignore` 里，所以**仓库侧看不出**，判定要看本地目录），v0.4.78 补回 ALL GREEN —— 避免后来者误以为一直有闸门；
- 新增「豁免可见性纪律」小节。

### 5. `tests/b4-tools.test.ts`：win32 豁免补注释

`describe.skipIf(process.platform === "win32")` 上方补说明：跳过原因（用例断言 POSIX `pwd` 输出的正斜杠相对路径，Windows cmd 无 `pwd`、PowerShell 输出反斜杠绝对路径，断言必失败）与恢复条件（PD-1 落地后把断言改平台中立，届时移除 skipIf）。

### 6. `README.md` 补真

- 平台支持表的 macOS 基线从「1039 测试 / PTY 20/20」更新到当前实测；
- 新增 v0.4.77 / v0.4.78 / v0.4.79 三条特性说明（链接目标校验、canonical 路径口径、max_tokens 安全防护）；
- `max_tokens` 段落补**不透明 400 的降级兜底**与启动体检告警 —— 原文只讲了「网关明说上限」那一类；
- 开发段补**闸门对 skip 敏感**：`bun test` 有 skip 时退出码仍是 0，光看退出码会误判成全绿；`verify.sh` 因此会解析 skip 数并告警，`NEO_STRICT_SKIPS=1` 可令其直接失败。

### 7. `.gitignore` 补漏

- **`.env` / `.env.*`**：本仓用 `settings.json` 存密钥，但 `.env` 同样是常见密钥载体，不得入库 —— 这是本次检查发现的唯一缺口；
- **`bot-comments/`**：提示词源文件（仓库外的兄弟目录，内容不进版本控制）。

## 已知未做

- **`bot-comments` 是否纳入版本控制** —— 维护者决定：临时文件，暂不纳入。代价是「提示词与源文件逐字一致」这条契约的验证义务落在有源文件的机器上（靠 `NEO_BOT_COMMENTS_DIR` + `NEO_STRICT_SKIPS=1` 强制零跳过）。
- **提示词正文的内容断言** —— 提示词三档正文里的关键句（如「缺批准就先询问」）尚无内容断言测试，误改不会被拦。按维护者决定暂不开 issue，待提示词下一版优化时一并处理。
- **跨层互链** —— 维持现状，不做跨层链接解析。
