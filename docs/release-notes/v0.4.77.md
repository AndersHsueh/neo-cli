# v0.4.77 — wiki_write 写入时校验 [[ ]] 链接目标

## 问题

2026-11-08 跨会话记忆实验里，新建页面写了互链 `[[环境-技能与工具路径]]` —— 该页真实存在于用户级库 `~/.neo/wiki/`，项目级库没有，于是在项目级成了断链。

断链直到人工逐链核对才被发现：`wiki_write` 只校验页面名后缀（`src/wiki/write.ts:47`）与摘要/日期戳（`:68`），不碰正文里的链接。根因不是模型凭空编名字，而是用户级/项目级两层记忆「串层」——同名页面在另一层存在时，写入路径没有任何机制提示。

## 改动

**新增 `src/wiki/links.ts`** —— 链接提取与归一化的唯一真源，从 `src/wiki/lint.ts` 抽出：

- `normalizeLinkTarget`：`[[目标|别名]]` / `[[目标#锚点]]` / `[[目标.md]]` → 纯页名；含 `/` 的路径式目标归一为空串（按 lint 口径跳过）
- `extractLinks`：代码块与行内反引号内的链接不计
- `extractLinkTargets`：去重并保留首次出现顺序

`src/wiki/lint.ts` 改为 re-export 共享模块，既有 import 方不受影响。write 不依赖 lint，也不复制逻辑 —— 两处口径漂移正是本 issue 要消灭的那类不一致。

**`src/wiki/write.ts`** —— 落盘前校验：

- 新增 `checkLinkTargets(content, { layout, selfPage?, otherLayout? })`
- 本层缺失但另一层存在 → 跨层提示，指名层名（如「X 在用户级 wiki，项目级 wiki 没有 —— 请改链到本层，或把该页复制到本层」）
- 两层都无 → 「X 在项目级 wiki 不存在（另一层也没有）—— 写入后会成断链」
- 固定页名（INDEX/index/log/AGENTS）与自链不算断链
- `writeBack()` 新增 `otherLayout` 与 `linkCheck` 两个可选参数；结果对象新增 `linkIssues`

**`src/tools/wiki.ts`** —— 解析另一层布局并把警告拼进工具输出（写项目级查用户级，反之亦然；另一层未创建按「两层都无」处理）。

**`src/memory/merge.ts`** —— 自动沉淀路径同样传入另一层布局，使正文里的跨层引用能被正确识别，而不是误报为「两层都无」。

## 行为口径：警告不阻断

`LinkCheckMode = "off" | "warn" | "strict"`，默认 `warn`：

- `warn`（默认）：写入照常发生，问题以 `⚠️ 链接目标缺失：…` 出现在工具输出里，指名缺失目标与所在层，由模型自行决定是否改链。append 场景多为追加审计行，硬报错会挡死整次回填；跨层链接有时正是作者有意引用另一层。
- `strict`：缺失/跨层直接抛错，不落盘。
- `off`：跳过校验。

**待 Anders 拍板**：create 场景是否默认走严格模式。当前默认全局 `warn`；若决定 create 走 strict，只需在 `src/tools/wiki.ts` 按 `action` 传 `linkCheck: "strict"`，校验逻辑无需改动。
