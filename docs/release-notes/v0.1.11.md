# v0.1.11

> 2026-10-20 · 次要版本：**记忆激活（memory activation）** —— 双作用域存储 + 自动归纳 + 项目优先召回
> 规格：`docs/001-memory-system-design[done].md` §7（唯一规格文档；变更记录见 §7.0.1）

## 背景

v0.1.10 之前的记忆子系统是「只写不读」的空转模块：

- 用户级 wiki `~/.neo/wiki/` **从未被创建**；`profile.md` 全仓无写入者，启动注入恒为空；
- `ingestUserLevel` 零生产调用点；`recordIndex` 只记首条输入前 200 字（实测 7 条全是 `exit` 类噪音）；
- 记忆互斥锁用 `mkdirSync(recursive:true)`，EEXIST 被吞掉，互斥从未生效；
- `wiki_write append` 不同步 INDEX 摘要。

本版本把「记录 → 提炼 → 落页 → 召回 → 注入」整条链路接通，并修复上述基础缺陷。

## 新增

### 双作用域记忆库

- **项目级** `<cwd>/.neo/wiki/`（跟仓库、进 git）：决策 / 踩坑 / 架构 / 进度 / 待澄清；
- **用户级** `~/.neo/wiki/`（跨项目、本机私有、不进 git）：用户画像 / 偏好 / 环境 / 经验；
- 两者目录同构（`raw/ wiki/ outputs/`），复用既有 wiki 校验、INDEX、log、lint；
- 用户级支持 `NEO_USER_WIKI_DIR` 覆盖；懒创建骨架（首次写入时建）。

### 自动归纳（capture，规格 §7.6）

- 四类触发：轮末（boundary 价值判定）、压缩前（摘要）、`remember` 工具 / `/remember`、会话退出 flush；
- 先落 journal 再提炼（`~/.neo/memory/journal/YYYY-MM-DD.jsonl`），崩溃/超时可恢复；
- 提炼器用 **fast 档**，只喂「用户话 + 助手结论 + 工具名/成败/路径」，不喂工具原始输出（防间接注入、控 token）；
- 硬规则校验：ops ≤2、置信门槛（事实 0.65 / 推断 0.75）、body 20–1500 字、evidence 必须能在原文中找到、密钥类内容丢弃、页名/摘要/日期戳强制；
- 合并：内容哈希 + shingle 相似度去重、supersedes 冲突更正、单页 16KB 转续页、每会话页数上限；
- **推断显式标记**：用户级事实进 `## 事实（用户明确表达）`，推断进 `## 推断（待确认）`，条目带 `（推断 日期 · 置信 · session）`，召回时以 `[推断]` 提示只作背景。

### 项目优先召回（recall，规格 §7.7）

- **R0 启动**：双库 INDEX 主题清单进 system prompt（项目 ≤40 / 用户 ≤20），`用户画像` 摘要注入 messages[1]（≤200 token）；
- **R1 每轮**：从用户输入抽中文 bigram + 英文词，先项目级（≤2 页）再用户级（≤1 页），总预算 ≤900 token，无命中零注入；召回是临时 system 消息，轮末摘除，abort 回滚一并清理，压缩输入过滤；
- **R2 工具**：`wiki_search` 增加 `scope=auto|project|user|both`（默认 auto 项目优先合并），`wiki_write` 增加 `scope`；新增 `remember` 工具（子代理不可见）。

### `-p` 单次模式只用项目级记忆（D5）

服务器脚本场景不混入操作员个人记忆：`-p` / 非交互模式设置 `memory.scopeMode=project`，
启动不注入用户画像、召回只查项目库、捕获只写项目库，`remember`/`wiki_write`/`wiki_search` 的用户作用域一律拒绝。

### 命令面

- `/memory` 完整子命令：`status` / `list [project|user]` / `recall <q>` / `why` / `flush` / `forget <scope>/<page>` / `migrate` / `lint` / `on|off`；
- `/remember <文本> [--user|--project]`；
- `/memory lint` 用户级轻量体检（复用 lint，不并入项目 `/wiki-lint`）。

## 修复

- **记忆锁互斥失效**：改为「先递归建父目录、再非递归 mkdir」；新增跨进程写锁 + 2 分钟残留锁自愈（E2E 实测进程被杀会留锁，无自愈会永久卡死）。
- **`wiki_write append` 不同步 INDEX**：append 后刷新 INDEX 摘要与日期戳，log 类型显式化（自动写入用 `wiki`）。
- **append 顺序反了**（新内容插到旧内容之前）：改为真正追加到 `## 推理与依据` 段末。
- **首条输入噪音索引**：移除 `recordIndex` 启动钩子，由 TurnRecord 取代。
- **系统提示工具说明漏项**：补齐 `use_skill` / `task` / `wiki_search` / `wiki_write` / `remember` 说明。
- 全部记忆页写入改为原子写（tmp + rename）。

## 迁移

- `/memory migrate`：`profile.md` → `用户画像.md`；`~/.neo/memorys/raw/*.md` 归档为 `~/.neo/wiki/raw/legacy-memorys.md`；写 `.migrated-v2` 标记；**不删除旧数据**、幂等。
- 旧 `recordIndex` 不再写入；`~/.neo/memorys` 迁移后只读保留。

## 测试

- 新增 6 个测试文件：`memory-layout` / `memory-recall` / `memory-capture` / `memory-bridge`，覆盖双库布局、锁互斥（含真实子进程）、召回排序/预算/作用域、提炼校验、合并去重/冲突/推断分流、journal 恢复、Agent 注入生命周期、跨会话 E2E、工具作用域、命令面。
- 全量 **496 pass / 1 skip / 0 fail**（22 文件），`bunx tsc --noEmit` 零错误。
- 真实链路 E2E（本地实测）：`-p` 写入项目记忆 → 下次启动 journal 恢复 → 落页 `约定-提交信息规范.md`（含来源行、INDEX/log 同步）。

## 已知限制

- 后台提炼不阻塞主流程：会话/进程在提炼完成前退出时，journal 保留，下次启动恢复处理（这是设计行为，不是丢数据）。
- 提炼质量依赖模型，配置阈值/`/memory why` 可审计并可随时 `/memory forget`。
- `-p` 单次模式不参与用户级记忆（设计决策 D5）。
- 用户级推断可能不准确：一律带 `[推断]` 标记，召回时明确「不得当作硬性要求」。
