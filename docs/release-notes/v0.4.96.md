## 为什么发这一版

v0.4.95 之后 main 上有一组已合入、尚未发版的提交：#77 为 `-p` 增加 `--json-schema`，在 harness 层把进程级最终答案约束为符合给定 JSON Schema 的 JSON 值，并按输出格式单独返回。功能提交与发版提交分开：**本提交仅改版本元数据及文档，无新增运行时行为**，不改源码、测试、ACP 或 settings。不宣称与 Claude Code 或 Codex 兼容。

## 变更

1. `09bf228a9282a5568a50953b682dfb05a43e6310`（feat: -p --json-schema 结构化输出，#77）：
   - 仅 `-p` 增加 `--json-schema`：支持 inline JSON、`@path` / 普通路径、以及 `--json-schema=`。判断 inline 或路径前先 trim；以 `{` / `[` 开头当 inline，否则当路径（相对 `-C` / `args.cwd`，否则 `process.cwd()`）。缺值、读不到、JSON 解析失败、或不是可编译的 JSON Schema：exit 2 + stderr 诊断，一次模型请求都不发。`stream-json` 用法错误走既有 `error` + `result`（`status=usage_error`，`exit_code=2`）收口。无 `-p` 或与 `acp` 同用同样是用法错误 2。不叫 `--output-schema`。
   - 只做 harness 层 JSON Schema 校验，新增 pinned 运行时依赖 `ajv@8.17.1`。`format` 当注解、不强制。支持常见的 draft-07 与 2020-12；声明了无法编译的 `$schema` 视为非法 schema，exit 2。P1 不把原生 `response_format` / `text.format` 写进请求体。
   - 只校验进程级最终答案（drive 循环结束之后），不校验每一轮自动续跑的中间作答。不合规则把诊断回喂再跑，最多 2 次（共 3 次尝试）；空答案视为抽取/校验失败。回喂在 DriveManager 之外：不计入 `--max`，不重跑检查命令，可被 SIGINT 取消；回喂若再调工具，仍走既有权限 / `-y`。`--json-schema` 不强制 `-y`。
   - **drive 结束后的回喂可能再调工具、改变工作区，且不会重跑检查命令**；drive 退出来源仍按循环结束时计算。这一点已写入帮助文案。
   - 输出形状：`json` 仅在校验通过时增加 `structured_output`（解析后的 JSON 值，可以是对象、数组或 schema 允许的其它 JSON 值，不限定为 object），不改名、不删 `answer`；无旗标或最终不合规则省略该键，`answer` 仍保留原文。`text` 无旗标行为不变；带旗标时 stdout 只打这份校验通过的紧凑单行 JSON 值（不是 json 模式那整包信封），进度/工具改走 stderr；最终不合规时 stdout 不打正文，靠非 0 退出码和 stderr 诊断。`stream-json` 只在最终 `result` 携带该字段（已写入 `normalizeEventData` 的 result 白名单），中间事件键集不变。
   - 抽取偏严：先对整段最终答案 `JSON.parse`（允许前后空白）；失败时仅当 trim 后的全文是单个 `json` 围栏或普通围栏时再解围栏内容。围栏外还有叙述、或多个围栏，都不抽取；不在长叙述里扫描第一个 `{`。
   - 不新增退出码。若字段仍缺失且原来会是 0，改为 1（`json.ok` 仍等于 `exitCode===0`）。不借用 2（仅用法）或 3（drive `model_done`）。优先级仍是：用法 2（开跑前）→ EPIPE 1 → abort 130 → hadError/blocked 1 → drive 0/3/1。SIGINT 中止回喂为 130，省略该字段。`model_done` + 字段缺失保持 3 与 `model_done`。`stream-json` 若因 schema 把 0 改成 1，`status` 用 `failed`。
   - 不改 `src/acp/*`。交互 TUI、ACP、子代理、规划态、中间工具输出、无 `-p` 的 stdin oneshot，以及 Codex 式 `-o` 落盘，都不在本版范围。

## 验证

本地 Linux release worktree、清空残留 NEO_* 环境后运行 verify.sh。全新 worktree 按流程先执行 `bun install --frozen-lockfile`。安装后、改版本前的官方闸门见 `verify-after-install.txt`（当时 package.json 仍为 0.4.95）：tsc exit 0，2517 pass / 3 skip / 0 fail（148 文件），PTY 36/0，ALL GREEN；D1 通过（85.75ms）。改完版本后的官方闸门见 `verify.sh.log`，版本证据前缀为 v0.4.96：tsc exit 0，2517 pass / 3 skip / 0 fail（148 文件），PTY 36/0，ALL GREEN；D1 通过（83.53ms）。三条 skip 均为 worktree 下 prompt-tiers 找不到 bot-comments 源文件的既有豁免（不要设 `NEO_STRICT_SKIPS=1`）。

**D1 直述（必须保留）**：`oneshot-drive` 测试 D1（缺 `-y` 时预期零模型请求）存在**间歇性、根因未定**的失败。v0.4.95 及更早发版说明已记录观察。本版相关官方闸门补充如下：#77 功能提交在合入前，Amelia 独立重跑官方 verify 为 2517 pass / 3 skip / 0 fail（148 文件），PTY 36/0，ALL GREEN，D1 通过（86.23ms）；合入后 Leo 独立闸门为 tsc 0、2517 pass / 3 skip / 0 fail（148 文件）、PTY 36/0，D1 通过（81.70ms）。本发版 worktree 的官方闸门（安装后基线与改版本后）D1 结果见上，即使本轮通过，也**不能宣称已修好**。**官方绿不等于 D1 已解决**，根因仍未定位。D3 与 D1 不混同。
