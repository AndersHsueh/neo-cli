# v0.2.3

> 2026-10-25 · 界面补漏：**不丢信息、不吃输入、可回看、能回放**
> 上游版本 v0.2.2

## 背景

v0.2.2 把工具调用压成一行，屏幕清爽了，但代价暴露出来：**信息一旦滚过就永久丢失**。
本次不换渲染模型（inline + append-only + 终端 scrollback 仍是 2026 年的主流默认），
只修 5 个日常使用的漏，并把终端渲染的验证从「手工敲一遍」固化成仓库内脚本。

动手前先用真 PTY 复核了调研清单，**推翻其中最高优先级的一条**：「模型在工具批次之间说的话
不上屏」不成立 —— 正文经 `onContent → StreamFormatter` 实时上屏。真 bug 是同一条链路上的
流式状态泄漏（见下 D1）。

## 变化

### D1 正文前缀不再只出现一次（真 bug）

旧版 `agent.ts` 正常路径从不调用 `endStream`，Console 的 `streaming` 置 true 后再无复位，
下一批次的 `beginStream` 直接早退 —— **一次会话里 `●` 正文前缀只会出现一次**，推理块
`┌ think` 同理。现在每段正文/推理收尾都按记录下来的块类型复位。

```
● 第一段说明
 ⚡ read_file {"path":"a.txt"} ✓
● 第二段说明        ← 旧版这里没有 ●
```

### D2 宽度正确性

- `theme.truncate` 改为**按显示列**截断（CJK 安全）。旧实现按 code unit 切：
  `truncate("中文内容很长的字符串", 10)` 返回 20 列，窄终端里右侧被折断。
- 终端宽度回落值 100 → **80**（80 列是最普遍默认宽度；旧值系统性算宽 20 列）。
- 新增 SIGWINCH / `resize` 处理：动画行先定格成完整行再从新行重画，**不再用失效坐标
  吃掉用户正在输入的那一行**；计时器保留，长任务里 resize 不会让动画永久消失。
- 失败摘要不再挤掉工具名（旧算法在长路径错误下会把 `read_file` 压成 `read_fi…`）。

### D3 `/last`：紧凑模式的工具输出可以回看了

Console 内存缓存最近 **20** 次工具调用（名称/参数/耗时/完整输出，不落盘、不读 session json）。

```
/last        # 最近 1 次
/last 3      # 最近 3 次（时间顺序）
```

失败时紧凑行保持一行，但追加 ≤3 行错误正文（优先 stderr 首行 + `[exit N]`，
不再被 `$ cmd` 挤掉）和 `（完整输出：/last）` 提示。成功路径仍是 1 行，不回归 v0.2.2 的清爽。

### D4 `--resume` 不再恢复成空白屏

恢复会话后回放最近 3 轮（用户行 `❯ `、助手行 `● `），总行数上限 120，超长单段补
「本段还有 N 行未显示」。`-p` / 管道模式不回放，避免污染 stdout。

### D5 Ctrl+C 提示不再破坏提示符

旧实现超时后调用 `promptEcho("")` —— 打一行 `❯ ` 再换行，既不重绘 readline 也不恢复行缓冲：
敲到一半的字从屏幕上消失，回车却会把它发出去。现在提示写完/超时都把重绘交回 readline
（`setPromptRestorer` 注入），Console 不再自己画提示符。

```bash
bash scripts/verify.sh     # 或 bun run verify
```

`process.stdout.columns`，窄终端要在 PTY 内 `stty`。

## 已知边界

- 已输出的历史行无法重排（append-only 的本质）：resize 只保证「不再吃掉当前输入行」。
- `/last` 是**本进程内存**：`--resume` 之后旧工具输出不可回看（回放提示已明确说明）。
- 工具正文在紧凑模式仍不上屏（这是 v0.2.2 的设计），要逐条看请用 `/last`。
- `@` 文件补全、多行输入、底部常驻状态栏、轮次 diff 未做：见 v0.2.4 / v0.3 路线。
