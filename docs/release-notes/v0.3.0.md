# v0.3.0

> 2026-10-25 · TUI：**底部常驻状态条 + Claude Code 式输入框**
> 上游版本 v0.2.4

## 背景

v0.2.3 / v0.2.4 把「输出不丢信息、输入能补全」补齐了，但两个体验硬伤还在：

1. **跑 3 分钟的 turn 全程无反馈**：唯一的时间 / ctx / token 指标是每轮结束后的
   `showStats`。看不到「现在在干什么、跑了多久、上下文用了多少」——这是 v0.3 路线里
   [[TUI进化路线-2026Q4]] 的「常驻状态」段，也是团队日常使用最直接的阻碍。
2. **输入区不像 2026 年的产品**：单行 readline 文本，没有边界、没有模式提示、没有
   承载候选/活动/状态的位置。

本次仍然**不换渲染模型**：inline + 终端 scrollback，不引入 alt-screen。做法是把底部变成一块
**live 帧**（可重画区域），上面的历史只追加、永不重画 —— `Cmd+F` / tmux copy mode 照常可用。

动手前先写了 M0 探针（`scripts/tui-probe.ts`，真 PTY，P1~P4 全 PASS），确认了
raw mode / 按键形态 / 底部帧擦除重画 / 异步输出交错 / 退出后终端恢复全部可行，
才决定采用「自绘 live 帧」而不是「每 10s 打一行进度」的降级方案。

## 变化

### 一、底部常驻状态条

```
────────────────────────────── neo · neo ──
❯ 输入消息…
────────────────────────────────────────────
deepseek-flash · balanced · ask · ⎇ main · ctx ▓▓░░░ 42% · 0:42 · 12.3k tok
```

- 字段：**model · tier · 权限模式 · git 分支 · ctx 百分比 + 进度条 · 本轮已跑时长 · 累计 tok**；
  队列里有消息时追加 `⇥ N 排队`。
- 宽度不足按优先级降级（先丢排队/ tok /分支/时长，最后保底 `model · ctx`），**不折行**；
  60 列与 resize 中途切宽都有真 PTY 断言。
- 忙碌时顶线标题追加「运行中」，用户随时知道 agent 还在跑。
- 轮末不再打印三行状态栏，改成一行摘要（耗时 / 本轮 token / 工具数 / ctx / 累计），
  状态条本身常驻不消失。

### 二、Claude Code 式输入框

```
──── 顶部横线（右端：会话名 / 滚动行号）────
❯ 多行输入（首行 ❯，续行两空格对齐；光标反显）
──── 底部横线 ────
状态条
```

- **只画上下横线、不画左右边框**（宽度守恒：行宽恰好等于终端宽时不会二次折行）。
- 多行：`Ctrl+J` 换行（**最可靠**）；`Shift+Enter` / `Alt+Enter` / `Ctrl+Enter` 只在终端发送修饰键信息时可用（Kitty 键盘协议等），普通终端里它们与 Enter 同字节、会提交；
  行尾 `\` 等价；超过 8 行滚动窗口（顶线显示 `a-b/c 行`），不丢内容。
- 编辑：方向键 / Home/End / Backspace/Delete / Ctrl+A/E/K/U/W / 按词移动（Alt+←→）；
  退格与删除按**码点**（中文一次一个字、emoji 一次一个），光标按**显示列**定位。
- 历史：↑↓ 在首/末视觉行翻历史（前缀搜索，草稿保留）。
- 补全：复用 v0.2.4 的 `@` 文件 / `/` 命令补全；候选提示显示在框上方，连按 Tab 同批循环。
- 粘贴：bracketed paste 整体接收；小段多行直接进输入框，大段/超长折叠为
  `[Pasted text #N]` chip；`Ctrl+V` 贴图；**paste-end 丢包有 1s idle 兜底**
  （否则会永久吞键，这是 qwen-code 用注释标出来的坑）。
- 审批：问题显示在输入框上方（顶线变「确认」），输入框**不卸载**，`y/N` + Enter；
  批准后照常执行。
- 选择菜单（`/tier` `/model` `/mode` `/resume` 等）在 live 帧里渲染，↑↓/Enter/Esc。
- 双 Ctrl+C 退出（第一次一行提示，第二次退出）；Ctrl+D 空输入时退出；Esc 运行中取消本轮、
  空闲时清空输入。
- **非 TTY（`-p` / 管道 / CI）完全不进这套 UI**：保留 v0.2.4 readline 路径，输出零控制序列。

### 三、为了不闪/不串行做的工程件

- **原子帧**：一次 render 只写一次 stdout；支持的终端（iTerm2/WezTerm/Ghostty/Kitty/
  Apple_Terminal）包 `?2026h…?2026l`（DEC 2026 synchronized output），tmux/SSH 下自动关。
- **帧坐标单一来源**：光标行号只在 `FrameRenderer` 记账；提交行后归零（探针踩过的 bug），
  resize 先尽力擦旧帧再 invalidate 重画（S15 残影修复）。
- **Console 全量改走 dock**：流式文本按完整行提交、未完成行显示在框上方；
  工具行/spinner 变成 live 活动行（transient，persist 语义沿用 v0.2.3 的
  `yieldAnimationLines` 纪律）；失败详情仍落历史。
- **banner / 记忆提示 / `--resume` 回放**在 composer 启动前先缓存，启动后补写到帧上方。

## M0 探针（2026-10-25，bun 1.3.13，真 PTY 100×40）

| # | 问题 | 结论 |
|---|---|---|
| P1 | raw mode + 自解析按键 | 可用。Ctrl+O = `{name:"o",ctrl:true}`；**Ctrl+J 看 `sequence="\n"`、Enter 看 `"\r"`**；UTF-8 汉字是单个 keypress 且 `name=undefined`；bracketed paste 有 `paste-start/end` |
| P2 | 底部 live 帧「上移 N 行 + `\x1b[0J` + 整帧重写」 | 稳定：输入/提交/多行/帧高变化/连提 30 行/光标坐标全对 |
| P3 | 异步输出与输入交错 | 不互相破坏：12 行异步提交期间持续输入，内容完整 |
| P4 | 退出后终端恢复 | `stty -a` 显示 `icanon` 恢复，退出码 0 |

测不出的如实记：**真实 IME 候选窗位置**（PTY 无法模拟，发布前人工在 Terminal.app/iTerm2
输入中文验证）、tmux/SSH/Windows ConPTY 下的行为（只按 qwen 的经验做了开关与降级）。

## 已知边界

- **`Ctrl+O` transcript 视图与轮次 diff 不在本版**：分别留 v0.3.1 / v0.3.2
  （各自独立大件；共用 live 帧会放大回归面）。本版按 `Ctrl+O` 只给一行提示。
- **输入法候选窗位置**未能用 PTY 验证：实现把硬件光标定位在插入点并隐藏、自绘反显块；
  若你的终端 IME 候选窗偏移，请在真终端反馈。
- 启动瞬间（banner 打印期间）的按键没有做「early input capture」；极端情况下开头几个键
  可能丢/回显。日常使用无感，后续可按 qwen 的做法补。
- 历史上限仍是进程内 200 条（不落盘）；不支持撤销栈 / 选区 / Vim 模式（v0.3.x 候选）。
- 交互式 `!cmd` 会让出终端执行：已实现 suspend/resume（恢复 cooked、显示光标、擦帧）并在 PTY 验证了
  `!echo` 的输出与输入框恢复；**Ctrl+C 中断长子进程的回显/归还时序在 PTY 下不稳定，未纳入自动断言**，
  留 v0.3.1 改为「子进程输出走 pipe → dock」。
- resize 采用「按旧坐标尽力擦 + invalidate 重画」；PTY S15 覆盖了 100→60 的帧行宽不串行，
  但极端重排（pending/notice 行数变化）下可能留下旧行，属已知 best-effort。
- Linux/Windows 未实测；Windows ConPTY 的 bracketed paste/回车分块差异按 qwen 的经验留了
  idle 兜底，但未跑过 CI。
- 帧行数超过终端高度时只渲染输入窗口（不重排历史）；没有 alt-screen。

## 升级注意

- 版本号双源 bump 到 `0.3.0`（`package.json` + `src/index.ts`）；无配置变更。
- TTY 下的输入行为变化：`Shift+Enter` / `Alt+Enter` / `Ctrl+Enter` = 换行（以前无意义或提交）；
  `Esc` 空闲时 = 清空输入；`Ctrl+C` 仍是双击退出。
- 非 TTY（`-p`、管道、CI）行为完全不变。
- `/help` 已更新「输入」一节；`Ctrl+O` 提示 v0.3.1 提供。
- 终端需支持 ANSI 颜色与 bracketed paste（现代终端默认都支持）；不支持时退化为普通输入，
  不影响提交与命令。
