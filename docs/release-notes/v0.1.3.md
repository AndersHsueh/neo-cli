# v0.1.3

> 2026-10-18 · 补丁版本：工具调用预算 + 热键系统

## 新增

### 工具调用预算 —— 模型始终知道「第几次 / 还剩几次」

此前模型不知道存在工具迭代上限（`max_tool_iterations`，默认 40），会一路调工具直到被硬截断，用户拿到的是半截答案。现在每次 LLM 请求前注入一条临时 system 消息：

```
本轮工具调用：第 3 次 / 上限 80（已用 2，剩余 78）。
```

剩余 ≤ 5 时追加明确次数并要求收敛（只写「即将耗尽」模型无法判断还能做几件事，仍会继续探索）：

```
预算即将耗尽，仅剩 4 次工具调用机会。请停止继续探索，立即基于已有信息给出最终答案；
信息不足就在答案中明确说明缺什么，不要再用工具。
```

计数在每次用户新输入时归零。临时消息请求后立即移除，不进对话历史。

### 热键系统 —— ESC 中止回滚，Ctrl+C 双击退出

| 按键 | 空闲 | 运行中 |
|---|---|---|
| ESC | 无操作 | 取消本轮 + **历史回滚** + 回提示符 |
| Ctrl+C ×1 | 橙色提示 2s | 中断请求（半截历史保留）+ 橙色提示 2s |
| Ctrl+C ×2（2s 内） | 退出 | 退出 |

- **ESC**：输入错了 / 不完整时，取消当前轮并把历史回滚到本轮开始（含 user 消息），直接重输。回滚是刻意的——残缺对话不该留给下一轮。
- **Ctrl+C**：双击退出（模仿 Claude Code）。第一次按下底部闪现 2 秒橙色提示 `Press Ctrl+C again to exit`，窗口内再按才退出；运行中第一次按下中断请求但**不回滚**——跑了几十轮工具的进展不该被误按丢掉。两种中断不同语义，是设计而非不一致。
- 新增 `src/hotkeys.ts` 作为用户按键的唯一入口（`HotkeyRouter`）：以后加方向键等热键只需一行 `on("up", ...)`。Ctrl+C/Ctrl+D 归 SIGINT 信号语义，不经 keypress。

## 改进

- `max_tool_iterations` 默认值 40 → 80（`config.ts` 与 `settings.example.json`）。
- 达到上限的警告改为「本轮被截断 —— 上面的回答可能不完整」，明确告知后果。
- `AgentOptions` 新增 `chatStream` 注入点，测试可注入假 LLM（见下）。

## 不进 git 的配置变更

`settings.json` 在 `.gitignore` 中（本地配置含密钥），`max_tool_iterations` 需手动同步：

```diff
-  "max_tool_iterations": 40,
+  "max_tool_iterations": 80,
```

不改也行——缺省时回落 `config.ts` 的默认值 80，仅当你本地显式写过 40 才需要动。

## 测试

新增 `tests/hotkeys.test.ts`（13 用例）：HotkeyRouter 按键映射、doubleStrike 双击窗口、`rollbackOnAbort` 回滚语义。全量 277 pass / 1 skip / 0 fail，`tsc --noEmit` 干净。

测试基建教训：bun test 单进程共享模块表，`mock.module` 是进程级副作用（实测污染 `skill-budget.test.ts` 的 `estimateTokens`，M4 假失败）。正解是构造注入点——这也是 `AgentOptions.chatStream` 的由来。
