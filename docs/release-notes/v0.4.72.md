# v0.4.72 — 超预算提示 + 工具可见性 dry-run（issue #20）

## 背景

提示词 + 工具 schema 的总开销可能超出模型窗口预算，但 neo 此前超了也不说。本版（issue #20）做两件事：超预算时**明确告知**；并给出「按预算能显示哪些工具」的 dry-run 计算——只算不改，运行时行为不变。

## 改动

- **超预算一次性提示**（Step 0）：系统提示词放不进预算时，TUI 显示一次性通知（窗口、估计开销、预算、两条补救建议），启动诊断日志记 `kind=prompt-budget` 一条
  - 分类口径：这是**当前配置的可行动后果**，不归入 issue #18 的能力诊断（那些没有行动可做）
  - 仅交互模式：`-p`/pipe 绝不写 stdout，`--output-format json` 的 stdout 保持单行
  - 去重：按 `provider|model|window` 去重；打印位置在启动块内（banner 与记忆行之后）
- **工具可见性 dry-run**（Step 1）：新增 `src/prompt/visibility.ts`（296 行）——`visibleToolNames()` 按实测开销算出「放得下的最大工具前缀」；动态块裁剪（技能索引/wiki 索引/目录树）是 all-or-nothing；MCP 工具排最后
  - 成本模型复用选档自己的计数（`countSystemTokens`），对候选工具集合合成提示词：全集合合成结果与真实提示词**逐字节一致**（保真验证）
  - `/context` 新增 "visible tools" 行；运行时工具集与选档不变
- `src/prompt/manager.ts`：新增 `onSelection` 回调（仅在档位真重算时触发；回调抛错不影响渲染）与 `currentVisibility()` / `currentSelection()`
- PTY 新场景 S22c：验证通知位置

## 验证

- 运行时行为不变：8K/16K/32K/64K/200K 五个窗口下请求体（system + tools + 字段）与 v0.4.71 **逐字节相同**（fake gateway 验证）
