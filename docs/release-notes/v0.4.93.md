## 为什么发这一版

v0.4.92 之后合入两组提交：#81 / K01 把 legacy 上下文窗口算法委托给已 pin 的 core compat 归档（当时未涨版本），以及 #68 的 MCP 工具按需发现（功能提交 + 复审修复）。功能提交与发版提交分开：**本提交仅改版本元数据及文档，无新增运行时行为**，不改源码、测试、ACP 或 settings。不新开版本 PRD；#68 规格见 `docs/mcp-tool-search-prd.md`，#81 见 `docs/k01-compat-prd.md`。

## 变更

1. #81 / K01（`be6392c`、`7bb4a7e`、`38f50b6`、`5ddec0e`、`9d7e23c`；合入时版本仍为 0.4.92）：
   - `be6392c`：把 legacy 窗口算法委托给已 pin 的 `@neo/core-compat/compat/v1` 归档（`vendor/neo-core-compat-v1.tgz`）。本仓不再自持 known 表、错误正则/解析与基础 fallback 算法；保留 `configuredExplicit` 与旧 env 扩展来源适配，返回原 env 对象且不改变数值/优先级。
   - `7bb4a7e`：legacy 结果 DTO 从 core 公开类型派生，去掉一份平行形状。
   - `38f50b6`：兼容适配过程保留继承来的 legacy 窗口元数据。
   - `5ddec0e`：在工具链分离之后 pin 最终 core 候选。`vendor/compat-pin.json` 固定 core 候选 `6e38c30462f3e3c6fc0469cbaa7071f67a6c5993`、归档 SHA256 `6942996c08baaeedec00cce82091116a46877c7f22810c0917f348fc4d2258e4`，以及锁与构建器摘要；安装路径含 `compat:check` / `compat:install` 与普通 `bun install` 的 pin 校验。
   - `9d7e23c`：文档记录配对 pin、闸门与版本限制。不改 Matrix 协议/检查器，不改 ACP 源码。本片不宣称「旧融合窗口实现已退役」。

2. `e0dee18`（feat: MCP 工具按需发现，#68）+ `253b6bd`（fix: 自动压缩成功后重算 tool specs，#68）：
   - 默认 `mcp.tool_search=auto`，可延迟 MCP 数达到 `tool_search_threshold`（默认 10）才启用；`true` / `false` 强制开或关。不认 `ENABLE_TOOL_SEARCH`，不按窗口百分比判定。
   - 只延迟 MCP；第一方工具与内置 `tool_search` 始终全量装入。
   - 一个内置 `tool_search`（`query` + 可选 `limit`，默认 5、上限 10）：按名字/描述做可测的大小写不敏感匹配；命中立刻写入**本会话**已加载集合，同一 agent loop 下一次模型请求即可经现有审批调用。空查询或无命中返回明确空结果，不得随便装入。不拆 search/load，不设累计装入上限。系统提示里放目录短节（描述约 80 字，不含 schema）。
   - 直接点名已注册但未装入的 `mcp__*`：走现有审批并执行，同时加入已加载集合（含与 `tool_search` 同批并行）。未注册/编造的名字明确失败。不强制先搜索。审批与 `sensitive` 未放宽。
   - 已加载集合只在会话内存，按会话隔离（工具表仍是进程级）。仅在压缩**真正成功**、`/clear`、会话结束时丢弃；resume 不持久化，只保留 `alwaysLoad`（server 级，本单不做按工具名单）。PreCompact 阻断（#64 exit 2、历史保留）不得清已加载项。
   - 自动压缩或近窗压缩一旦成功落地，同一轮发给模型的 tools 会在 `mainStreamFn` 之前重算 `toolSpecsFor()`，非 `alwaysLoad` 的 schema 不再跟出。
   - 交互、`-p`、ACP 主会话同一套规则（经共享 `toolSpecsFor()` 进入 ACP，不改 ACP 协议/stdout）。子代理拷贝父会话当时已加载集合（新 Set，不写回），并自带 `tool_search`；wiki worker 不扩权；规划态不暴露 MCP / `tool_search`。
   - `/mcp` 仍全量列出；`/tools` 与 `/context` 区分「已装入上下文」和「仅目录」。#20 仍是 dry-run（按实际将发送的 specs 计量，不启用运行时裁剪）。用量、压缩估计与 PromptManager 选档按实际将发送的 specs，与请求同口径。目录短节随已加载集合更新（CLI 已在请求边界接线）。
   - OpenAI 兼容与 Anthropic 都把 `tool_search` 当普通 function / `input_schema` 工具，不走厂商专用 API。

## 验证

本地 Linux release worktree、清空残留 NEO_* 环境后运行 verify.sh，版本证据前缀为 v0.4.93：tsc exit 0，2406 pass / 3 skip / 0 fail（143 文件），PTY 36/0，ALL GREEN。全新 worktree 按流程先执行 `bun install --frozen-lockfile`（同时装入 `@agentclientprotocol/sdk` 与 K01 的 `@neo/core-compat`），安装后的基线官方闸门见 `verify-after-install.txt`（当时 package.json 仍为 0.4.92，证据前缀为 v0.4.92）；改完版本后的官方闸门见 `verify.sh.log`。本次没有发生安装前跑 verify 而失败的情况。三条 skip 均为 worktree 下 prompt-tiers 找不到 bot-comments 源文件的既有豁免。
