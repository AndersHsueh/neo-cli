# v0.4.48 — `@path` 引用漏剥中文右引号/右括号，引用静默不展开

## 问题

`@path` 引用解析（`src/input/completion.ts` 的 `stripTrailingPunct`）只剥 ASCII 的 `)]}` 与全角句读（`，。；：、！？`），**漏了中文右引号 / 右括号 / 书名号**。而 ASCII 右括号是剥的 —— 两边口径不一致。

| 输入 | 旧 path | 应得 |
| --- | --- | --- |
| `见 @a.ts）` | `a.ts）` | `a.ts` |
| `见 @a.ts」` | `a.ts」` | `a.ts` |
| `见 @a.ts》` | `a.ts》` | `a.ts` |
| `见 @a.ts】` | `a.ts】` | `a.ts` |
| `见 @a.ts」》】）` | `a.ts」》】）` | `a.ts` |
| `见 @a.ts)` | `a.ts` ✓ | `a.ts` |
| `见 @a.ts。` | `a.ts` ✓ | `a.ts` |

后果是**静默失败**：路径带上 `）` 后 `exists()` 返回 false，引用不展开、也不报错 —— 正文里就是没有内容块。这是最难排查的一类缺陷：用户看到的是「我明明 @ 了文件，怎么没生效」。

中文用户写「（见 @a.ts）」这种全角括号包裹是最自然的写法，触发概率不低。

## 根因

`TRAILING_PUNCT` 的字符集是手工枚举的，枚举时只想到了 ASCII 括号和中文句读，漏了中文的成对符号右半边。ASCII `)` 在集合里、全角 `）` 不在，说明这是**枚举遗漏**，不是有意的设计取舍。

## 改动

- `src/input/completion.ts`：`TRAILING_PUNCT` 补上中文右引号 / 右括号 / 书名号
  ```ts
  const TRAILING_PUNCT =
    /[,.;:!?)\]}，。；：、！？）］｝〕〉》」』】〗〙〛｠]+$/;
  ```
  只剥**尾部**：`@a（b）.ts` 中间的括号不动；以右括号结尾的文件名（如 `@foo）.md`）本来就不是合法路径，剥掉不损失。
- `tests/references.test.ts`：新增 `剥掉中文右引号/右括号/书名号`，覆盖 10 个单字符 + 叠加 + 全角括号包裹。

## 验证

- 红测：改前 `parseReferences("见 @a.ts）")` 的 path 是 `"a.ts）"`，期望 `"a.ts"`
- `bun test`：1157 pass / 0 fail / 71 files，3666 expect（v0.4.47 为 3654，+12 = 本轮新增断言；断言都在同一 `test()` 内，故测试条数 +1）
- `bunx tsc --noEmit`：exit 0
- 证据：`docs/evidence/v0.4.48-tests.txt`、`docs/evidence/v0.4.48-tsc.txt`

## 为什么不是「策略分叉」

ASCII 右括号已经剥、中文右括号不剥，这是同一规则的两半，补齐是修 bug。若反过来把 ASCII 括号也从剥离集里去掉（改成「一律不剥」），那才是改口径 —— 那会让 `(@a.ts)` 这种写法失效，与现有测试 `C3a 解析 > 剥掉尾随标点` 冲突。

## 本轮仍排除的候选

- **`nextDots` 域外返回值**：负数输入返回 `-1`/`-2`，`NaN`/`Infinity` 返回 `NaN`；`dotsText` 对同样输入做了 `((x % 3) + 3) % 3` 归一化，两者不对称。但 `nextDots` 唯一调用方 `ui/console.ts:450` 的 `toolDots` 每次工具调用重置为 0（`console.ts:442`）后只自增，**域外输入不可达**。属契约瑕疵，不是可触达缺陷。
- **`formatOutputLines` 窄宽溢出**：`room = Math.max(8, width - marginW - 2)` 在 `width < 10` 时输出超过终端宽度。但 `Console.cols()`（`ui/console.ts:142`）有 `n > 20 ? n : 80` 兜底，实际传入的 width 恒 ≥ 21，**不可达**。
- **`wrapAnsi` 末段重复 RESET**：`wrapAnsi("\x1b[31mabcdefghij\x1b[0m", 4)` 最后一段是 `"\x1b[31mij\x1b[0m\x1b[0m"`（两个 RESET 相连）。终端效果相同，只是多 4 字节，属输出冗余非行为错误；且紧邻 v0.4.35 的 RESET 逻辑。
- **末档封顶口径**（`formatBytes` / `formatTokens` / `clock` 的 `1e300` 科学计数法）、**C1 控制字符**、**三处 ANSI 剥离合并**：均为禁区，未动。
