# v0.4.16 —— 档位纪律抽成共享工具

## 为什么

v0.4.13（formatTokens）、v0.4.14（formatDuration）、v0.4.15（formatBytes）连续三次修的是**同一类缺陷**：`toFixed` / `Math.round` 把档内值进位到档边界（`9_999 → "10.0k"`、`59_950ms → "60.0s"`、`1023.95K → "1024K"`），输出既跨档（宽度突然多 1~2 列，状态栏与 `/last` 单行头抖动），又与下一档写法撞值。

三次都是各修各的，纪律只写在注释里、没有共享实现，`formatElapsed` 与 `formatDuration` 的 `m:ss` 拼装还各有一份。下次再加一个格式化函数，大概率第四次踩同一个坑。

## 改了什么

新增 `src/ui/format.ts`（纯函数、零依赖，不引入循环依赖）：

| 工具 | 语义 |
| --- | --- |
| `fixed1(x)` | 一位小数档，进位到 10.0 时降级为整数 `"10"`（token/bytes 口径） |
| `fixed1Raw(x)` | 纯 `toFixed(1)`，升档阈值交给调用方（时长秒档口径） |
| `rounded(x)` | `Math.round` 返回数值，便于与档宽比较决定升档 |
| `clock(sec)` | 秒 → `m:ss` / `h:mm:ss`，负数/非有限值按 0 |

四个调用点改为复用：

- `src/tui/status.ts`：`formatTokens` 用 `fixed1`/`rounded`；`formatElapsed` 收敛为 `clock(ms / 1000)` 一行。
- `src/ui/toolLog.ts`：`formatDuration` 秒档用 `fixed1Raw`，分钟以上走 `clock`（删掉重复的 `m:ss` 拼装）。
- `src/env/render.ts`：`formatBytes` 内联的 `fmt` 换成 `fixed1`。

**行为零变化**——这是纯重构，所有既有边界用例原样通过。

## 抽取时踩到的坑（已固化为回归用例）

第一版把 `fixed1` 直接用在时长秒档上，结果 `12_340ms → "12s"`、`59_940ms → "1:00"`，`tests/toollog.test.ts` 两条用例立刻红。

根因：`fixed1` 的「≥10 转整数」是 **token/bytes 的档内规则**（<10 一位小数、≥10 整数），不是通用的「一位小数」语义；时长的秒档要一直保留一位小数，只有进位到 `60.0` 才升分钟档。阈值不同（10 vs 60），不能共用一个降级函数。

修法：拆成 `fixed1`（降级到 10）与 `fixed1Raw`（不降级），`tests/format.test.ts` 的 F2c 专门钉住两者在 10~60 区间的分歧点。
