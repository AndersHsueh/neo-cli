## 为什么发这一版

`#35` 第 2 批四项全部落地：把「长会话压缩」「回滚操作」「后台子代理」「大仓探索」四个高频场景补完整。
过程与第 0/1 批一致：独立 worktree → 先红后绿 → simplify → 全量闸门 → ff-only 合入 → 关单；
两个卡住的回合由 Lead 接手补完（Oracle 的 PTY 根因定位、Tank/Keymaker 的改派）。

另附一条**测试-only**修正：v0.4.82 引入的 `-p` 资源回收集成测试在重负载全量跑时会假红
（`-p` 从起后台到退出 killAll 之间可能只有几十毫秒，ps 轮询窗口太窄）。已改为
「工具轮后延迟 800ms 再回最终答案」制造稳定观测窗口，断言仍是两段式（运行期必须看到进程 → 退出后必须消失）。

## 变更

- **定点压缩（#46）**：`/compact --from <轮次|last>` —— 以用户轮次为锚点，只压缩该轮之后的对话；
  更早的原文/摘要边界保持不动。切点落在工具链中间时整体前移到 `assistant(tool_calls)` 之前（保配对完整）；
  压缩后按 #39 机制平移 `/rewind` 轮次下标。
- **交互式 rewind 菜单（#47）**：空闲且输入框为空时连按两次 Esc → 轮次列表 → 选 code / conversation / both
  → 执行；Esc 取消。readline 会把连续两个 ESC 合并成单个 keypress（`sequence="\x1b\x1b"`），
  新增 `escape-escape` 动作识别；单 Esc 的 5 种既有语义不变；仅 TUI 路径。PTY 新增 S30。
- **子代理续聊（#48）**：子代理对话落盘到 `<sessions>/transcripts/<sessionId>/<jobId>.json`
  （60 条 + 单条 8k 上限、系统提示恒保留）；`runSubagent` 支持带历史继续；`/tasks chat <id> <消息>`
  接着追问。本进程内在跑的任务无历史，会明确提示。
- **仓库地图引用图排序（#49）**：纯文本解析 ts/js/py/go/rs 的 import/require 建引用图，按被引用度排序；
  引用度只用于排序、不进提示词正文；缓存改为目录 mtime/文件数指纹（20s TTL 兜底深层改动）。
  **未引入 tree-sitter**。
