# v0.4.4 —— 入口与循环拆分

> 行为不变。把两个过大的文件拆成可独立演进的模块。

## 为什么

`src/index.ts` 同时负责参数、REPL、全部斜杠命令、shell 直通和会话列表。
`src/agent.ts` 同时负责循环、权限、预算提示和压缩切点。
新命令和新宿主能力都得改这两处，改一处容易带出另一处。

## 结构

| 模块 | 职责 |
|---|---|
| `src/index.ts` | 组合根：解析参数、装配会话、跑 REPL |
| `src/agent.ts` | 兼容入口。测试和 `task` 工具仍从这里导入 |
| `src/agent/loop.ts` | 轮次循环 |
| `src/agent/policy.ts` | 权限判定。工具审批和 `!cmd` 共用 |
| `src/agent/steer.ts` | 工具预算、目标锚、手段计数提示 |
| `src/agent/compact.ts` | 压缩切点。不拆开 `assistant(tool_calls)` 与 tool 结果 |
| `src/agent/types.ts` | `AgentOptions` / `AgentIO`。新宿主能力加回调，不把具体模块 import 进循环 |
| `src/cli/commands.ts` | 斜杠命令实现。顶层 case 自动登记到注册表 |
| `src/cli/command-registry.ts` | 名字 → 处理器。未知命令在分发前拒绝 |
| `src/cli/version.ts` | 运行时版本只读 `package.json` |

新增命令的顺序不变：先在 `src/input/commands.ts` 登记，再在 `src/cli/commands.ts` 加 case。漂移守卫仍对照两边。

## 版本

`package.json` 是唯一发布真源。`--version` 与 `/help` 都读 `src/cli/version.ts`。
`scripts/verify.sh` 的证据前缀同步为 `v0.4.4`。
