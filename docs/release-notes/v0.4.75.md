# v0.4.75 — 按模型学习 max_tokens 上限 + Anthropic thinking 块跨轮回带

## 背景

对照 MiniMax 官方 Anthropic 文档并逐模型实测后的两处补强：

1. **max_tokens 上限因模型而异**（M3 系 524,288 / M2.7 系 196,608），而 provider 级 `max_tokens` 四个档位共用——配成 M3 可用的值，切到 fast 档的 M2.7 必然 400。
2. **带工具调用的多轮对话必须原样回带 thinking 块**（含 signature），否则 Anthropic 协议直接拒绝。

## 改动

- **max_tokens 上限学习**（`src/llm.ts`）：从 400/422 报错里解析该模型的上限，夹紧后**同轮重发一次**——不占重试预算、不改写用户配置、按 `provider|baseUrl|model` 记忆，并提示用户。上下文窗口类错误、鉴权错误、非 4xx 一律不认，避免误判与死循环
- **thinking 块跨轮回带**（`src/anthropicWire.ts`）：Message 新增可选 `thinking_blocks`；流式 `thinking_delta` + `signature_delta` 累积成带签名的块，**无签名的块丢弃**（回带必被拒），`redacted_thinking` 原样保留；`toAnthropicMessages` 把它排在 text/tool_use 之前
- OpenAI 请求体里剥掉该字段且不改写会话原消息；会话落盘/恢复保留；压缩与 token 估算**刻意忽略**（thinking 不占预算口径）

## 验证

- `tests/anthropic-provider.test.ts` 扩展 162 行；`tests/anthropic-thinking-agent.test.ts` 新增 136 行
- 真实 MiniMax 验证：M2.7-highspeed 在 max_tokens=512000 下自动夹紧到 196,608；M2.7 与 M3 的 4 轮工具对话每轮收到并回带带签名的思考块，结果正确
