# v0.4.74 — Anthropic Messages 协议 + provider `api_type`（anthropic 优先）

## 背景

此前 neo 只说 OpenAI 兼容协议，接 Anthropic Messages 协议的端点（如 MiniMax 的 anthropic 端点）必须靠网关转译。本版原生支持双协议：provider 新增 `api_type`，两种协议都声明时**优先 anthropic**。

## 改动

- `src/config.ts`：provider 新增 `api_type`（字符串或数组，旧的 `provider_type` 仍识别）
- **回退语义**：仅当 anthropic 端点不存在（404/405/501）时回退 openai 并记住结果；401/400/429/5xx **不回退**——换协议不能掩盖配置错误（鉴权错、参数错换协议也没用，只会把问题藏深）
- 新增 `src/anthropicWire.ts`（413 行）：内部消息保持 OpenAI 形态，Anthropic 只在请求边界转换——system 提顶层、tool 结果合并为 `tool_result` 块、`parallel_tool_calls` 换成 `disable_parallel_tool_use`、stop_reason/usage 映射回内部取值
- `src/llm.ts`：chat / chatStream / listModels 与 `/models` 能力探测共用同一份协议候选
- settings.example.json 与 README 更新

## 验证

- `tests/anthropic-provider.test.ts`：新增 422 行
- 真实 MiniMax（anthropic 端点）验证：chat、流式、工具往返、`-p` 端到端、双协议下 anthropic 404 回退 openai 均通过
