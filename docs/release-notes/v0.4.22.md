# v0.4.22 —— web_search 实体只解一次；转义标签不再被吞

## 为什么

`parseBingRss` 对标题/摘要做了**两次**实体解码：

1. `tag()` 内部 `decodeXml(m[1])`
2. 外层 `stripTags()` 又 `decodeXml` 一次

于是 RSS 里字面量 `<b>y</b>` 的正规转义写法 `&amp;lt;b&amp;gt;y&amp;lt;/b&amp;gt;`
第一遍解成 `&lt;b&gt;y&lt;/b&gt;`，第二遍解成真标签 `<b>y</b>`，再被
`stripTags` 的 `/<[^>]+>/g` 当标签剥掉 —— 用户只看到 `y`。

影响面：搜索结果标题/摘要里的代码片段、比较符（`a &lt; b`）、转义标签被静默吞掉，
模型拿到的是残缺文本，且没有任何错误信号。

## 改了什么

- `decodeXml` 改为**单次扫描**（一个正则 + 回调），解出的字符不再参与后续匹配。
  链式 `.replace()` 无论怎么排序都不等价于单次解码（`&amp;` 放最后则 `&amp;amp;` 又错）。
- `tag()` 不再解码，只取原文；解码由调用方做一次（`stripTags` / `decodeXml`）。
- `url` 侧显式 `decodeXml` 一次，保持原有行为不回退。
- 顺带补齐 XML 侧 `&#39;` / `&nbsp;`（与 `htmlToText` 对齐，此前只有 HTML 侧认）。

## 测试

新增 1 条：`&amp;lt;b&amp;gt;` 保留为字面量、`&amp;amp;` 停在 `&amp;`、
单层转义仍照常解码、url 侧同样只解一次。

全量 1107 pass / 0 fail；`tsc --noEmit` 干净。
证据：`docs/evidence/v0.4.22-tests.txt`、`docs/evidence/v0.4.22-tsc.txt`。

## 已知未修

`htmlToText`（src/tools/index.ts）仍是链式替换，`&amp;#65;` 会解成 `A`
（v0.4.21 已用测试固化为「已知非严格单次解码」）。同样的单次扫描方案可移植过去，
但会改变现有测试断言，留作候选。
