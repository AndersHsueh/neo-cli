# v0.3.2

> 2026-10-26 · v0.3.1 的 critical hotfix（发布后审查发现）
> 上游版本 v0.3.1（tag 保留在 `f28acf9`）；本版只修缺陷，不加新功能。

## 为什么发 hotfix

v0.3.1 推送后，质量审查发现一个**并发 critical**：

- `createIdentity` 在抢 `.alive` 锁**之前**就 `writeProfile`，且抢锁失败不回滚。
- 两个终端几乎同时 `--resume`/`/resume` 同一个已死会话时，失败方在抛 `session_alive` 之前
  已经把存活方的 `name/cwd/mode/pid` 覆盖成自己的；若失败方退出，存活方会被误判 dead，
  第三方可抢锁 → 同一 session 文件双写。邮箱失败「只降级」的前提也失效。

同轮审查还有一个 major：`cross_session_dead_after_ms` 未贯穿 `adopt`/`renameSession`，
配置非默认时名字查重与 resume 预检会使用不同存活口径。

## 修复

### 1. 抢锁成功后才写 profile（critical）

- `createIdentity` 顺序改为：选名 → `acquireAlive` → `writeProfile`；抢锁失败不再落盘，
  `writeProfile` 失败会 `releaseAlive` 回滚。
- `.alive` 锁内新增 `owner.json`（`{pid, at}`）：并发抢锁时用 **owner pid** 识别持有者，
  覆盖「锁已建、profile 还没写」的启动窗口；老锁没有 owner 时退回 profile pid/心跳。
- 活/死判定保持用户裁决：pid 死 → 立刻回收；pid 活但心跳 >120s（卡死/休眠）→ 回收；
  owner 新鲜但心跳未建立（正在启动）→ 拒绝双开。
- 回归 `R2h`：对同一 live id 再 `createIdentity` 必须抛错，且原 profile 的 name/cwd/mode/pid 不变。

### 2. deadAfterMs 贯穿（major）

- `Mailbox.adopt → createIdentity`、`renameSession → pickUniqueName`、启动 select 全部透传
  `cfg.mailbox.deadAfterMs`；`renameSession` 支持 `{nowMs, deadAfterMs}`（兼容旧数字参数）。

### 3. 同轮修掉的 minor

- `/sessions` 的「另有 N 个运行中会话」不再把当前会话自己算进去。
- 多行输入的滚动范围（`1-8/10 行`）从 Matrix 绿名字中拆出，恒 dim。
- 3 帧字符雨现在**每一帧都未收敛**，第 3 帧不再提前等于目标（此前实际只有 2 帧雨）。
- `/resume` adopt 时排除「即将退役的当前身份」，不再把目标旧名白撞成 `Trinity-2`。
- `--name` 缺值/空值/以 `-` 开头 → 用法错误 exit 2，不再静默随机或吞掉下一个 flag。
- 名字匹配优先于 session-id 片段（`neo` 不会被 base36 id 抢走）。
- 新增/加强测试：抢锁失败不污染 profile、adopt 不白后缀、名字 vs id 片段、3 帧雨宽度与
  未收敛、flash 中途 stop/setName、S19 精确标题（不接受 `Trinity-2`）。

## 验证

- `bunx tsc --noEmit` 零错误。
- `bun test` **876 pass / 0 fail（52 文件）**（v0.3.1 为 873）。
- `bash scripts/verify.sh` ALL GREEN，PTY **19/19**。
- critical 红态：在 v0.3.1 树上重放「同 id 再 createIdentity」→ 抛错后 profile 被覆盖；
  v0.3.2 修复后 profile 保持原值（`docs/evidence/v0.3.2-critical-red.txt`）。
- 版本双源 bump `0.3.2`；v0.3.1 tag 不移动（保留已发布历史）。

## 已知边界（记录不修）

- profile 损坏/缺失但 `.alive` 新鲜且无 owner 时，仍会保守拒绝双开；等心跳超时或手工清理。
- `sweepSessions` 仍按 `.alive` 存在判活（TTL 语义）；pid 死残留依赖下次 resume 回收。
- `listSessions()` 仍全量读+parse（存量 API 设计，v0.3.2 候选优化）。
- S18 暂无「交互 `/resume` 成功 adopt」的端到端断言（当前覆盖列表/取消/运行中拒绝）；
  单测 `mailbox.adopt` 已覆盖 id/name/退役。
