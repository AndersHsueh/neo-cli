> 2026-10-19 · 次要版本：空正文自动重试 —— 推理模型退化响应的自愈

## 修复

### 空正文自动重试（`src/agent.ts`）

推理模型（glm-5.3-flash 等）偶发只返回 `reasoning_content` 而 `content` 为空的退化响应。原实现只打一行 info 并把空 assistant 消息写入历史，用户拿到空回复，且空消息污染后续轮次（部分服务端会拒绝该消息序列）。

- **原因区分**：`finishReason === "length"` → 提示「输出预算被思维链耗尽，可调大 max_tokens」（README 记录过的坑：思维链本身吃几十 token）；其余（通常 stop）→ 模型把答案全写进思维链通道；reasoning 也为空 → 空响应。三类分别提示。
- **自动重试一次**：追加 user 提示（要求把最终答案作为正文输出）后重发请求；`nudgeMsg` 标记保证至多重试一次，不死循环。重试成功则摘掉提示、正常写正文；仍失败则 warn 后放弃，提示同样摘除——历史回到失败交换之前。
- **不再写入空 assistant 消息**：空回复留在历史里对模型自身也是错误示范。
- `dropBudgetMessage` → `dropTransientMessage`：重试提示与预算提示共用「按引用摘除临时消息」逻辑。

## 测试

- 新增 `tests/subagent.test.ts`「空正文自动重试」区块 3 例：重试成功后提示摘除、重试仍失败放弃且历史干净、length 场景针对性提示
- 原「子代理未产出报告」用例补第二个 step（重试消耗第二次调用，单 step fake 会脚本耗尽）
- 全量 402 pass / 0 fail / 1 skip，`tsc --noEmit` 零错误

## 已知限制

- 重试请求的消息数是 4 条而非直觉的 3 条（每轮请求前预算提示临时注入一条 system 消息），测试断言时需注意
- 重试消耗一次额外 LLM 请求，仅在退化场景触发，常规路径零开销
