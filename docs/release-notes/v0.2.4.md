# v0.2.4

> 2026-10-25 · 输入层：**文件引用、命令补全、多行输入**
> 上游版本 v0.2.3

## 背景

v0.2.3 补齐了「输出」侧的漏（不丢信息、可回看、能回放），但「输入」侧还停在 2023 年的水平：
`@` 只是纯文本、Tab 按下去什么都不发生、想贴一段多行 prompt 只能靠粘贴折叠成 chip。
本次按 [[TUI进化路线-2026Q4]] 的第一段推进，仍然**不换渲染模型**（readline + 自接管按键）。

## 能力

### `@` 文件补全（Tab）

- 输入 `@` + 路径前缀 + `Tab`：模糊匹配当前工作目录，路径边界加权（`src/ui/con` 优先命中 `src/ui/console.ts`）。
- 候选来源 `git ls-files --cached --others --exclude-standard`（尊重 `.gitignore`，2 万文件上限），
  非 git 目录回退到有界遍历（跳过 `node_modules/.git/dist/build` 等）。
- 索引在启动时后台预热（一次），之后按键路径只读缓存（TTL 5s，过期后台刷新）。
- 多个候选：第一次会打印候选提示行，**连按 Tab 在同一批候选里循环**（不是重新搜索）。

### `@path` 引用展开

提交时把文件内容附在消息末尾，模型不必再跑一次 `read_file`：

```
——— src/ui/console.ts（397 行）———
<content>
——— end src/ui/console.ts ———
```

- 预算：最多 5 个文件 / 单文件 400 行 / 总量 60KB；超限**截断并标注**（先 `stat`，不会为 50MB 文件整读）。
- 失败不阻断：文件不存在 / 二进制 / 预算耗尽 → 一行软提示，`@path` 按原文保留。
- 绝对路径与相对路径归一后去重；`@` 边界与补全共用同一判定（`读一下@src/a.ts` 也能触发，`a@b.com` 不误判）。

### `/` 命令补全（Tab）

- 行首 `/` + 前缀 + `Tab`：33 条命令全部可搜到（命令候选不设 20 上限），多候选打印提示行。
- 命令表 `src/input/commands.ts` 与 `handleCommand` 的 switch 有**双向漂移守卫**测试，任一侧漏改立刻红。

### `Ctrl+J` 多行输入

- `Ctrl+J` 续行：提示符从 `❯ ` 变 `… `，`Enter` 提交为**一条**含 `\n` 的消息，`Esc` 放弃续行；行尾 `\` 为等价触发。
- **非 TTY（管道/脚本）下 LF 仍按 Enter 处理** —— `printf '/help\n' | neo` 这类用法不受影响。
- 换行判定走 stdin `data` 事件的队列（一个数据块可能产生多个 line 事件；CRLF 只算一个 Enter）。
- 续行的半行会从 readline history 回滚（只回滚确实入过历史的非空行）。

## M0 探针与一次自我纠错

动手前先探 bun readline 的真实行为（`scripts/readline-probe.ts` + `docs/v0.2.4-m0-probes[done].md`，P1~P7 全 PASS）：

| 事实 | 影响 |
|---|---|
| 原生 `completer` **可用**（单候选自动补全、多候选第 2 次 Tab 列候选） | 「bun 不支持 Tab 补全」的说法**错误**（我最初在非 TTY 管道里探测得出，真 PTY 推翻了它） |
| completer 入参只有整行、**不给 cursor**；样式与排序不可控 | 仍选自接管 Tab：`@` 需要「光标前 token 精确替换」+ 同一批候选循环 |
| 不传 completer 时裸 Tab 会被当字面量 `\t` 插进缓冲 | 注册 no-op completer 从源头吞掉 |
| `Ctrl+J`(LF) 与 `Enter`(CR) 可区分，但 keypress/line 顺序由注册时机决定 | 换行判定改走 stdin `data` 事件（更早、稳定） |

## 已知边界

- 带空格的 `@` 路径暂不支持（需要引号语法，留给下一版）；`@` 指向目录不展开。
- Tab 只在空闲时接管（agent 运行中/审批问句/select 菜单期间不补全，避免与流式输出抢行）。
- 命令行里不提供 `@` 补全（避免补出来的 `@x` 在提交时被静默忽略）。
- 文件索引上限 20000 条；超大 monorepo 可能只覆盖前 2 万个文件。
- 启动多付一次索引预热（2 万文件实测 ~75ms，一次性）。

## 升级注意
