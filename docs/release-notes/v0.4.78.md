## 为什么发这一版

macOS 上托管 worktree 的清单**恒空**，复用必报「不是 neo 托管的 worktree」。

根因是路径比对口径不对称：代码拿**调用方传入的原始路径**去和 **git 报的 realpath** 比。macOS 的 `/var → /private/var`、`/tmp → /private/tmp` 是系统级软链，于是同一个目录有两种写法：

```
调用方给的是   /var/folders/.../repo
git 报的是     /private/var/folders/.../repo
```

字符串不等 → 4 处比对全部失配：

| 位置 | 失配后果 |
|---|---|
| `listManaged` | `relative(rootDir, item.path)` 得到 `../../private/var/...`，以 `..` 开头被跳过 → **清单恒空** |
| `ensureWorktree` | `listed.find(w => w.path === path)` 不等 → **复用失败**，随后误报「已存在，但不是 neo 托管的 worktree」 |
| `orphanDirs` | `known.has(p)` 不对称 → 真实托管目录被**误判成孤儿** |
| `detectRepo` | mainRoot 是 canonical、调用方 repo 常是原始路径 → **「不套娃」断言在 macOS 不成立** |

Linux 上 `/tmp` 不是软链，CI 恰好是绿的 —— 那是平台巧合，不是正确性。

## 变更

### 1. 边界归一：新增 `canonicalize(p)`

修法不是逐处打补丁，而是在**边界**统一口径。新 helper 走「祖先归一 + 拼回尾部」：

```
1. p → resolve(p)
2. 从深到浅找第一个**已存在**的祖先 cur
3. head = realpath(cur)（展开软链）
4. 返回 head + 原样拼回剩余的不存在段
```

为什么只对**已存在的祖先**做 realpath：托管叶子（`.neo/worktrees/<name>`）在首次 `ensureWorktree` 之前并不存在，整条路径直接 `realpathSync` 会抛 ENOENT —— 而要比较的恰恰包含「尚未创建的托管路径」。

不存在的尾部原样拼回，**不写死 `/private`、不依赖开发机目录形态**。

### 2. 四处比对点统一走 canonical

- `listManaged`：`rootDir` 与 `item.path` 两侧归一后再取 `relative`；
- `ensureWorktree`：复用查找改为 `canonicalize(w.path) === canonicalize(path)`；
- `orphanDirs`：`known` 集合按 canonical 存；
- `detectRepo`：`mainRoot` 返回 canonical（源侧口径），调用方与测试侧都按 canonical 比较。

### 3. 测试

新增 h 组 9 例（软链路径下 list / reuse / 混合写法复用 / remove / orphanDirs / detectRepo，外加 3 条安全断言）。用例会**显式造软链**而非依赖开发机 `/tmp` 形态，因此两个平台都验证同一条不变量。

「不套娃」断言改为 canonical 口径，并**补一条更强的语义断言**（新建的 worktree 不在另一个 worktree 内部套娃），确保契约没被削弱。

### 4. 安全断言未削弱

以下三条在软链路径下重跑，仍然成立：

- 不是 neo 托管的 worktree → **绝不覆盖**；
- 当前会话所在的 worktree → **永不删**（`--force` 也不放行）；
- 脏工作区 → **拒绝删除**。
