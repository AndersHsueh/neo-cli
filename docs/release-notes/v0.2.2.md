# v0.2.2

> 2026-10-20 · 界面优化：**工具调用紧凑单行显示** —— 默认不再刷屏，详情可配置开关
> 上游版本 v0.2.1

## 背景

真实双会话里，一次任务连续调用 7 次 `list_dir`，每次都打印 header + 缩进结果块，
把真正重要的信息（模型判断、用户指令、跨会话消息）冲散。终端用户不需要逐行阅读
工具调用的原始输出；模型仍然需要，只是不该占屏幕。

## 交互设计

默认（`toolcall_info_details: false`）：

```
 ⚡ list_dir {"path":".","limit":5} .
```

- 只占一行；`.` / `..` / `...` 每 350ms 循环，表示正在执行。
- 下一个工具调用到来时，光标回到行首覆盖上一行，**不新增行**。
- 工具完成后尾标变成 `✓`；失败变成 `✗` + 错误首行摘要（最多一行，超出截断）。
- 工具原始输出不再打印（模型仍收到完整结果；需要看时把开关打开）。
- 模型/用户输出开始前自动收尾换行，不会和 `●` 正文粘连。

详情模式（`toolcall_info_details: true`）：恢复 v0.2.1 的旧版行为（header + 缩进结果块）。

## 配置

settings.json 顶层（默认 false）：

```json
{ "toolcall_info_details": false }
```

同时接受连字符写法 `toolcall-info-details`（兼容手写习惯；项目惯例仍是 snake_case）。

**作用域**：紧凑模式只在 TTY 生效；`-p` / 管道 / CI 等非 TTY 环境保留逐行详情，
避免 `\r` / ANSI 控制符污染日志与脚本输出。

| `src/ui/toolLine.ts` | 纯格式化：点号循环、单行宽度收敛（含 CJK 宽度）、✓/✗/错误摘要截断 |

## 验证

- 新增 `tests/toolcall-display.test.ts`（7 例）：点号循环、✓/✗、长参数/CJK 错误摘要宽度收敛、配置默认与别名。
- 全量 **530 pass / 0 fail（27 文件）**，`bunx tsc --noEmit` 零错误。
- PTY 渲染实测：
  - 紧凑模式最终屏幕只有一行 `⚡ send_message … ✗ 错误: 找不到目标`，工具结果正文未出现；
  - `toolcall_info_details: true` 时旧版 header + 结果块正常显示。

## 已知边界

- 紧凑模式下工具错误只留首行摘要；完整错误把开关设为 true。
- 非 TTY 不做紧凑（日志可读性优先）。
- 若工具执行期间有审批/通知插入，当前工具行会先收尾换行，之后的结果状态另起一行。

## 升级注意

- 版本号双源 bump 到 `0.2.2`；无配置变更也生效（默认紧凑）。
- 想回到旧版显示：settings.json 加 `"toolcall_info_details": true`。
