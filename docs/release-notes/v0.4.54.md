# v0.4.54 — 瘦网关输出上限写回不再静默（#6，经 #7 PR 交付）

## 背景

issue #6：瘦网关（不透出 `max_output_tokens` 的网关）场景下，输出上限的探测写回是**静默失败**的——撞了长度墙、写回逻辑跑了，但网关就是不吐字段，用户看不到任何提示，也不知道 neo 到底知不知道上限。修复经 PR #7 交付（含 `fix(#6)` 提交 `ae642d1`），本版 tag 收口。

## 问题

- 长度截断（带部分文本或工具调用）时，旧逻辑不尝试 `/models` 写回
- 网关始终不吐 `max_output_tokens` 时，写回什么都不发生，`/context` 与 `/env` 也不说明原因

## 改动（含 ae642d1 的实现体）

- **放宽写回触发**：长度截断且带部分文本/工具调用时，也尝试 `/models` 写回——但仍然只填空字段，不覆盖用户值
- **诚实提示**：网关确实不吐上限时，`/context` 与 `/env` 明确说明「网关未暴露输出上限」，不再无声
- **预算分离**：请求预算 `max_tokens` 与模型输出上限 `max_output_tokens` 分开维护，互不串写
- **逐字段首次使用探测**：能力位按字段独立探测
- `/models` 探测超时 5 秒，可配置
- `settings.example.json` 补示例；测试面覆盖 context-command / context-window / model-capabilities / model-caps-writeback 四个文件

## 验证

- `tests/model-caps-writeback.test.ts` 扩展 383 行；`tests/context-command.test.ts`、`tests/context-window.test.ts`、`tests/model-capabilities.test.ts` 相应扩展
- 依据说明：本篇依据提交 `1580fa9`（tag）与 `ae642d1`（实现）的完整消息与 diff 撰写；`docs/evidence/` 无本版本证据文件
