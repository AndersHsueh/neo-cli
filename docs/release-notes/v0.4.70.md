# v0.4.70 — 探针回调不改写在途提示词 + 在途护栏（issue #20）

## 背景

窗口探针是异步的：回调完成时主请求可能还在流式中。若回调立刻重渲染 `messages[0]`，同一轮里前后请求会带**不同的系统提示词**——messages 是活引用，工具循环与重试会再发同一份数组。本版把「探针回调保持提示词陈旧」落成明确语义，并加上护栏。

## 改动

- 语义明确化：探针回调只改 cfg 状态（`resolveAndApplyModelWindow`），**不主动重渲染**；升档由下一个请求边界统一生效（PromptManager.render 的指纹含窗口/来源，cfg 一变指纹就变）
- 理由：render() 还会同步做文件 IO（目录树/技能/wiki 索引），中途重渲染既危险又慢
- `src/agent/loop.ts`：Agent 新增**在途护栏**——请求发出到返回之间 `refreshSystemPrompt` 直接返回，不改写 `messages[0]`。此前这条只是注释里的约定，无法被测试钉住；现有调用点全在请求之外，行为不变
- 溢出校正（窗口变小）同样只在下一轮边界重选，与探针路径一致
- 测试方法：注入 chatStream 挂住第一次请求，探针走真实的 `resolveAndApplyModelWindow` + env 快照，断言在途不改写、本轮后续请求同档、下一轮才升档
