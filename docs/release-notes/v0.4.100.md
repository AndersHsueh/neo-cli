## 变更

按合入时间顺序。

1. `be9996e04a726b0cff122be56ebfc88f771ee5cd`（test）、`15540ec63bb3c17ed79c3a8b36558d9dbfc55d1b`（feat）、`52515749e37890e4948f4ba2ccedf17e935766ae`（test）、`d81941f8964f19a44af380912f3d75d5e494b418`（fix：首跑结算后再启动 refreshInterval）（#57 可脚本化自定义状态栏）：
   - 从获胜的那一份 `settings.json` 顶层 `statusLine` 读一条 shell 命令（第一份存在的文件全赢，不合并多层），把会话 JSON 从 stdin 喂给它，把退出码 0 的 stdout 画在输入框与内置状态行之间。不替换内置状态行。未配置、`command` 为空、`--safe-mode`、`-p`、非 TTY、ACP 都不跑命令。
   - 这不是 hook：不走 hook 执行器，也不登记进 hooks。超时默认 2 秒、上限 10 秒。事件防抖 300ms；会话开始第一次立刻跑；可选 `refreshInterval`（最小 1 秒），且等首跑结算后再计时，避免首跑超过间隔时被提前杀掉。失败 / 超时 / 非 0 / 空输出只让自定义区空白，不往对话打错误。
   - 多行最多 5 行（丢底部）；`padding` 上限 8；stdout 硬上限 8KiB。JSON 只含 neo 能诚实给出的字段；没有费用、`rate_limits`、`prompt_cache`，也不输出 `transcript_path`。不提供 `/statusline` 命令，只支持手写 settings。改配置要新开会话（不做 settings 热重载）。
   - 这不是沙箱，也没有工作区信任对话框。用户 settings 里的命令按用户权限跑，口径与 hooks 相同。不宣称与 Claude Code 官方 statusline 或社区脚本开箱即用。

2. `0e1ec41376b3255654aad451021edb7e9f8e99bf`（fix: 启动时 provider 与 model 不再交叉绑定）：
   - 旧 `loadConfig` 用 `default_provider`（或 `NEO_PROVIDER`）的 endpoint，却用 `model_routes[档位]` 里另一家的模型名。无 `--provider` / `--tier` 的启动就会把两套拼在一起，启动屏和运行时请求都是这套混绑（例如 provider minimax、endpoint `api.minimaxi.com`、model 却是 `glm-5.3-flash`）。
   - 启动时先按当前档位走 `model_routes`；若显式写了 `default_provider` 或 `NEO_PROVIDER`，且与路由供应商不同，再按 CLI `--provider` 语义切换：档位不变，模型改用该 provider 在此档位下的模型。`NEO_MODEL` 等覆盖仍然生效。不自动改写用户的 `settings.json`。
   - settings 搜索顺序未变：第一份存在的文件全赢（工作区 → 包装根 → `~/.neo/settings.json`）。若在 neo 仓库目录里启动，仓库根的 `settings.json` 仍会赢过用户级文件。

3. `098dc0b40a1225b381364b5e80bdce682ecc0a9c`（test: statusline 的 version 断言跟随 package.json，#57）：
   - `#57` stdin JSON 测例不再写死 `0.4.99`，改为使用 `VERSION`（读 `package.json`）。否则把版本改到 0.4.100 时该测例会红。生产路径本来就把 `VERSION` 传入 payload。无运行时行为变更。
