# v0.3.3

> 2026-10-26 · v0.3.2 的并发 hotfix（发布后质量审查发现）
> v0.3.1 / v0.3.2 tag 保留不移动；本版只修缺陷。

## 为什么又发 hotfix

v0.3.2 修掉了「抢锁失败覆盖 profile」，但质量审查在 `a6ddfbc` 上又发现两条 resume 并发窗口：

1. **index 把 resume 的身份失败当“信箱降级”继续跑**（critical）
   `--resume` 的活进程检查是 check-then-act；`createIdentity` 抛 `session_alive` 后，main 只
   `ui.warn` 并 `mailbox=null`，但 `sess` 已经 `adoptSession(meta)`。后续 `persist` 仍写同一
   会话文件 → 两个近同时 `--resume` 会双写，进程还 exit 0。
2. **owner.json 保护被心跳条件门住**（critical）
   v0.3.2 的 `startingFresh = !isFinite(heartbeatAge) && ownerFresh`：崩溃残留会话的
   state/profile 都存在（旧 mtime），`heartbeatAge` 永远 finite → owner 新鲜也判 dead，
   P2 会 `rm .alive` 接管 P1 刚抢到的锁。实测 P2 成功写走 P1 的 cwd/name。

还有一个无 owner/无 profile 的退化：v0.3.2 会直接回收，而 release note 承诺“保守拒绝”。

## 修复

### critical 1：resume 身份失败 = 致命 exit 2

- `meta`（resume 命中）时 `createIdentity` 失败不再降级：打印「另一个进程可能正在恢复/运行该会话」
  并 `return 2`；新建会话才保留 mailbox 降级。
- 因此双进程 `--resume` 只有一个能继续，另一个在写会话文件前就退出。

### critical 2：owner 新鲜独立保护启动窗口

- 抢锁判定改为：
  `running = pidAlive(pid) && (heartbeatFresh || ownerFresh)`；
  无 owner 且无 profile、但 state 心跳新鲜 → 保守拒绝（不能确定 pid 时宁可等）。
- 用户裁决仍保留：pid 死 → 立刻回收；pid 活但心跳和 owner 都超时（卡死/休眠）→ 回收。
- 老锁（无 owner.json）退回 profile pid + 心跳判定。

### 同轮 minor

- `--resume` 不再无条件吞下一个 argv：`neo --resume --name X` 现在是「resume last + name X」，
  `--resume -p "q"` 也不会把 `-p` 当 session id。
- S19 改为 `--name Trinity` 起会话再 `/rename neo`（避免随机名恰好 neo 时 10–20s 动画造成假红）；
  busy 窗口用 `slow-800`；S18 的 E 先 `waitFor` 报错再 `waitExit`，避免 stdout 未排空假红。
- 新回归：`R2i`（owner 新鲜 + 旧 state 心跳 → 第二个 createIdentity 不得接管）、
  `R2j`（无 owner/无 profile 但心跳新鲜 → 保守拒绝）、`R2h` 增加 `.alive/owner.json` 未被抢断言；
  `R2e`/`F5` 更新为「心跳与 owner 都旧才 takeover」。
- 红/绿：`docs/evidence/v0.3.3-owner-red.txt`（v0.3.2 接管成功并写走 cwd/name；v0.3.3 拒绝）。

## 已知边界（记录不修）

- 交互 `/resume` adopt 后 `MemoryBridge` 的 sessionId 仍是旧 id（启动 `--resume` 路径没有该问题）；
  记忆 capture/audit 会按旧 id 记录。属于记忆桥 API 的后续改造，不影响会话文件/信箱身份。
- S18 仍无「并发双 `--resume` 恰好都越过预检」的集成断言；本轮用 `createIdentity` 层 `R2i`
  锁定接管窗口，index 致命退出路径由代码分支保证。
- 其余同 v0.3.2：损坏 profile + 新鲜锁且无 owner 保守拒绝、`sweepSessions` 按 `.alive` 判活、
  `listSessions()` 全量解析。
