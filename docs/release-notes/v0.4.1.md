# v0.4.1 —— 实战可靠性修复 + askUser 特性

> 发布日：2026-10-27
> 基线：v0.4.0（974 pass / 59 文件 / PTY 19）
> 发布闸门：tsc 0 错 · **1027 pass / 0 fail / 66 文件** · **PTY 20/20** · `ALL GREEN`
> 证据：`docs/evidence/v0.4.1-{tsc,tests,pty}.txt`

## 为什么发这一版

2026-10-26 下午的售前资料分析实战暴露了 15 个真实问题，最严重的是：

- 会话跑到 **184k tokens** 仍未触发压缩（配置 512k，模型真实窗口未知）；
- 最后一轮「重试」**没有 assistant 回复、没有报错**，mailbox 仍记 `outcome=ok`，用户只能换会话；
- 显式 `remember` 回执「已登记」，实际提炼结果因「append 目标页不存在」被静默丢弃；
- `use_skill karpathy-ax-html` 报「技能不存在」；`extract-assets.sh ./outputs` 产出 `outputs/outputs/assets`；
- xlsx dump 被 `tool_output_limit` 截断后，中间内容永久丢失；
- 56/66 条 shell 命令靠模型手写 `cd`；101 次工具调用里 0 次 web_fetch；
- TUI 缺少「向用户提问」的组件，模型遇到歧义只能猜。

本版按 B1–B5 五批修复，全部有回归测试。

## 新特性

### askUser 提问组件（TUI）

模型可在关键分叉/歧义/破坏性操作前调用 `ask_user`：

- 单选：`↑↓` + Enter；多选：`Space` 勾选 + Enter；自由输入：「其他（自行输入）」或纯文本提问；
- `Esc` 取消，`Ctrl+C` 取消并沿用中止语义；答案以 JSON `{status,selected,custom}` 回给模型；
- 只在交互 TUI 注册：`-p` / 管道 / 子代理看不到该工具；`-y` 不会自动回答；
- PTY 场景 S20 覆盖「问题/选项可见 → 选择 → 模型继续」。

### 上下文窗口自动探测 + `/context`

- 启动时从 env 事实文件恢复窗口，并异步探测 `/models` 元数据；
- 服务端返回 400/413 上下文超限时，解析真实上限（128000 / 200k / 1m），持久化到
  `~/.neo/env/<machineKey>.json` 的 `models` 字段，压缩（失败则裁剪旧工具输出）后同一轮重试一次；
- `/context` 显示窗口及来源（config/models_api/overflow_error）、阈值、估算用量、消息数、最近压缩；
- `/env refresh` 顺带探测并展示模型窗口事实。

### 其它

- `web_search`：Bing 中国站 RSS，无需 API key，返回标题/URL/摘要（实测联网可用）；
- `shell` 新增 `cwd` 参数：只影响本次调用，不改变会话 cwd；
- 超长工具输出：完整内容落盘 `~/.neo/tmp/tool-*.txt`（0600，`NEO_TMP_DIR` 可覆盖；plan 模式不落盘），返回头尾 + 路径；
- `/export [session-id]`：导出 Markdown 到 `<cwd>/.neo/exports/<id>.md`；
- `skills_extra_paths` / `NEO_SKILLS_PATHS`：额外只读技能目录（外部技能包可直接接入）。

## 可靠性修复

| 问题 | 修复 |
|---|---|
| 空转静默成功 | 连续两轮空正文 → `hadError/emptyResponse`、明确错误、诊断日志；`finishReason=length` 自动放大 max_tokens 重试一次 |
| 无日志可查 | 每轮元数据 JSONL：`~/.neo/logs/turns/YYYY-MM-DD.jsonl`（不记 prompt 正文，30 天/5MB 滚动） |
| resume 不知道上次失败 | `session.meta.lastTurn` + 恢复时显式告警 + `/sessions` ⚠ 标记 |
| remember 假成功 | 等待 capture audit（≤15s），如实回「已写入/未写入+原因」；显式记忆不再被 confidence/页存在性规则丢弃 |
| 捕获没有轮次记录 | 被价值判定过滤/abort 的轮次也写 `skipped` 审计；`/memory status` 展示最近 3 条 |
| 技能找不到 | 额外技能路径 + `not_found` 错误列出已搜索目录与配置提示；修复外部 `extract-assets.sh` 的 `outputs/outputs` 与 `--force` 解析 |
| 运行时垃圾只增不减 | 启动清理 7 天前的 `.neo/tmp` 与已死 mailbox 会话目录 |

## 升级注意

1. **窗口来源变多**：`settings.context_window` 仍是默认值，但 env 探测/溢出学习会覆盖它；
   `/context` 会显示来源，怀疑覆盖错误可删 `~/.neo/env/<machineKey>.json` 的 `models` 字段。
2. **remember 变慢**：显式记忆要等提炼落页（通常数秒，上限 15s），换来真实回执。
3. **工具数 10 → 11**：新增 `web_search`；若你有脚本断言工具清单需同步。
4. **ask_user 只在交互模式**：CI/`-p` 里模型看不到它。
5. **工具输出落盘改到 `~/.neo/tmp`（0600）**，不再写进项目仓库；tmp 默认保留 7 天，启动时清理。
6. **env 快照兼容**：`EnvStatic` 仍为 version 1，新增可选 `models` 字段；旧快照可读。

## 已知限制

- Windows 实机验收仍未做（PD-1，沿用 v0.4.0 实验性标记）。
- askUser 未做「每轮最多 N 次」硬限制；靠提示词与用户 Esc 兜底。
- `glm-5.3-flash` 在 ipsa 网关的 `/models` 不给窗口元数据时，只能等一次溢出错误学习；
  首次长会话仍可能先撞一次 400（会自动压缩重试，不会静默失败）。
- 数字类 Python 脚本报错（`too many values to unpack`、`range.end`）属模型生成代码问题，
  本版只通过提示词/工具输出改善，不 hack harness。
