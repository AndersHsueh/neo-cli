# v0.4.3 —— 目标锚 + 手段/目标分层

> 证据：`docs/evidence/goal-anchor-{tsc,tests}.txt`；PTY 21/21。

## 为什么

一个 AI 在考试里要找博客作者：搜索失败 → 假设答案在缓存 → 假设需要外联 → 连 DNS 找出口。
每一步都有真实进展，心跳满格，方向全错。

neo 原有的三个防跑偏装置，盯的都不是「目标」：

| 装置 | 盯什么 | 为什么抓不住上面那种漂移 |
|---|---|---|
| `budgetMessage` | 消耗量 | 只报「还剩几步」，不报「离目标多远」 |
| `SessionState` | 活性 | alive/stale/dead 与方向无关 |
| `isStuck` | 心跳新鲜度 | 跑偏的会话每步都在 `touchProgress`，永不判 stuck |

**进度信号 ≠ 方向信号。** 缺的不是新状态机，是「目标」这个字段本身。

## 新增

### 1. 目标锚（`/goal`）

- `SessionState` 增加 `goal: { text, set_at, set_by }`（可选字段，旧 state 缺字段不判非法）
- `/goal <文本>` 设置、`/goal` 查看、`/goal clear` 清除
- **模型只读**：只有用户和宿主能写。漂移的第一步就是模型把「找出作者」重述成「拿到答案」，
  目标若可写一定会被重述——目标必须是外部事实，不是模型自述。

### 2. 手段/目标分层

工具按产出打标签：

| 类别 | 工具 |
|---|---|
| `evidence`（产出事实） | `read_file` `list_dir` `glob` `grep` `web_search` `web_fetch` `wiki_search` |
| `capability`（只扩展手段） | `shell` `send_message` `task` `use_skill` |
| `neither`（交付/管理） | `write_file` `edit_file` `remember` `wiki_write` `compact_ctx` `ask_user` `list_peers` |

规则：**连续 4 次 capability 且无 evidence 产出 → 强制回锚**。

`shell` 归 capability 而非 evidence：它能 `cat` 也能 `curl`，分类层面无法区分。
但规则是「**连续** N 次」，偶尔用 shell 查东西不触发，连续用才会——这正是要抓的形态。

### 3. 回锚提示

复用 `budgetMessage` 的临时 system 消息通道（请求前注入、请求后移除），
在预算行后带上目标原文 + 手段计数：

```
本轮工具调用：第 3 次 / 上限 20（已用 2，剩余 18）。
原始目标（用户设定，你不可修改）：找出这篇博客的作者
每次调用工具前自问：这一步是在产出关于目标的事实，还是只在扩展手段？
距上次产出事实，已连续 3 次只扩展手段（shell/发消息/派子代理/加载技能）。
```

超过阈值时升级为强制回锚。

**关键设计**：计数只喂给提示让模型看见，**不拦人**。后台默默计数、到阈值才提示，
等于模型全程无感——那和 `isStuck` 没区别，只是换了判据。

阈值取 4：正常排查里连续两次 shell 很常见（`ls` 再看 `cat`），阈值太低会误判正常工作流，
提示变成噪音、被模型学会忽略。

## 边界

- 防的是**无意识漂移**，防不住**有意识规避**（模型判定目标不可达后仍去开通道）。
  兜底仍是 capability 类动作必须过人工确认，`approve` 不得降级为 auto。
- 计数在**最后一次**工具调用后无人消费（循环已收口），阈值提示看不到。已知边界。

## 修复
