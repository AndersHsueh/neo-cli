## 为什么发这一版

`selectPromptTier` 在连 `mini` 也超过 12.5% 系统提示词预算时已经返回 `fits=false`，但请求仍带着全套动态块和全套工具 schema 发出去，超预算提示按未收窄的估计来报。116K 这一档的窗口因此会一直看到「放不下」，尽管可见集算法从 v0.4.72 起就算好了。本版只在 `fits=false` 时把这套收窄接到真正发出的系统提示词和工具 schema 上，收窄后落入预算就不再按收窄前的开销报警。

功能提交与发版提交分开。功能在 `39320ac` 与 `0086255`（PR #105 快进合入 `0086255`）。本发版提交只改 `package.json` 的 `version`、`docs/v0.5.1-runtime-visibility-prd[done].md`、`docs/release-notes/v0.5.1.md` 与 README 对齐。

## 变更

1. `fits=false` 时，请求只发送当前预算下最大可放下的优先级前缀；「## 工具」名单和说明行与发出的 schema 一致。`fits=true` 不收窄。
2. 技能索引、记忆库索引、目录树三项成组裁。多根树标题「工作根目录结构」也裁。仓库地图和 `/add-dir` 额外工作根说明留下。
3. 候选集里的 `read_file`、`edit_file`、`shell`、`shell_output` 始终发送。dry-run 的空集不落地成「四个也不发」。
4. 收窄后落入预算则不再提示「放不下」。仍超预算则保留警告，不再建议在 settings 手写 `context_window`。
5. `/context` 在已收窄时展示实际发出的可见集。规划态套同一层过滤，并留下 `submit_plan` / `exit_plan_mode`。

受控夹具（不是现场 15,893 那次 Magpie 会话的回放）：窗口 116,000 / `models_api` / 预算 14,500；收窄前 mini 全量估计 16,397；收窄后 11,400，已落入预算；三项动态块都裁了；21 个候选工具全部保留。
