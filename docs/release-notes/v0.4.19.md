# v0.4.19 —— 越界数字实体不再让 web 工具崩溃

## 为什么

`web_fetch` 的 `htmlToText` 和 `web_search` 的 `decodeXml` 都用
`String.fromCodePoint(数字)` 解码 HTML/XML 数字字符引用。该函数在码点
超出 Unicode 上限（> 0x10FFFF）或落在代理区（0xD800–0xDFFF）时抛
`RangeError`。

字符引用来自**外部网页/RSS**，不是我们自己生成的。页面上出现一个畸形实体
（`&#1114112;`、`&#99999999;`）就足以让整个工具调用抛异常失败——抓取本身
是成功的，却因为一个坏字符拿不到任何内容。

## 改了什么

`src/tools/index.ts`：新增 `codePointToString(cp)`，越界/代理区码点原样保留
（返回 `&#<cp>;`），其余照常解码。`htmlToText` 改用它。

`src/tools/webSearch.ts`：`decodeXml` 内新增同名辅助函数，多带一个 `raw`
参数以便十六进制引用（`&#x110000;`）原样回填、不丢格式。

选择「原样保留」而非「丢弃」：畸形实体是页面内容的一部分，静默吞掉会让
输出看起来正常但实际缺字；保留原文至少可诊断。

## 测试

- `tests/core.test.ts`：`htmlToText` 越界实体（十进制/超长/代理区）不抛异常
  且原样保留；合法实体（`&#65;`、`&#128512;`）照常解码。
- `tests/b4-tools.test.ts`：`parseBingRss` 同上，覆盖十进制与十六进制两条路径。

红相已验证：还原 src 改动后两条新测试均 fail，恢复后 pass。
全量 1100 pass / 0 fail（原 1097，新增 3 条）；`tsc --noEmit` 干净。
