# v0.4.2 —— tier 视觉语言 + 切档即时反馈

> 发布日：2026-10-27
> 基线：v0.4.1（1027 pass / 66 文件 / PTY 20）
> 发布闸门：tsc 0 错 · **1039 pass / 0 fail / 67 文件** · **PTY 20/20** · `ALL GREEN`
> 证据：`docs/evidence/v0.4.2-{tsc,tests,pty}.txt`

## 为什么发这一版

两个问题：

1. **分类切档的提示出现太晚**：模型实际在首次 LLM 请求前就切到了 fast/balanced/deep，但 `tierSwitch` 只放在 `TurnStats` 里，`index` 等 `agent.send()` 整个 turn（含多轮工具调用和最终总结）结束后才打印。看起来像「总结完才切」，其实只是显示晚。
2. **TUI 全是绿色**：状态条 tier、spinner、工具行 `⚡`、回答 `●` 没有按档位区分，用户感受不到当前模型档位。

## 变更

### 0. 档位简写：`/tier deep` 可用

内部/配置仍用规范名 `deep_reasoning`（不改 settings schema、不破坏旧配置），但人类输入入口统一归一：

- `/tier deep`、`/tier d`、`/tier DEEP`、`/tier bal`、`/tier b`、`/tier f`、`/tier auto` 都可用；
- `/tier` 菜单/查询用短名展示，必要时括号带规范名：`deep (deep_reasoning)`；
- `--tier deep` 同样可用；
- `task` 工具的 `tier` 也接受 `deep` 简写；
- 内部 `ModelTier`/`model_routes`/`*_model_name` 保持规范名，避免 session/旧 settings 迁移。

### 1. 切档即时反馈

- `AgentEvent` 新增 `tier_switch`；`classifyTurn()` 在 `applyTier` 成功后立即发出。
- 交互 TUI 在**首次请求发出前**就打印：
  `⇅ 档位 default → fast（p/模型）` + 理由，并触发 composer 重绘。
- 轮末不再重复打印；`-p --output-format json` 仍保留最终 `tier_switch` 字段。
- 回归测试锁定：`tier_switch` 事件先于首次 `stream`，且第一次请求的 `cfg.model` 已是目标模型。

### 2. tier 语义色

| 档位 | 颜色 | 色值 |
|---|---|---|
| 深思 `deep_reasoning`（可输入 `deep`） | 亮红 | `#FF3B30` |
| 平衡 `balanced` | 磷光绿 | `#00FF41` |
| 快速 `fast` | 亮蓝 | `#00C8FF` |
| 默认 `default` | 冰绿中性色 | `#B4FFBE` |

应用位置：

- 状态条 `tier` 字段（独立 `tier` role）。
- 工作 spinner：`⚡ + 动画字符 + 文本`，`⚡`/动画按当前 tier 着色。
- 紧凑工具行：`⚡` 与运行中 `.`/`..`/`...` 按 tier 着色；工具名保持原亮色。
- 回答流式前缀 `●` 按 tier 着色。
- 详情模式工具标题的 `⚡` 同步按 tier 着色。
- 未知档位回退平衡绿；`NO_COLOR`/非 TTY 自动退化为无颜色，仍保留 `⚡` 与 tier 文本。

## 升级注意

1. **深思红与错误红接近**：深思用 `#FF3B30`，错误仍是 `#FF5555` 且保留 `✖` 形状；如果仍觉得混淆，可后续把深思调成橙红。
2. `default` 是独立第四档，用中性冰绿表示「自动/默认」，不占用三档语义色。
3. `-p` 非 JSON 模式也会在回答前打印档位切换行（以前在回答后）；JSON 模式输出结构不变。
4. 颜色只影响 TTY 视觉，不影响消息/协议/持久化。

## 已知限制

- PTY 屏幕解析器会剥离 ANSI，颜色断言放在纯函数/Console 单测，不靠 PTY 截图。
- 终端主题不同可能导致 RGB 观感有差异；颜色值为真彩色，256 色终端可能降级。
