# v0.4.12 —— 会话图片附件命名：按会话序号，不再按 part 下标

> 证据：`bash scripts/verify.sh` → `docs/evidence/v0.4.12-{tsc,tests,pty}.txt`（目录 gitignore）

## 为什么

`saveSession` 落盘图片时用 **part 下标** 命名：`img-${i}.png`。但每条用户消息的
content 都是「text part + 图片 parts」，下标恒从 1 起 —— 于是**每一轮的图都叫
`img-1.png`**，后一轮静默覆盖前一轮。

实测（两轮各一张不同的图）：

| | 修复前 | 修复后 |
|---|---|---|
| 附件目录 | `img-1.png` | `img-0.png`、`img-1.png` |
| 恢复后第 1 轮的图 | **被第 2 轮的图覆盖** | 原图 |
| 恢复后第 2 轮的图 | 第 2 轮的图 | 第 2 轮的图 |

这不是编号难看的问题，是**数据损坏**：`--resume` 恢复出来的历史里，前面几轮的图
全部变成最后一张图，模型会对着错误的图回答，而且没有任何报错。

同时它和 `hydrateMessages` 的占位口径打架：占位文本 `[Image #N 已丢失]` 里的 N 是
「会话内第几张图」（v0.4.8 修的就是这个），而文件名序号却是 part 下标 —— 两个编号
体系对不上，v0.4.8 的注释也把「落盘按 part 下标命名」当成了既定事实。

## 改了什么

`src/session.ts` 的 `saveSession`：

1. 引入跨消息递增的 `imgSeq`，文件名改为 `img-${imgSeq - 1}.png` —— 序号 =
   **会话内第几张图**，与 chip `[Image #seq]`、占位 `[Image #seq 已丢失]` 同一口径；
2. 非 data URL（自定义 URL）原样保留，**不占序号**（与 hydrate 只对 `image_ref`
   计数的行为对齐）；
3. `hydrateMessages` 的注释同步改写，不再宣称「按 part 下标命名」。

## 兼容性

旧会话文件里的 `ref` 是完整相对路径（`attachments/<id>/img-<i>.png`），hydrate 只认
`ref` 字符串、不解析序号，所以**旧会话照常恢复**。旧会话里已被覆盖的图片无法找回
（文件本身早就被覆盖了），这一点只能靠新版本不再制造。

## 测试

`tests/session-hydrate.test.ts` 新增 `saveSession 附件命名（v0.4.12）` 两条：

- 两轮各一张图 → 目录里是 `img-0.png` / `img-1.png`，恢复后两张内容各自正确；
- 删掉 `img-1.png` 后恢复 → 占位是 `[Image #2 已丢失]`（不是 #1），验证文件名序号
  与占位编号同一口径。

红态已验：把 `src/session.ts` 回退到 v0.4.11 后，第 1 条失败（`img-1.png` 只有一个）。

## 版本

`package.json` 0.4.11 → 0.4.12（verify.sh 的证据前缀自动跟随）。
