# v0.4.47 — formatBytes 末档 P 单位没除，≥1P 全部放大 1024 倍

## 问题

`formatBytes`（`src/env/render.ts`）在 P 档（末档）输出的数值是错的，**所有 ≥1P 的值都被放大 1024 倍**：

| 输入 | 真实值 | 旧输出 | 应输出 |
| --- | --- | --- | --- |
| `1024**6` | 1.0P | `1024P` | `1.0P` |
| `1.5 * 1024**6` | 1.5P | `1536P` | `1.5P` |
| `2 * 1024**6` | 2.0P | `2048P` | `2.0P` |
| `1024**7` | 1024P | `1048576P` | `1024P` |

`formatBytes` 用在 `/env` 命令、wiki 环境页、系统提示词「资源」行（内存总量）与磁盘可用/总量。1P 级内存在今天不常见，但**磁盘总量**在 NAS / 大容量阵列上完全可能进 P 档，届时 `/env` 会显示一个差 1024 倍的数字。

## 根因

两处叠加，都在末档：

1. **单位没除**。`while (v >= 1024 && i < units.length - 1)` 的循环条件带 `i < units.length - 1`，所以 v 在 T 档（i=4）时若 `v >= 1024`，循环**直接退出**，v 仍是 T 档的值、i 仍是 4；紧接着的档内格式化循环 `while (i < units.length - 1)` 同样在 i=4 时立即退出，然后 `return ${fixed1(v)}${units[i]}` —— v 是 T 档数值，标签却是 `P`。
2. **末档没有整数档**。即便 v 已经除到 P 档（如 `1024**6` → v=1），`fixed1` 只负责把 `10.0` 降级成 `10`，不负责把 `1024.0` 收成整数，末档的「≥10 整数」那一半缺失。

这与 v0.4.45 修 `formatTokens` P 档是**同一类缺陷**（末档漏了整数档），只是 `formatBytes` 还多一个单位换算没落地。

## 改动

- `src/env/render.ts`：末档返回前先判断 v 的来源，再决定是否除一次
  ```ts
  // 走到这里 i 已是末档 P。v 有两种来源，不能一律再除一次：
  //  - 循环因 `i < units.length - 1` 结束（v 已除到 P 档，如 1024**6 → v = 1）；
  //  - 循环因 `Number(text) >= 1024` 结束（v 仍是 T 档的值，如 1024**5 → v = 1024）。
  const p = v < 1024 ? v : v / 1024;
  return `${fixed1(p)}${units[i]}`;
  ```
  判据是 `v < 1024`：已除到 P 档的 v 必然 < 1024（否则上一步会继续除）。
- `tests/env.test.ts`：`formatBytes 档位边界` 补 6 条断言（`K**6`、`1.5*K**6`、`2*K**6`、`48*K**6`、`1023*K**6`、`1024*K**6`）

## 验证

- 红测：改前 `formatBytes(1024**6)` 实际输出 `"1024P"`，期望 `"1.0P"`（见 `docs/evidence/v0.4.47-tests.txt` 前的探针记录）
- `bun test`：1156 pass / 0 fail / 71 files，3654 expect（v0.4.46 为 3648，+6 即本轮新增断言）
- `bunx tsc --noEmit`：exit 0
- 证据：`docs/evidence/v0.4.47-tests.txt`（env 单文件）、`docs/evidence/v0.4.47-full-tests.txt`（全量）、`docs/evidence/v0.4.47-tsc.txt`

## 与 v0.4.46 候选记录的关系

v0.4.46 的 release note 把「`1024**6 → "1024P"`」判为**档内合法值、不是缺陷**。那次判断的依据是输出本身 —— 但 `1024**6` 恰好就是 1P，那个输出正是本缺陷的产物。`1024P` 在 1024 进制下确实是合法值，但它对应的输入是 `1024**7`，不是 `1024**6`。本轮的探针用「真实 P 值」做对照（`c / 1024**6`）才把两者区分开。

## 已知未修（留作候选，不在本轮范围）

1. **末档封顶口径**：`formatBytes(1e300) → "8.673617379884036e+281P"`、`formatTokens(1e300) → "1.0000000000000001e+285P"`、`clock(1e300) → "2.777777777777778e+296:36:00"`。JS 的 `Math.round` / `toFixed(0)` 在 1e21 以上退化，要彻底解决得给末档封顶或做十进制展开 —— 改口径，需单独决策。
2. **C1 控制字符**（`\x9b` / `\x9d`）：`sanitizeOutput` 的 C0 剥除范围不含 0x80–0x9f，需先确认口径。
3. **三处 ANSI 剥离合并**：`stripAnsi` / `theme.ts` / `sanitizeOutput` 职责不同，属重构。
