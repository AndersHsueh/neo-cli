## 为什么发这一版

v0.4.91 之后合入两笔功能提交，把 hooks 从四个工具/回合事件扩到**主会话生命周期**，并在复审中修掉语义载荷与诊断尾部混用的问题。功能提交与发版提交分开：**本提交仅改版本元数据及文档，无新增运行时行为**，不改源码、测试、ACP 或 settings。不新开版本 PRD；规格见 `docs/lifecycle-hooks-prd[done].md`。

## 变更

1. `438fbd0`（feat: 补齐主会话生命周期 hooks，#64）：交互、`-p`、ACP **主会话**接入四个新事件；子代理与 wiki worker 不触发，避免递归；未配置 hooks 时行为不变；ACP 诊断走 stderr/协议错误，不污染 stdout。
   - `SessionStart`：仅 `new` / `resume` / `clear`；失败只诊断并继续。不加 fork / ENV_FILE；compact 只触发 `PreCompact`，不发 `SessionStart`。这是 neo 的事件子集，不宣称完全兼容竞品。
   - `UserPromptSubmit`：只对真实用户输入；`-p` 一次输入一次；ACP 每次 `session/prompt` 一次；load/历史回放不是提交。exit 2 在写主历史与首个模型请求之前阻断，原因可见；ACP 返回合法 refusal，不挂起。
   - `Stop`：仅模型正常终止（不是工具迭代、截断、abort、error）。只有 exit 0 且 JSON `{"decision":"block","reason":"非空字符串"}` 才请求续跑；普通 stdout 不续跑。每条真实输入最多自动续跑一次，drive/loop 内部轮不重置额度；续跑共享原迭代预算、取消信号和总上限，不开新预算。第二次 block 只诊断上限。最终 TurnEnd / Notification 各一次。
   - `PreCompact`：覆盖手动/自动，hook 先于任何破坏历史/快照的动作。exit 2 保留原历史与快照；自动压缩被拒时本轮明确停止并提示，不递归重试、不降级裁剪。附加上下文只给摘要器，不永久落主历史。
   - exit 0 纯文本或 JSON `additionalContext`：`SessionStart` / `UserPromptSubmit` 给主模型，`PreCompact` 只给摘要器。只注入字段值，不把 JSON 原串再注入。合法对象没有 `additionalContext`（仅未知字段如 `diagnosticMetadata`）一律不注入。坏 JSON 不崩会话：上下文路径按纯文本回退，Stop 路径不续跑。旧四种 hook（`PreToolUse` / `PostToolUse` / `TurnEnd` / `Notification`）失败策略与诊断尾部语义保留。
2. `12cbfba`（fix: 分离生命周期 hook 语义载荷与诊断尾部，#64，复审 B1）：`HookOutcome.stdout` / `stderr` 仍是给人看的诊断尾部（800 字符，超出加 `…`），不是解析输入；生命周期 exit 0 语义改走 `HookOutcome.semantic` 的完整原始 stdout，先完整解析再按字段限长。
   - 原始语义输出上限 `HOOK_SEMANTIC_OUTPUT_LIMIT` = 1048576 字节（UTF-8 原始字节，不是 JS `string.length`）；恰好上限保留，多 1 字节整段拒绝（raw 为空 + overflow）。
   - `additionalContext` 与纯文本字段上限 `HOOK_CONTEXT_FIELD_LIMIT` = 32000 字符，超限保留前 32000 并诊断。
   - Stop `reason` 先解析再按 `REASON_LIMIT` = 2000 字符裁剪，裁剪后续跑请求仍有效，仍受原预算/额度/取消约束。
   - 超载必须明确诊断（文案含「上限」），不得把截断输出降格为普通文本，不得静默丢失合法 Stop 续跑；继续排空管道并等待真实退出码，不杀 hook 进程；超载 stdout + exit 2 仍阻断 `UserPromptSubmit` / `PreCompact`。
   - 旧四事件不设该语义接收上限，保留完整 JSON 失败原因解析与 800 字符诊断尾部、原 exit / `onFailure` 策略。

## 验证

本地 Linux release worktree、清空残留 NEO_* 环境后运行 verify.sh，版本证据前缀为 v0.4.92：tsc exit 0，2363 pass / 3 skip / 0 fail（139 文件），PTY 36/0，ALL GREEN。全新 worktree 在安装依赖前的第一次官方命令因缺少 `@agentclientprotocol/sdk` 于 tsc 失败，完整日志保留为 `verify-before-install.txt`；`bun install --frozen-lockfile` 之后的官方闸门见 `verify-after-install.txt`。三条 skip 均为 worktree 下 prompt-tiers 找不到 bot-comments 源文件的既有豁免。

**D1 直述（必须保留）**：`oneshot-drive` 测试 D1（缺 `-y` 时预期零模型请求）存在**间歇性、根因未定**的失败。作者在 #64 修复轮次的独立完整 `bun test` 曾出现 2362 pass / 3 skip / 1 fail（唯一 D1）；随后官方 verify 通过。Leo 第二轮独立复审的官方闸门 D1 通过，但明确「不能据此宣称 D1 已修好或无竞态」。**官方绿不等于 D1 已解决**，根因仍未定位。D3 与 D1 不混同：D3 在复审中已确认普通迭代错误不会被误停为 idle-stop。
