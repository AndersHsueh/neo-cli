# v0.2.0

> 2026-10-20 · 功能版本：**跨会话消息** —— 多个前台 neo 会话互相派活 / 回信 / 人工接管
> 规格：`docs/cross-session-messaging-prd[done].md`（v1.2，2026-10-20 裁决）

## 背景

neo 一直只能一个终端、一个会话。多角色协作（实现 / review / 测试 / 产品）靠人肉复制粘贴消息；
单进程 `task` 子代理同步阻塞、输出静音、只回最终报告，跑偏了无法中途叫停。

本版本把「会话」变成可互相通信的对等节点：任何会话都能发任务、接任务、多跳协作；
人类可以随时进入任意终端叫停、补话、继续。消息仍是纯文本，不携带上下文/文件。

## 用户可见能力

- **`send_message(target, body, reply_to?)`**：给任意存活会话投递纯文本消息；`target` 支持精确
  session id / id 片段 / `/rename` 名字。回信带任务号（`reply_to` = 原消息 id），宿主自动计算
  执行时长（`exec`），发起方据此对账。
- **`list_peers(target?)` / `/peers [name]`**：查看存活会话的状态机摘要（空闲 / 工作中 /
  等待人类 / 在等别人 / 停滞 / 已死）。
- **`/rename <name>` / `neo --name <n>`**：给会话起名；撞名自动加 `-2` 后缀，dead 会话名字可复用。
- **自动投递与自动 turn**：活跃 turn 中在工具批次结束后注入（P1）；空闲时 1s tick 检查 inbox，
  自动开新 turn（P2），连续自动 turn 上限默认 20（可配）。状态通知同路注入。
- **人工接管**：任意终端 ESC 叫停；自动 turn 被 ESC 中止时只停不删（保留任务与已完成结果），
  人类自己输入的 turn 保留原有回滚语义。补话后继续，完成后按约定回信发起方。
- **入站三态**：`accept` / `hold` / `refuse`，缺省按接收方权限档自动判定；`/inbox` 查看 held，
  `/inbox release <id>` 放行。
- **`/resume` 身份改键**：交互恢复切换 session-id 时，信箱目录 / profile / state / `.alive` 同步迁移；
  目标会话已 dead 则接管其信箱（按裁决丢弃未读），仍有活进程则拒绝迁移并提示。
- **免打扰**：`-p` / 非交互模式不启用信箱（不建目录、不注册工具、不跑 tick）。

## 实现

| 模块 | 职责 |
|---|---|
| `src/mailbox/types.ts` | 信封 / profile / state / 台账 / 观察快照类型、默认配置、路径与 `NEO_MAILBOX_DIR` |
| `src/mailbox/state.ts` | 状态机转移、心跳/进度、effective state、receipts、委派台账、watchdog 纯判定 |
| `src/mailbox/identity.ts` | profile、`.alive` 锁、名字去重、resume 改键、TTL 清理、peer 观察 |
| `src/mailbox/store.ts` | 发送/接收/限流/去重/队列上限/hold/release/peers/watchdog 编排 |
| `src/mailbox/inbound.ts` | 入站三态判定 + 消息/通知文本框架 |
| `src/tools/mailbox.ts` | `send_message` / `list_peers` 工具（子代理不可见） |
| `src/agent.ts` | `AgentOptions.pollInbox` + P1 注入点（工具批次结束、自动 compact 之后） |
| `src/index.ts` | 启动身份 / 1s 空闲 tick / 120s watchdog / 状态转移 / `/peers` `/inbox` `/rename` |
| `src/system-prompt.ts` | 启用信箱时注入「跨会话消息」九条规则 |

磁盘布局：`~/.neo/mailbox/<session-id>/{profile,state,delegations}.json + inbox/`。
状态机：`idle / working / waiting_input / exiting`，`dead` 由 `.alive` 缺失或心跳超 120s 派生。
写路径全部 `tmp + rename` 原子写；消息投递 at-most-once（读即删）。

## 配置（可选，settings.json 顶层）

```json
{
  "cross_session_inbound": "auto",
  "cross_session_auto_turn_limit": 20,
  "cross_session_heartbeat_ms": 15000,
  "cross_session_dead_after_ms": 120000,
  "cross_session_progress_timeout_ms": 300000,
  "cross_session_watchdog_interval_s": 120
}
```

`cross_session_inbound` 取 `accept | hold | refuse | auto`。默认信任档下，`auto-all` 接收方会
hold 来自非 auto-all 会话的消息；承接方建议用 `--edit`（写文件自动批、shell 仍批），或显式配
`accept`。详见 README「跨会话消息」节。

  `mailbox-state`（状态机/台账/回执/纯判定/身份改名改键/TTL）、`mailbox-inbound`（三态/框架/工具/
  prompt/config）、`mailbox-agent`（P1 协议合法性 / 错误不击穿主循环）。
- 全量 **519 pass / 0 fail（26 个测试文件）**，`bunx tsc --noEmit` 零错误。
- 交互式 PTY smoke：启动、`/rename`、`/peers`、`/inbox`、`/exit` 与 `.alive` 清理通过。
- **fake-LLM 双端 E2E**（本地 SSE 端点，不触网）：对端在 A 空闲时投递消息 → P2 tick 自动收信并开 turn；
  A 经 `send_message` 工具实际投递到 B 的 `inbox/`；A 的 `state.json` 正确记录
  `last_inbound` / `last_outbound` / `last_turn`；用户发起的**新任务不会被误标成回信**（无 `reply_to`）；
  退出后 A 的 `.alive` 删除。`reply_to` / `exec` 自动填充由单测覆盖（回信路径）。

## 已知边界（v0.3 路线）

- 不做 supervisor / 后台会话 / `--bg` / attach / agent view / 跨机路由。
- 投递 at-most-once：P1 注入后未落盘进程就崩溃，可能丢一条消息（接受，进程崩了用户会看到）。
- 死进程未读消息不保留、不补投；只服务活着的前台进程。
- 多跳环（A↔B↔C）靠每会话自动 turn 上限 20 + 发送端限流 + 接收端去重兜底，无全局环检测。
- `reply_to` 缺失时退回「同一 target 最早未回」近似；建议回信始终带任务号。
- `-p` 模式不参与跨会话协作。
