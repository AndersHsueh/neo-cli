# /btw 旁支提问（基于已有上下文、不入历史、不打断主轮次）

> 状态：实施中（issue #61）
> 参考：Claude Code `/btw`（https://code.claude.com/docs/en/interactive-mode#side-questions-with-%2Fbtw）

## 1. 要做什么

用户在 neo 的输入框输入 `/btw <问题>`，neo **基于当前会话已有上下文**（此前的对话、工具结果）回答这个旁支问题。

做完能干什么：主任务跑着的时候插一句「刚才那个配置文件叫什么」，得到答案，但这条问答**不进对话历史**——主任务的上下文不被污染，模型也不会被带偏。

## 2. 现状与缺口

- 源码中无 `/btw` 或等价的旁支提问命令。
- 用户想确认一件已经聊过的事，只能发正式消息：既污染上下文（这条问答会进历史、占 token、影响模型判断），又打断主任务。
- 主轮次运行中无法插问。

## 3. 交互契约

| 环节 | 行为 |
| --- | --- |
| 命令 | `/btw <问题>`（缺参数 → 给用法提示，**不发请求**） |
| 上下文来源 | 当前会话已有消息（**快照**，见 §4），过滤掉召回注入的临时消息 |
| 工具 | **不带任何工具**（`tools` 传空数组）——旁支问答只做「回答问题」，不改任何东西 |
| 历史 | 问答**不进** `agent.messages`，**不进** session 文件 |
| 主轮次 | 主轮次运行中也能问，且**不打断**它：独立的一次请求，不动主循环的在途状态 |
| 用量 | 显式记账（`recordUsage`），否则 `/cost` 会少算这笔 |
| 渲染 | 按 markdown 渲染回答 |
| `-p` 模式 | oneshot 没有「当前会话上下文」可言 → 给可读提示，**不发请求** |
| 失败 | 模型报错 / 返回空正文 → 给可读原因，不崩会话、不污染历史 |

## 4. 关键约束：快照而非引用

`Agent.messages` 是**活引用** —— 工具循环的每次迭代、失败重试、降级重发都复用同一份数组（见 `src/agent/loop.ts` 的注释）。旁支请求若直接往里 push，会同时污染主上下文并随 session 落盘。

因此实现上必须：取 `[...this.messages]` **浅拷贝快照**，往**快照**里 push 问题，绝不 push 回主数组。

## 5. 非目标（本版不做）

- 回答的可关闭浮层展示（v1 直接打印到输出区）。
- 一键 fork 成带工具的后台子代理继续深挖。
- 旁支问答的**多条**追问串（每条 `/btw` 彼此独立）。
- 旁支请求的流式逐字输出（v1 一次性拿结果）。

## 6. 验收条款

每条都要能在测试里找到对应（`tests/btw.test.ts`）：

| 编号 | 条款 |
| --- | --- |
| E1 | `/btw` 得到的回答**基于当前上下文**（请求里含此前对话与本轮问题） |
| E2 | 回答**不进入** `agent.messages`，也不进 session 文件 |
| E3 | 发给模型的请求**不带任何工具** |
| E4 | 主轮次运行中调用**不破坏**主轮次、不丢主轮次消息 |
| E5 | 缺参数 / 模型失败 → 可读提示，不崩 |
| E6 | `/btw` 出现在命令清单（命令菜单可见） |
| E7 | oneshot（`-p`）模式下不可用，不发请求 |

## 7. 已知风险

- 旁支请求与主轮次请求并发打同一个 provider：两者独立，provider 侧的并发由服务商决定；neo 不做串行化。
- 旁支请求的 token 消耗计入 `/cost`（走 `recordUsage`），但**不计入**上下文窗口占用 —— 因为它不进历史。
