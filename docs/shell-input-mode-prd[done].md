# 输入框 `!` shell 模式 PRD（issue #30）

> 状态：实现中（待审查）
> 关联：GitHub #30；维护主流程 `docs/maintenance.md`
> 与前序工作的关系：不改变提交态 `!<cmd>` 语法（那是 v0.2.x 起就有的行为），只补**输入态** UX。

## 1 背景

neo 已支持「整行以 `!` 开头 → 交给 `src/cli/shell.ts` 直通 shell」（受权限模式约束，plan 拒绝，TUI 用
suspend/resume 让子进程写 tty）。缺的是 Claude Code 式的**输入态切换**：打出首字符 `!` 时输入框进入
shell 模式（前缀变成 `! `、正文配色区分），回车执行后自动恢复普通模式。

## 2 需求

### 2.1 进入

- 仅在**空缓冲区**下键入 `!` 时进入；`!` 是模式开关，**不留在命令正文**。
- 缓冲区已有内容时键入 `!` 按字面插入，不切模式（避免把普通句子改成 shell 命令）。

### 2.2 呈现

- 首行前缀 `! `（warn 色，取代普通态 `❯ `）；续行缩进 2 空格与现有折行一致。
- 正文用 warn 色（与普通输入的 text 色区分），光标反显不变。
- 占位文案改为 `shell 命令 · Enter 执行 · 删空或 Esc 退出`；其余布局（横线/状态条/滚动）不变。
- shell 模式下不触发命令/文件补全（Tab 无动作、无单行 hint）：shell 命令是外部语法，不该被
  neo 的补全语义污染。

### 2.3 提交

- Enter：把缓冲区**原样**交给宿主的 `onShellCommand`（组合根直接调 `runShellWithTui`），
  **不再走「整行 startsWith `!`」那条路径**，避免双重剥前缀。
- 空命令（只进了模式、缓冲区空）：不执行，直接退回普通态。
- 执行结束（含权限拒绝 / plan 拒绝）：输入框回到普通态，前缀与配色恢复。
- 兼容：旧的提交态 `!<cmd>` 一行语法保留（非 TUI / 脚本 / scrollback 重放仍可用）。

### 2.4 退出（不执行）

- 空缓冲区按 Backspace/Delete → 退回普通态；
- Esc：不在忙时退回普通态并清空缓冲（忙时仍是「请求取消本轮」，全局语义优先）；
- 提交后自动退回普通态。

### 2.5 非目标

- 不做完整交互式 PTY 登录 shell（仍是「一条命令、跑完回 neo」）；
- 不改默认权限模型、不新增旁路；权限/hooks/plan 判定与现 `!<cmd>` 完全共用；
- 不做后台长驻 shell（#28）。

## 3 验收

1. 空输入框键入 `!` → 前缀变 `! `、配色切换、占位变化；输入 `echo hi` 回车 → 执行且输出可见，之后恢复 `❯`；
2. 空 shell 模式直接回车 → 不执行、回到普通态；
3. 非空普通输入中插入 `!` → 不进入 shell 模式；
4. Backspace 删空退出、Esc 退出（非忙时）；
5. 旧 `!<cmd>` 提交语法行为不变；
6. `bun x tsc --noEmit` 零错误、`bun test` 全绿（含 TTY 场景）、`bash scripts/verify.sh` 为 `ALL GREEN`。
