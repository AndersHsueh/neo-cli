# 后台子代理 PRD（issue #16）

> 状态：实现中（待审查）
> 关联：GitHub #16。与 #9（托管 worktree 的文件隔离并行）正交：本单是**同一会话进程内**的异步 task。

## 1 背景

`task` 工具已能派生子代理（深度结构性 ≤1、静音输出、独立上下文），但 `execute` **同步等它跑完** ——
子代理探索的几分钟里主会话完全卡住。目标：让模型可以「一边深挖依赖，一边继续对话/改码」，完成后结果
自动回来。

## 2 需求

1. **发起**：`task` 新增可选参数 `background: true`。为 true 时：
   - 立刻返回任务 id 与说明（不等待）；
   - 子代理在后台跑，完成后结果作为一条 **user 消息**在下一次请求前注入主会话
     （`<后台子代理结果 id="bg-N" status="done">…</后台子代理结果>`），只注入一次。
   - 不传 / false = 旧同步行为**一字不改**。
2. **可见**：`/tasks` 列出后台任务（id / 状态 / 已跑秒数 / 提示摘要 / 失败原因）；
   `/tasks cancel` 取消全部、`/tasks cancel <id>` 取消单个。
3. **上限**：并发默认 3，超过直接拒绝（不排队 —— 排队会让「后台」变成隐藏积压）；
   深度仍结构性 ≤1（子代理看不到 `task`），不做多级后台链。
4. **取消与生命周期**：
   - 每个任务一个 `AbortController`，取消会 abort 子代理（`runSubagent` 既有 abort 链路）；
   - 会话退出 `cancelAll()`，不留幽灵任务；
   - 主 turn 的 **ESC 只取消当前 turn，不误杀后台任务**；有任务在跑时会提示
     `/tasks cancel` 这条出口（刻意与 issue 草案的「ESC 也能取消后台」不同：后台任务价值就在
     「独立于当前 turn」，ESC 顺带杀掉会让人白等；需要时一条命令即可取消）。
   - 已取消的任务**不**向主会话汇报。
5. **权限**：后台子代理的审批仍冒泡到主 TTY（既有 `SilentConsole` 委托 `confirm` 口径），
   不新开旁路；plan 模式下照旧只读。

## 3 验收

1. `task(background: true)` 立刻返回、主循环继续；完成后结果注入且只注入一次；
2. `/tasks` 能看到运行中/已完成/失败/已取消，`/tasks cancel [id|all]` 生效；
3. 并发上限生效；深度仍 ≤1；会话退出无残留任务；
4. 同步模式行为不变；
5. `bun x tsc --noEmit` 零错误、`bun test` 全绿（含 PTY）、`bash scripts/verify.sh` 为 `ALL GREEN`。

## 4 非目标

- 后台任务不落盘、不跨会话恢复（进程退出即结束）；
- 不做多级后台链 / 后台「再发消息」续聊（Claude Code 的 `/tasks` 续聊属后续）；
- 不做后台任务的 attach/终端切换（跨会话信箱仍是前台多终端协作）。

## 5 追加记录（2026-11-10，issue #45）

原实现任务表纯内存、进程退出即消散。现追加**任务落盘**（不做续聊/续跑，续聊另开）：

- 落盘位置：`session.meta.backgroundTasks`（与 todos / rewind 同一恢复路径；上限 20 条、单条结果 2k 字符）。
- 只存可序列化纯数据（显式逐字段拷贝，绝不带 `ctx` 的 console / checkpoint / signal 活引用）。
- `--resume` 后作为只读历史展示；`running` 一律映射成 `interrupted`（进程重启后不可能还在跑，不假装在跑），
  `/tasks` 显示「中断」；脏数据丢弃不崩。
- 写盘时机：发起即写；主循环 `pollBackground` 前整表比对（变化才写，避免每轮重写 session 文件）；
  `shutdown()` 前再同步一次。
- 本进程有活任务时 `/tasks` 只显示活任务（避免同 id 重复），恢复的历史被遮蔽 —— 如需并列另定口径。
