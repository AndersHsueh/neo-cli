# v0.2.3 TUI 补漏 PRD

> 2026-10-25 · 状态：**已交付**（v0.2.3，见 docs/release-notes/v0.2.3.md）
> 上游 v0.2.2（工具调用紧凑显示）
> 定位：不换渲染模型，只补「信息留存 / 宽度正确性 / 恢复可见性」三类漏

## 0. 为什么不是「重写 TUI」

2026 年主流终端 agent 的默认渲染模型就是 neo 现在这套：**inline + append-only +
终端自己的 scrollback**（Claude Code classic、Codex 默认）。全屏 alt-screen
（OpenCode / Crush）的代价是丢掉 `Cmd+F`、tmux copy mode 与会话内搜索
（opencode#4714 至今未解）。v0.2.3 因此**不引入全屏渲染器**，只修既有模型里的漏。

## 2. 范围（v0.2.3 只做这 5 项）

### D1 流式状态复位

- `Console.endStream(kind, newline=true)`：正文路径的新行由 `StreamFormatter.finish()`
  负责，调用方传 `newline=false`，避免双空行。
- `agent.ts` 交互分支在正文/推理收尾时**每次都复位**，不再只靠异常路径的
  `ensureStreamClosed`。
- 验收：一轮内两次工具批次，第二段正文必须带 `●` 前缀；推理块 `┌ think` 可重复出现。

### D2 宽度数学与 resize

- `theme.truncate(s, max)` 改为**按显示列**截断（CJK 安全）；`toolLine.ts` 的
  `truncateDisplay` 下沉到 `theme.ts` 复用，删除重复实现。
- `Console.cols()` 回落值 100 → **80**（`>20` 判定保留）。
- `Console.handleResize()`：TTY 且收到 `SIGWINCH`/`resize` 时，先把动画行收尾成完整行
  （不再用 `\r\x1b[2K` 覆盖已重排的行），再让 readline 自己重绘提示符。
- 不做全量重排（append-only 已输出的历史行无法回溯），只保证**不再吃掉用户正在输入的行**。

### D3 `/last` 工具回看 + 失败可读

- `Console` 内存缓存最近 **20** 条工具调用（name / args / ok / 耗时 / 完整输出，
  单条输出按 `tool_output_limit` 截断），不落盘、不读 session json。
- 新命令 `/last [n]`（默认 1，上限 20）：打印该次调用的单行摘要 + 缩进输出（默认 40 行，
  超出提示省略行数）。
- 失败时紧凑行**保持一行**，但追加最多 3 行缩进错误正文 + `（完整输出：/last）` 提示。
  成功路径仍是 1 行，不回归 v0.2.2 的「清爽」。
- 纯格式化逻辑独立成 `src/ui/toolLog.ts`，bun test 直测。

### D4 `--resume` 回放最近 N 轮

- 新增纯函数 `src/ui/transcript.ts`：`transcriptLines(messages, {turns, width, maxLines})`
  → 行数组。规则：只取 `user` / `assistant`，跳过 `system` / `tool` / 空正文；
  用户行 `❯ ` 前缀，助手行 `● ` 前缀，正文过 `renderMarkdown`；总体行数上限
  `maxLines`（默认 120），超出以 `… 更早的 N 轮未显示` 收尾。
- 交互模式恢复会话后立即回放最后 **3 轮**；`-p` 模式不回放（避免污染管道输出）。
- 验收：恢复后屏幕上能看到上一轮的问答，而不是只有一行「已恢复会话」。

### D5 `flashNotice` 不再破坏提示符

- `Console.setPromptRestorer(fn)`：由持有 readline 的一方注入「重绘提示符 + 恢复行缓冲」
  （`rl.line` 保持不动，只 `_refreshLine()`）。
- `flashNotice`：`\r\x1b[2K` → 提示文字 → `\n` → restorer()；超时后 `\r\x1b[2K` → restorer()。
  全程**不打印** `❯`（提示符由 readline 自己画），也不清空行缓冲。
- 无 restorer（非 TTY / 测试）时退化为「提示 + 换行」，不伪装提示符。

## 3. 明确不做（留给后续版本）

| 事项 | 理由 |
|---|---|
| 全屏 / alt-screen 渲染器 | 丢 scrollback，与 neo 的 append-only 一致性问题大；社区反模式 |
| 底部常驻状态栏（整块重绘 + 光标上移补丁） | 需要渲染器级设计，单独立 PRD（v0.3）+ M0 探针 |
| 轮次级 diff 审核 | 依赖 edit 工具的 hunk 结构化，属 v0.3 |
| `@` 文件补全 / tab 接线 / 多行输入 | v0.2.4 输入层批次 |
| 桌面通知 / 音效 | 非必需，且有 tmux OSC 兼容成本 |
| 工具输出分页器 | `/last` 先解决「能回看」，分页留待真实反馈 |

## 6. simplify 三阶段审查记录（2026-10-25）

按 simplify-reviewer 的方法（并发 3 个 reviewer → 聚合 → minor 自动修 / major 预览后修）执行，
3 个只读 reviewer 共报 **1 critical + 9 major + 10 minor**，全部处理完毕：

| 来源 | 严重度 | 问题 | 处置 |
|---|---|---|---|
| quality | critical | `flashNotice` 不回让动画行：长工具运行中按 Ctrl+C，350ms 工具行计时器下一拍会把 readline 重绘的提示符擦掉 | 抽 `yieldAnimationLines()`，`flashNotice`/`flush`/resize 统一先收尾动画行；补计时器回归测试 |

## 7. 测试基建（可复用，落在仓库里而不是 /tmp）

| 文件 | 说明 |
|---|---|
| `scripts/fake-llm.ts` | 无状态假 OpenAI SSE 端点。`PORT=0` 内核分配端口并打印 `FAKE_LLM_READY port=<n>`；`SCENARIO=tool-then-answer/narration/resume` |
| `scripts/pty-e2e.ts` | 真 PTY E2E。系统 `script(1)` + 最小屏幕缓冲（`\r` 回行首 / `\x1b[2K` 清行 / 宽字符 2 列）；`s1 s4` 过滤、`KEEP_TMP=1`、`NEO_ENTRY=`、`PTY_E2E_VERBOSE=1` |
| `scripts/verify.sh` | 全量闸门 tsc → bun test → pty，逐阶段 tee 到 `docs/evidence/v0.2.3-<stage>.txt`；全过 `ALL GREEN` |
| `docs/evidence/v0.2.3-{tsc,tests,pty,pty-red}.txt` | 绿态 + 红态原始输出 |

踩坑（已固化在脚本里，后续复用不要去掉）：

1. **必须 `--auto off`**：规则分类器切档会经 `applyTier` 把 `baseUrl` 重置回 settings.json 的真实 provider，悄悄绕过 fake-llm 打真实网络。
2. **macOS `script(1)` 不接受 Bun 的 `stdin:"pipe"`**（socketpair → `tcgetattr: Operation not supported on socket`），须 `mkfifo` + `cat fifo | script`。
3. **`COLUMNS` 环境变量不改变 Bun 的 `process.stdout.columns`**，窄终端要在 PTY 里 `stty cols 60 rows 40`。

## 8. 风险与遗留

- `agent.ts` 的交互分支改动影响所有 TTY 用户；用 `tests/stream-state.test.ts` 锁定行为，
  PTY 场景兜底「真终端」差异（bun 的 keypress/时序类 bug 只有真 PTY 能暴露）。
- `Console` 缓存工具输出有内存成本：20 条 × 单条 ≤ `tool_output_limit`（30k 字符）≈ 600KB 上限，
  可接受；上限常量集中在 `toolLog.ts`。
