## 0. 一页速览

**一句话**：neo v0.1.0 在 v0.0.3 单 agent CLI 之上，新增**两个 user-facing 特性** —— **Skills**（三层渐进披露的能力扩展机制）+ **Memory**（基于 wiki 的跨项目记忆系统）。两者均由模型通过工具按需调用，**不** 注入到 system prompt，保持 v0.0.3 的 prompt 缓存友好性。

### 范围

| 域 | 内容 |
|---|---|
| 新增工具 | `use_skill(name)`（沿用现有 8 个工具 +1） |
| 新增目录 | `~/.neo/skills/`（用户级技能库）+ `~/.neo/memorys/{raw,wiki,outputs}/`（用户级记忆）+ `<cwd>/.neo/wiki/{raw,wiki,outputs}/`（项目级 wiki） |
| 新增命令 | `/skills <name>` + `/memory {status, list, forget, reindex, redact}` |
| 配置文件 | `settings.json` 加 `memory.*` 字段 |
| 第三方依赖 | 零新增（沿用 v0.0.3 现状） |
| 代码变更行 | +1276 / -（相对 v0.0.3 的 4437 行 TS） |

### 非目标

- ❌ 向量库 / embedding（v0.2 路线）
- ❌ GUI / IDE 插件 / 托管服务
- ❌ 第三方 skill 仓库自动同步
- ❌ 主观经验自动抽取（依赖 LLM 抽取；v0.2 路线）
- ❌ 守护进程 / 后台 ingest 循环

## 1. 两条主特性

### 1.1 Skills（渐进披露的能力扩展）

**问题**：模型需要按需加载「专家级能力」（如 karpathy-wiki 工程方法、PR 评审 checklist），但**不**希望 8 个工具的全集把 system prompt 撑爆。

**方案（v0.1.0 final 决议）**：

```
~/.neo/skills/<skill-name>/SKILL.md       # 用户级技能库（共享）
<cwd>/skills/<skill-name>/SKILL.md       # 项目级技能（用即软链）
```

- `use_skill(name)` 工具触发加载（边 +79 tokens spec）
- 软链而非 git clone：首次命中时 `symlinkSync` 把全局技能链到项目级 `skills/`
- AGENTS.md 路由 + symlink 守卫：写工具不穿透软链到全局库
- gitignore `skills/`：软链路径不可移植，永不进 git

**具体能力（已交付技能）**：

| 技能 | 触发 |
| --- | --- |
| `karpathy-wiki-new` | 首次进新目录，建项目级 wiki 骨架 |
| `karpathy-wiki-ingest` | 写入后 / staleness check，raw → wiki |
| `karpathy-wiki-lint` | 提交前 / 用户显式，wiki 健康检查 |
| `karpathy-wiki-query` | 用户问「以前做过 XX」，跨库查询 |

详细规格 → `docs/skills-prd[done].md`（1008 行）

---

### 1.2 Memory（基于 wiki 的跨项目记忆）

**问题**：跨项目、跨会话，模型不知道「这个项目用 bun」「X 月 X 日我做过 XX」。v0.0.3 已有的 `AGENTS.md` 全文注入在 cwd 多时不扩展，且无检索 / 无容量上限。

**方案（v0.1.0 final 决议）**：

```
~/.neo/memorys/
├── profile.md                       # 常驻注入，≤500 tokens
└── {raw,wiki,outputs}/
    └── raw/*.md                     # 客观元数据，自动写
```

```
<cwd>/.neo/wiki/
└── {raw,wiki,outputs}/
    └── raw/entries/*.md            # v0.1.0 占位 schema，不实现
```

- 用户级索引自动写（`recordIndex`，按 cwd 同日去重）
- 项目级 wiki 懒创建（`/init` 或首次 shell/write_file）
- profile.md 注入到 `messages[1]`（避开 `noteModelChange` 正则改写）
- AGENTS.md 路由 `use_skill karpathy-wiki-*`（先手 / 降级两套文案，约束 14a）
- 并发安全契约（约束 9a）：mkdir 锁 + tmp/rename + read-compare-append
- PII 过滤（约束 45-47）：summary 字段脱敏，正文留原样
- 召回率验收（约束 54-55）：Top-1 ≥ 0.85 / MRR ≥ 0.90

**关键约束（共 55 条）**：

| 类别 | 约束 |
|---|---|
| 数据模型 | 9a（并发契约）/ 28b（frontmatter 例外）/ 36-38（默认值 + 测试隔离） |
| 行为 | 12a（三层 fallback 截断）/ 14a（先手/降级路由）/ 23（零审批）/ 24（同 cwd 同日去重）/ 27（compact 不吃 profile） |
| 安全 | 45-47（PII 过滤）/ 39-41（不依赖 skills API）/ 51（降级不可静默） |
| 验收 | 52-53（forget journal + 不删 .ingest-failures）/ 54-55（召回率门槛） |

详细规格 → `docs/memory-prd.md`（1103 行）

## 2. 用户级接口

### 2.1 新增命令族

| 命令 | 行为 | 规格 |
| --- | --- | --- |
| `/skills <name>` | 加载指定技能到当前会话 | §skills-prd §6.2 |
| `/skills` | 列出当前可用技能 | §skills-prd §6.2 |
| `/init` | 懒创建项目级 wiki 骨架（v0.1.0 起 `/init` 双语义：skills 侧 + memory 侧） | §memory-prd §5.1 |
| `/memory status` | 列当前 cwd 的用户级索引 | §memory-prd §6.2 §A |
| `/memory list [--cwd=...] [--date=...]` | 范围索引 | §memory-prd §6.2 §A |
| `/memory forget <id> [--yes] [--dry-run] [--resume]` | 删除索引条目（含二次确认 + journal 回滚） | §memory-prd §6.2 §A + 约束 52-53 |
| `/memory reindex <cwd>` | 重建 cwd 索引（CWD 改名恢复入口） | §memory-prd 约束 48 |
| `/memory redact [--pattern=...]` | 对已有条目按模式串重脱敏 | §memory-prd 约束 46 |
| `--no-profile` | 显式禁用 profile 注入（沿用 v0.0.3 已有 flag） | §memory-prd 约束 25 |
| `-p` | 单次模式（默认不注入 profile） | §memory-prd 约束 25 |

### 2.2 配置文件（settings.json）

```json
{
  "memory": {
    "enabled": true,
    "user_level_dir": "~/.neo/memorys",
    "profile_tokens_limit": 500,
    "ingest": { "provider": "classifier_provider", "model": null, "timeout_ms": 2000 },
    "auto_write_index": true,
    "no_profile_in_one_shot": true,
    "platform": "auto",
    "worktree_isolation": false
  }
}
```

`skills` 端配置零新增 —— 全部走 `~/.neo/skills/` 目录约定。
