# 定时 / 自节奏循环提示 PRD（issue #25）

> 状态：实现中（待审查）
> 关联：GitHub #25；与 #24（目标驱动自动续跑，条件驱动）正交 —— 本单是**时钟/节奏驱动**。

## 1 背景与目标

典型场景：「每 2 分钟看一眼 CI / 日志，红了再修」。现在只能人坐在终端反复回车，或外挂 cron 调
`neo -p`（丢上下文与审批态）。目标：**在同一个交互会话里**，按固定间隔或「上一轮结束后」自动再注入
同一条提示。

## 2 需求

### 2.1 命令

| 命令 | 行为 |
|---|---|
| `/loop <间隔> <提示>` | 启动固定间隔循环。间隔写法 `30s` / `2m` / `1h` / 纯数字=秒；最小 5 秒（更小的值夹紧到 5 秒并提示），最大 24 小时 |
| `/loop self <提示>` | 自节奏：上一轮结束后自动排下一拍 |
| `/loop` | 查看状态：模式、已跑 / 跳过次数、提示摘要、下次唤醒（相对秒数） |
| `/loop stop` | 停止并清掉定时器 |

- **默认关闭**：不敲 `/loop` 就零定时器、零额外请求。
- 启动后**立刻跑第一拍**，之后按节奏排（固定间隔从这一拍结束时刻起算）。
- 仅交互会话可用；`-p` 单次模式下命令直接提示「不可用」，不启动。

### 2.2 唤醒策略（重叠合并/丢弃）

一拍要入队时若「正在跑 turn 或队列非空」→ **丢弃这一拍**（不排队、不叠加），计入 `跳过` 次数，
下一拍仍按原节奏排。理由：循环提示是「看一眼」类任务，排队执行只会累积过期任务、放大成本。

因此**不存在排队中的下一拍**可以取消 —— ESC 取消的是当前正在跑的那一拍（既有语义），
`/loop stop` 才是彻底停。

### 2.3 生命周期

- 会话退出（正常 quit / 双 Ctrl+C / SIGINT）必须 `dispose()`，不留幽灵定时器；
- 定时器 `unref()`，不阻止进程退出；
- 循环状态只存内存，不落盘、不跨会话恢复（重启后需重新 `/loop`）。

### 2.4 与既有能力的分工

| 能力 | 触发条件 | 停 |
|---|---|---|
| `/loop` | 时钟 / 上一轮结束 | 手动 `/loop stop` |
| `/goal` | 每轮注入目标锚（不自动触发） | `/goal clear` |
| TurnEnd hooks | 每轮结束跑脚本（不注入提示） | 改 settings |
| #24 目标驱动续跑 | 完成条件判定 | 判定完成 |

## 3 验收

1. `/loop 2m <提示>` / `/loop self <提示>` 可启动，`/loop` 看状态，`/loop stop` 停止；
2. 状态含：模式、已跑次数、跳过次数、提示摘要、下次唤醒；
3. 忙碌/队列非空时丢弃该拍并计入跳过；ESC 取消当前拍；退出会话不留定时器；
4. 默认关闭；`-p` 不可用；
5. `bun x tsc --noEmit` 零错误、`bun test` 全绿、`bash scripts/verify.sh` 为 `ALL GREEN`。

## 4 非目标

- 不做云端 cron / 跨机器调度 / 后台常驻进程（关闭终端即停）；
- 不做循环的落盘与跨会话恢复；
- 不做与邮箱/IM 推送的打通。
