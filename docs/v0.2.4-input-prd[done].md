# v0.2.4 输入层 PRD

> 2026-10-25 · 状态：**实施中**
> 上游 v0.2.3（TUI 补漏）
> 定位：补「输入」这一层 —— 文件引用、命令补全、多行输入。不碰渲染模型。

## 0. 为什么是这三件事

2026 年终端 agent 的标配清单里，neo 缺的正好是输入层的三条（调研见 [[TUI进化路线-2026Q4]]）：

| 标配能力 | neo 现状 |
|---|---|
| `@` 文件模糊补全（内容随消息带入） | **不存在**。`@` 只是纯文本，`HotkeyRouter` 映射了 `"tab"` 但全仓无人注册 |
| `/` 命令/技能补全 | 只认整行精确匹配，无候选、无提示 |
| 多行输入（`Ctrl+J` / `\`+Enter） | **不可能**。粘贴含 `\n` 一律折叠成 `[Pasted text #N]` chip |
| 底部常驻状态栏 | v0.3（本版不做） |
| `Ctrl+O` transcript | v0.3（本版不做） |

选择原则与 v0.2.3 一致：**只在既有 readline 模型内补，不引入自绘输入框**。
自绘（raw mode 全键盘接管）会把粘贴、历史、Ctrl+C、终端原生选中全部重做一遍，
代价远大于收益 —— select 组件的 M0 探针（[[选择器组件-select]]）已经证明这条路的坑有多深。

## 1. 关键风险：bun 的 readline 到底支持什么（M0 探针）

三条能力都取决于 `node:readline` 在 bun 1.3.13 下的真实行为，**先探针、后设计**
（与 select 组件同一套纪律）。探针脚本 `scripts/readline-probe.ts`，结论落
`docs/v0.2.4-m0-probes[done].md`。必须回答：

| # | 问题 | 决定什么 |
|---|---|---|
| P1 | `createInterface({completer})` 是否被调用、Tab 是否替换行缓冲、多候选怎么展示 | 路线 A（原生 completer）是否可行 |
| P2 | completer 入参（是否给 cursor、是否支持异步/回调） | `@` 能否在句中补全 |
| P3 | Tab 是否同时触发 keypress 与 readline 补全（顺序） | `HotkeyRouter` 的 `"tab"` 要不要接线、会不会双补全 |
| P4 | `Ctrl+J`(\n) 与 Enter(\r) 在 keypress / line 事件上能否区分 | 多行用什么触发键 |
| P5 | `rl.line` 能否容纳 `\n`、`_refreshLine` 后显示成几行、提交时内容是什么 | 多行是「直接塞缓冲」还是「continuation 状态机」 |
| P6 | `setPrompt` 中途换 `… ` 是否安全 | continuation 模式能否显示续行提示符 |
| P7 | 补全与 ↑ 历史是否互相破坏 | 是否需要收尾/复位 |

**探针结论（2026-10-25，`docs/v0.2.4-m0-probes[done].md`，P1~P7 全 PASS）**：
真 PTY 下 bun 的**原生 `completer` 是生效的**（单候选自动补全、多候选第 2 次 Tab 列候选），
但入参只有整行、**不给 cursor**；不传 completer 时 Tab 会被当字面量 `\t` 插进行缓冲。
另外 keypress 能区分 `Ctrl+J`(LF) 与 `Enter`(CR)，但 keypress/line 的先后顺序由监听器注册时机决定、
不可靠 —— 换行判定必须走 stdin `data` 事件（比 readline 处理更早）。

> ⚠️ 记录一次误判：最初的探针是在**非 TTY 管道**里跑的（readline 的 terminal 模式默认取
> `output.isTTY`，非 TTY 不跑行编辑器），因此看到「completer 从不被调用、Tab 插字面 `\t`」。
> 真 PTY 复测推翻了这条。教训与 [[neo-开发踩坑]] 2026-10-25 条同类：**readline 行为必须在真 PTY 里断言**。

**最终选择**：路线 B（自接管 Tab）+ A′（continuation），但**注册一个返回空候选的 no-op completer**
从源头吞掉 Tab 字面量。不选原生 completer 的理由不是「不支持」，而是：
`@` 需要「光标前 token 精确替换」而原生不给 cursor；候选排序/样式不可控；多候选时无法做「同一批候选连按循环」。

**两条候选路线**（供未来迁移参考）：

- **A 原生 completer**：`createInterface({completer})`，Tab 由 readline 自己处理插入与候选列表。
  - 优点：零自绘、粘贴/历史/光标全归 readline，风险最低。
  - 缺点：只给「行 + 光标」，候选渲染样式不可控；多候选行为受 bun 实现约束。
- **B 自己接管 Tab**：`HotkeyRouter` 的 `"tab"` + 改写 `rl.line` + `_refreshLine` 自绘候选行。
  - 优点：样式可控（可高亮匹配段、右侧 hint）。
  - 缺点：候选列表要自己画在提示符下方再擦除，与 readline 的光标管理直接打架。

**多行同理两条**：A′ continuation 状态机（拦截触发键 → 暂存当前行 → 提示符换 `… ` → Enter
时拼接提交）；B′ 直接往 `rl.line` 塞 `\n`（仅当 P5 证明安全）。

## 2. 范围（v0.2.4 做这 5 项）

### C1 `@` 文件补全

- 触发：行内任意位置（句中也行），`@` 前面必须是行首/空白/`,([{"'` 之一；
  `@` 到光标之间不能有空白（带空格的路径暂不支持，文档写明）。
- 候选来源：`git ls-files --cached --others --exclude-standard`（尊重 `.gitignore`、快），
  非 git 仓库回退到有界 FS 遍历（跳过 `node_modules/.git/dist/build/.cache/target` 等）。
- 匹配：**模糊子序列** + 路径边界加权（`src/ui/con` 优先命中 `src/ui/console.ts`），
  大小写不敏感，候选上限 20，结果确定（同分按路径长度/字典序）。
- 索引有 TTL 缓存（默认 5s），Tab 连按不重复扫盘。

### C2 `/` 命令补全

- 只在对齐「行首 `/` 且还没输入空格」时触发（即正在敲命令名）。
- 候选来自单一声明表 `src/input/commands.ts`（名称 + 一句说明），
  与 `handleCommand` 的 `switch` 用测试做**漂移守卫**：两侧任一新增/删除而另一侧没跟上立刻红。
- **命令候选不设 20 上限**（表有 33 条；截断会让 `/wiki-lint`、`/ingest` 等尾部命令永远搜不到）。
- 多候选时打印一行候选提示（最多列 8 个 + 「还有 N 个」），命令带说明，文件带路径。

### C3 `@path` 引用展开（补全只是入口，内容要真的送达）

- 提交时解析 `@path`，读出文件内容附在用户消息末尾，格式带明确分隔符：

```
以下是 @ 引用的文件内容：
——— src/ui/console.ts（397 行）———
<content>
——— end src/ui/console.ts ———
```

- 预算：最多 5 个文件、单文件 400 行、总 60KB；超限**截断并标注**（`（已截断）`），不整份丢弃
  —— 先 `stat` 看大小，超预算的文件只读剩余预算的字节（避免为 50MB 文件整读后丢弃）。
- 失败不阻断发送：文件不存在 / 二进制 / 总量预算耗尽 → 一行软提示，`@path` 按原文保留。
- 去重：同一文件只展开一次；**绝对路径与相对路径归一后去重**（`seen` 用绝对路径做 key）。
- `@` 的边界判定与补全共用一份：前一个字符不是邮件本地部分字符（`[A-Za-z0-9._%+-]`）即为边界，
  所以中文紧贴写法 `读一下@src/a.ts` 也能触发，而 `a@b.com` 不会误判。

### C4 多行输入

- 触发键：`Ctrl+J`（真 TTY 下 LF 字节）；`\` + Enter 作为等价回退。
- **非 TTY（管道 / 脚本）下 LF 仍按 Enter 处理**：`printf '/help\n' | neo` 这类脚本化用法不能退化成续行。
- 换行判定用 stdin `data` 事件的**队列**：一个数据块可能产生多个 line 事件；CRLF 只算一个 Enter
  （否则粘贴 CRLF 文本会把 Enter 误判成续行）。
- continuation 期间提示符从 `❯ ` 变 `… `，Esc 放弃续行，Enter 提交拼接后的全文；拼接用 `\n`。
- 续行的半行会从 readline history 回滚（只回滚确实入过 history 的非空行），
  但粘贴折叠 chip 的语义不变（粘贴仍走 chip，不与多行输入抢）。

### C5 可见性

- `/help` 补：`Tab` 补全、`@` 引用、多行触发键、`Esc` 取消续行。
- 提交时若有引用：一行 `· 已引用 2 个文件（+180 行）`；被忽略的引用给软提示。

## 3. 明确不做

| 事项 | 理由 |
|---|---|
| 自绘输入框 / raw mode 全接管 | 会把粘贴、历史、Ctrl+C、原生选中全部重做，风险收益倒挂 |
| 带空格的 `@` 路径、`@` 目录展开 | 需要引号语法，属下一版；写完文档说明 |
| 技能（`/skills <名>`）二级补全 | 先做一级命令；技能列表可后续复用同一 completer |
| 语法高亮的候选列表 | 需要自绘，与本版「不换渲染模型」冲突 |
| `Ctrl+R` 历史搜索 | 独立功能，v0.2.5 候选 |

## 7. simplify 三阶段审查记录（2026-10-25）

并发 3 个只读 reviewer（复用/质量/效率）→ 聚合 → critical/major 全部处置。**最有价值的几条**：

| 来源 | 严重度 | 问题 | 处置 |
|---|---|---|---|
| quality | critical（人工 PTY 发现） | 无参 `rl.prompt()` 会把 `rl.cursor` 归零 → Tab 补全后继续输入变成 `X@a.txt`；S5/S6 原断言兜不住 | `applyLine` 固定用 `_refreshLine()`；新增 S9 专门断言光标位置 |
| quality | major | Tab 连按循环不成立：第二按 token 已变成候选本身 → 重新搜索、候选集缩小，首轮候选永远轮不到 | `tabCycle` 记住「上次应用后的整行 + 插入区间」，行未编辑才在同一批候选里推进；新增 S10 + 单测 |
| quality | major | 续行无条件 `dropHistory(1)` 会误删上一条真实历史（readline 本来就不收空行） | 改成只在 `history[0] === raw` 且非空白时回滚 |
| quality | major | 换行种类按「一个数据块一个标量」记录：一块多个 line 事件会误判；CRLF 末字节 LF 被当成 Ctrl+J | 改成按块解析的**队列**，CRLF 只算 Enter |
| quality | major | 引用超 60KB 是「整份跳过」，与 PRD「截断并标注」相反 | 先 stat，超预算按剩余字节 `readSlice` 截断并标注 |
| quality | major | 去重 key 只剥 `./`，绝对/相对路径指向同一文件会展开两次 | `seen` 用解析后的绝对路径 |
| quality | major | 命令补全沿用 limit=20，33 条里后 13 条永远不可见；提示行从不列候选 | 命令候选不设 20 上限；提示行列出候选名与「还有 N 个」 |
| quality | major | README/注释把「自接管 Tab」的理由写成「bun 不支持 completer」（与自家探针结论矛盾） | 全部改成准确表述：原生可用，但缺 cursor、排序不可控，故选自接管 + no-op completer |
| quality | minor | `@` 后紧跟中文不触发（`读一下@src/a.ts`）；命令行的 `@` 补全被静默忽略 | 边界改为「非邮件本地字符」；命令行内不提供 `@` 补全 |
| reuse | major | `FILE_BOUNDARY` 与 references 各一份；`promptForContinuation` 重写 `continuationPrompt`；`applyCompletion` 二次解析 token | 全部收敛为单份实现（`FILE_BOUNDARY`/`isAtBoundary`、`continuationPrompt`、`applyMatch`） |
| efficiency | critical | `FileIndex.list()` 在 Tab 回调里同步 `Bun.spawnSync('git ls-files')`：2 万文件仓库实测 75ms 卡按键 | 改为异步后台刷新 + 按键只读缓存（启动时 await 预热一次） |
| efficiency | major | 按 Tab 时无条件取文件索引（命令补全/普通文本也付费）；每次循环重跑全量打分 | 先判触发类型；`tabCycle` 缓存候选；空查询直接 `slice` |
| efficiency | major（跨域 bug） | `rankFiles` 用 `s >= 0` 过滤，而分数是 `score - target.length` → **深路径真实命中变负被丢弃**（monorepo 里 `@` 补全基本出不来） | 不命中改用 `-Infinity` 哨兵；补深路径回归用例 |
| efficiency | minor | 引用先整读再判预算（50MB 文件 5.86ms + 50MB 瞬时占用） | 先 `stat`，超预算才 `readSlice` |

**明确未采纳**（记录理由，避免下次重复讨论）：
- 把 readline 行缓冲改写收敛成一个 helper（涉及 paste-end 的历史回滚与 select 的清行，回归面大 → 留 v0.2.5）。
- 把仓库里 5 处目录遍历抽成共享 `walkTree`（跨 system-prompt/tools，改动面大 → 单独重构）。
- 把 `Ctrl+J` 改成「rl 创建前预注册监听 + 改写 key.name」路线（探针证明可行，但现字节队列已覆盖且更少侵入 readline）。

## 8. 风险

- **bun readline 能力不足**：A 路线不可行时退回 B，但 B 要自己管候选行绘制 —— 若探针显示两者都不可靠，
  C1/C2 降级为「`@`/`/` 触发时在下方打印一行候选（不接管 Tab）」，并在 PRD 记录降级理由。
- **`@` 展开改变消息体积**：预算（5 文件/400 行/60KB）与软提示必须生效，否则一次 `@` 可能顶掉半上下文。
- **多行与粘贴 chip 语义交叉**：粘贴仍折叠为 chip，多行只影响手打续行，测试要覆盖「两者同轮出现」。
