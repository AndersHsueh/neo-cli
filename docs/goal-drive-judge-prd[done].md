# 目标驱动 · LLM 评估完成条件（issue #50，来源 #24 非目标）

> 状态：已交付（v0.4.84）
> 口径依据：维护者 2026-11-10 拍板 **接受模型判断**（neo-agent 设计原则「信任模型判断」）。
> 与旧口径的关系：`docs/goal-drive-prd[done].md` 的「完成条件只认可验证信号」**被本 PRD 修正**，
> 但修正方式不是「模型说了算」，而是**验证优先、模型判断单独标注来源**。

## 1 背景与目标

`/drive` 现在的完成条件只有一种：每轮结束跑检查命令，`exit 0` 才算完成。这挡住了两类真实目标：

- 没有可执行检查命令的目标（「把 README 的可读性改好」「检查这套 API 命名是否一致」）；
- 检查命令只能覆盖一部分验收标准的目标（命令过了，但模型知道还剩手工步骤）。

目标：让 `/drive` 在**用户显式给出完成标准描述**时，用模型判断「是否达成」，并且**绝不把模型判断冒充成已验证**。

## 2 需求

### 2.1 命令面

- 现有形态不变：`/drive <检查命令> -- <提示>`，完成条件 = 检查命令 exit 0（**已验证**）。
- 新增形态：`/drive --judge "<完成标准描述>" -- <提示>`，完成条件 = 模型判断（**模型判断**）。
- 两者可同时给：`/drive <检查命令> --judge "<补充描述>" -- <提示>`：
  - 检查命令是**硬条件**：exit 0 → 立刻完成，标注 **已验证**；
  - 检查命令未通过时，再问模型判断；模型判断为达成 → 停止推进，但标注 **模型判断**（不是已验证）。
- 两者都没给：`/drive` 报用法错误（保持现有行为）。

### 2.2 判定规则（硬口径）

| 场景 | 结果状态 | reason 标注 |
|---|---|---|
| 检查命令 exit 0 | done | `verified`（已验证） |
| 无检查命令，模型判断达成 | done | `model`（模型判断） |
| 检查命令未过 + 模型判断达成 | done | `model`（模型判断；文案说明「检查命令未通过」） |
| 模型判断未达成 | continue（沿用 maxRounds / idleRounds） | — |
| 模型判断请求失败 / 超时 / 输出不可解析 | 视为**未达成**，记 note；连续 2 次失败提示用户 | — |

- **文案铁律**：`model` 的结束文案不得包含「已验证 / 通过验证」字样；`verified` 也不得写成「模型认为完成」。
- `/drive status` 要能看到最近一次判断的：来源（verified / model）、原因（reason）、轮次。

### 2.3 实现要点

- `DriveSpec` 增加 `judge?: { criteria: string }`；`DriveManager` 增加注入依赖
  `evaluate?: (input: { criteria: string; prompt: string; recentOutput: string; lastCheck: DriveCheckResult | null }) => Promise<{ done: boolean; reason?: string }>`，
  纯状态机保持可单测（不直接 import 模型调用）。
- 宿主（`src/index.ts`）接线：用**一次独立的小请求**（复用 agent 的 `streamFn` / provider 配置，参考
  `compactNow` 的「单独一次小请求」模式）判断，输入：目标提示 + 最近一轮工具输出摘要（截断到合理长度）
  + 最近检查命令结果（code/output 摘要）；期望输出 JSON `{done: boolean, reason?: string}`。
- 单轮判断只发一次请求；`maxRounds` 默认不变；判断请求计入成本但不在状态行实时显示（可选 `/drive status` 里给次数）。
- 提示词要明确要求：「只根据给出的工具输出判断，不要臆测未出现的结果；不确定就判 false」。

### 2.4 非目标

- 不做多轮辩论 / 自我反思链 / 自动改写完成标准；
- 不做「模型判断代替检查命令」的默认行为（只有用户显式 `--judge` 才启用）；
- 不做 `-p` 无人值守长跑（另见 #35 第 3 批）；
- 不加 PTY 场景（判定纯逻辑 + 命令层可单测；真实长跑属另一项）。

## 4 风险

- **模型自欺**：judge 只看工具输出摘要，可能顺着「应该完成了」说 done。缓解：提示词要求不确定判 false；
  来源标注保证用户知道这是模型判断；有检查命令时以命令为准。
- **成本**：每轮一次额外小请求。缓解：只在用户显式 `--judge` 时启用；`maxRounds` 上限不变。
- **摘要失真**：工具输出摘要截断可能让 judge 误判。缓解：摘要保留最近一轮的关键输出（命令、错误、文件路径），
  截断时明确标注「已截断」。
