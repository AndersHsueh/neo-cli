# 后台长驻 shell PRD（issue #28）

> 状态：实现中（待审查）
> 关联：GitHub #28。与 #16（后台子代理）正交：这里管**长时间 shell 进程**（dev server / watch / 长测试）。

## 1 背景

`shell` 工具同步等待 stdout/stderr/退出码，默认 120 秒，超时或中止直接 `kill(9)`。
想在同一会话里起 `npm run dev` 再改代码 → 要么卡死 agent 循环，要么超时被杀。

## 2 需求

1. **后台启动**：`shell` 新增 `background: true` → 立刻返回命令 id（`sh-N`），会话继续可用；
   不传 = 旧行为不变。
2. **回读**：新增只读工具 `shell_output`（参数 `id`、可选 `tail_lines`）→ 返回状态、退出码、已跑时长、输出尾部；
   未知 id 明确报错并指向 `/ps`。
3. **超时转后台（不杀）**：前台调用超过 `timeout_ms` 时，**不杀进程**，而是把同一条进程转入后台，
   返回 id 与提示。这样「长任务」既不会卡死循环，也不会白跑。
4. **用户可见/可停**：`/ps` 列出后台命令（id / 状态 / 耗时 / 退出码 / 命令摘要），`/ps kill <id|all>` 停止。
5. **生命周期**：会话退出 `killAll()`，不留孤儿；并发上限默认 5，超过直接拒绝（不排队）。
6. **权限**：与前台 `shell` 完全同口径（同一个 `gateTool` 审批 / plan 拒绝 / `-y`），不新增旁路。

## 3 验收

1. `shell(background: true)` 立刻返回 id，主循环继续；前台行为（`$ cmd` + 输出 + `[exit N]`）不变；
2. `shell_output` 能按 id 读后续输出 / 退出码 / 状态；`/ps` 能列出并停止；
3. 前台超时**默认转后台而不是杀进程**，并给出 id；
4. 会话退出清理本次会话拉起的后台进程；并发上限生效；
5. 审批与 plan 口径与前台一致；
6. `bun x tsc --noEmit` 零错误、`bun test` 全绿（含 PTY）、`bash scripts/verify.sh` 为 `ALL GREEN`。

## 4 非目标

- 不做交互式 PTY 会话、不做 attach/切终端（仍是「命令 + 输出流」）；
- 不做跨会话 / 跨机器后台进程（会话退出即清理）；
- 不做 Ctrl+B「把正在跑的前台命令撤到后台」的按键绑定（首期只给模型显式 `background` 与超时自动转入；
  按键绑定涉及 TUI 键位冲突，另议）；
- 不改权限模型。
