## 1. 本轮结论与边界

### 1.1 产品目标

1. **让无人值守结果可信**：检查命令未通过时，模型判断不得再被 CI 当成成功；模型/网关故障有有限、可解释的恢复路径。
2. **让长任务可编排**：`-p` 不只给最终文本，还能实时输出可解析、可追踪、保密边界明确的结构化事件。
3. **让公开表达与仓库事实一致**：用两个 Web 成果解释已发布能力、版本演进和当前限制，不把规划写成上线，不虚构安装渠道或平台保证。

### 1.2 固定范围

本轮只交付：

- **P1 / #52**：LSP、仓库地图默认关闭；`-p --drive` 仅模型判断时退出 3。
- **P1 / #59**：主 Agent 模型请求的有序备用链，可跨 provider，故障切换有界且可见。
- **P1 / #37**：`-p --output-format stream-json` JSONL 事件输出。
- **P1 / Web A**：独立、可离线打开的版本演进 HTML。
- **P1 / Web B**：响应式宣传推广 Web 门户。

本轮没有 P0 项。其余 15 个开放 Issue 均不在本轮实现范围；#35 只做状态梳理建议，不顺手完成其中事项。Web 页面可以做成本地静态成果，不包含公开部署、账号体系、下载服务、分析统计或后端。

### 1.3 用户故事

- 作为 CI 维护者，我希望只有真实检查成功才返回 0，以便不会把模型自判误记为构建成功。
- 作为长任务操作者，我希望主模型不可用时有明确、有限的备用链，以便一次网关波动不直接作废整个任务。
- 作为编排器开发者，我希望逐行消费初始化、轮次、工具、切换和最终事件，以便实时观察进度并可靠处理失败。
- 作为现有或潜在用户，我希望快速看懂版本、能力、限制和真实使用入口，以便判断是否适合我的终端工作流。

## 4. 本轮核心 Issue 增量 PRD

### 4.1 #52：默认能力收口与无人值守退出码修正

**用户价值**：默认上下文更克制，减少不常用工具和仓库扫描；CI 能把“检查通过”与“模型认为完成”可靠区分。

**范围**：

1. 未显式配置时，`lsp.enabled=false`、`repo_map.enabled=false`；示例配置和 README 给出显式开启方法。
2. 仓库地图关闭时不扫描、不注入；LSP 关闭时不启动 server，工具清单和系统提示词均不出现 `lsp`。
3. 用户已显式 `enabled:true` 时保持原能力；显式 `false` 继续关闭。
4. `-p --drive` 退出码改为：verified done=0；exhausted/idle-stop/timeout=1；用法错误=2；**model done=3**；SIGINT=130。
5. 交互式 `/drive` 的座次、停止流程和来源文案不变；stderr `[drive]` 摘要格式不变。

**非目标**：不拆主循环；不改变 shell 工具结果语义；不改变交互式 `/drive` 对模型判断的接受；不夹带 #37 或 #35 暂停项；不删除 LSP/仓库地图能力。

**可验证验收**：

- [ ] 52-A：无配置、显式 true、显式 false 三组测试覆盖默认值与覆盖关系。
- [ ] 52-B：默认配置下无仓库地图注入、无 LSP 工具/提示词；显式开启后既有 LSP/地图用例仍通过。
- [ ] 52-C：检查命令成功返回 0 且 `source=verified`。
- [ ] 52-D：无检查命令、judge 判 done 返回 3 且 `source=model`。
- [ ] 52-E：检查失败但 judge 判 done 同样返回 3，绝不返回 0。
- [ ] 52-F：1/2/130 的既有路径不回归，stderr 摘要字段与顺序不变。
- [ ] 52-G：全量 `bash scripts/verify.sh` 输出 `ALL GREEN`，记录实际 pass/fail/skip 和 PTY 数字。

**风险与文档**：默认关闭是预期行为变化，release note 必须明确；旧 v0.4.84 文档的“模型判断达成退出 0”是历史描述，当前行为文档须同步修订 `docs/oneshot-drive-prd[done].md`、README、CLI help 和下一版 release note。宣传中“可信”只指退出码与来源区分，不等于模型不会犯错。

### 4.2 #59：有序模型备用链

**用户价值**：主模型/网关在长任务中发生暂时或确定性故障时，主 Agent 能按用户配置的优先级继续，而不是耗尽同模型重试后整轮失败。

**产品语义与范围**：

1. settings 与 CLI 均可配置**有序**备用链；每项必须解析为明确的 `provider + model`。CLI 对本次运行覆盖 settings，不提供隐式随机选择或负载均衡。
2. 主模型对网络/超时/429/5xx 等可重试错误先执行既有同模型重试；耗尽后才进入下一项。明确的模型级“不存在/无权限”可提前切换。
3. 普通参数错误、上下文超长、用户中断、工具失败、检查命令失败不得被伪装成模型故障并触发备用链。无法明确归因的 400/401/403 不得仅凭状态码武断切换。
4. 每个候选使用自己的目标协议、上下文窗口、`max_output_tokens`/输出预算和已知能力；不得把源模型限制直接套到目标模型。
5. 切换必须有用户可见提示与机器可消费日志：来源 provider/model、目标 provider/model、脱敏原因；不输出 API key、Authorization 或完整 settings。
6. **恢复策略定为会话内保持**：一旦切换成功，本会话后续主 Agent 请求留在当前可用目标，不做后台健康探测或自动回切；用户显式切换或新会话才回到新解析的配置。切换结果不改写 settings。
7. 所有候选失败才报错，并保留按顺序的脱敏失败摘要；总重试/切换次数必须有界，禁止循环回已失败候选。
8. 用量和成本计入实际提供响应的 provider/model；流式响应、会话历史和系统提示中的当前模型信息保持一致。
9. 本轮承诺主 Agent 的交互与 `-p`（含 `--drive`）请求。分类器、compact、judge、记忆提炼、子代理不分别设计独立备用链；若复用底层自然受益，文档须如实说明，但不借此扩大本轮验收范围。
10. #37 落地后，备用切换必须产生 `model_fallback` 逻辑事件，最终结果反映实际模型；#52 的退出码语义不因切换成功而改变。

**非目标**：不做自动选“最便宜/最快”模型，不做跨会话健康缓存，不做自动回切，不做 provider 密钥管理或 OAuth，不承诺辅助 LLM 调用各自独立配置，不解决业务逻辑/工具失败。

**可验证验收**：

- [ ] 59-A：settings/CLI 有序链解析、CLI 覆盖、空链禁用、未知 provider/空 model/重复或非法项的可读错误均有测试；非法配置在发模型请求前失败。
- [ ] 59-B：同模型重试耗尽后按顺序切换；明确的模型不存在/无权限可切换；普通 400、用户中断、工具/检查失败不切换。
- [ ] 59-C：跨 provider 与 OpenAI/Anthropic 协议组合用 fake 流验证；目标上下文和输出预算重新约束，不继承源模型错误上限。
- [ ] 59-D：首个备用失败、第二个成功；全部失败；不重复候选；总尝试次数有限。
- [ ] 59-E：切换提示与日志无密钥；`/cost`、最终状态和后续轮次归属实际目标模型；会话内不自动回切且配置不被改写。
- [ ] 59-F：`-p --drive` 在主模型故障后由备用模型完成真实检查，最终仍按 verified=0；只有 model done 仍按 #52 返回 3。
- [ ] 59-G：全量闸门 `ALL GREEN`；测试使用 fake，不以真实第三方网关可用性作为唯一证据。

**风险与文档**：错误归因和跨协议历史是主要风险，架构需先给出复用边界与状态归属；配置命名必须区别既有 `fallback_allowed`。README/settings 示例/CLI help 必须给有序链示例、触发条件、会话内保持策略和成本提示；release note 说明该能力提高可恢复性但不保证任务成功。

### 4.3 #37：`-p` stream-json 事件流

**用户价值**：CI、IDE 和上层编排器无需等待进程结束或解析人类文本，即可逐行观察任务进度、工具状态、模型切换和最终结果。

**范围与 v1 契约**：

1. 新增 `-p --output-format stream-json`；既有 `text`、单行 `json` 默认行为不变。仅用于 `-p`，与其它模式的非法组合给可读用法错误并退出 2。
2. stdout 只输出 JSONL：一行一个完整 JSON 对象，无 ANSI、横幅、人类诊断或逗号包装；诊断走 stderr。每行可独立 `JSON.parse`，写出后及时 flush。
3. v1 统一信封至少含 `schema_version`、`type`、`session_id`、严格递增的 `seq`、`timestamp` 和 `data`；具体字段类型与示例由架构一次定稿并公开文档化，本轮内不得同义多套。
4. 至少覆盖逻辑事件：`init`、`turn_started`、完整 `assistant_message`、`tool_started`、`tool_finished`、`model_fallback`（#59 发生时）、`drive_finished`（使用时）、`error`、`result`。
5. v1 的 assistant 事件可以是每轮完整消息，不承诺 token 级 delta；工具和轮次事件必须实时。工具事件用稳定 call id 关联，至少含工具名、状态/错误和必要摘要；文件写改事件能定位路径。
6. 正常或已捕获失败路径最终恰好一个 `result`，含最终状态、退出码、实际 provider/model、用量及 drive 来源（若有）。事件顺序与进程退出码一致：#52 的 model done=3，verified=0，其它 1/2/130 规则不改。
7. 默认不输出模型思维链、密钥、Authorization 或 settings 原文。工具参数/结果采用文档化长度上限与显式 `truncated` 标记，避免无界单行；不宣称能识别所有任意形态秘密。
8. 下游关闭管道/写入失败不得造成死锁或无限重试；行为与诊断必须定义并测试。

**非目标**：不做 `--input-format stream-json`，不做交互式 TUI JSON 化，不做 ACP（#60），不承诺 Claude/Codex schema 兼容，不做 token 级流式文本、远程事件服务、事件持久化/重放或通用敏感信息扫描器。

**可验证验收**：

- [ ] 37-A：普通成功、多轮工具、模型错误、参数错误分别逐行解析；stdout 无额外文本，事件 `seq` 连续递增，最终 `result` 恰好一次。
- [ ] 37-B：工具开始/结束按 call id 配对，顺序和错误状态正确；长输出截断有标记，密钥字段和思维链不进入事件。
- [ ] 37-C：既有 text/json 回归通过；非法格式/模式组合退出 2。
- [ ] 37-D：与 #52 组合验证 verified/model/exhausted 的 result 与退出码；与 #59 组合验证 fallback 事件和最终实际模型。
- [ ] 37-E：下游提前关闭管道不挂死；资源清理沿用既有 `-p` 路径。
- [ ] 37-F：schema 示例可被脚本消费；全量闸门 `ALL GREEN`。

**风险与文档**：最大回归风险是 stdout 污染和异步事件乱序，其次是工具载荷泄露/超大行。README、CLI help 和 release note 必须包含最小命令、事件表、版本化 schema、截断/保密边界、退出码与一个可运行消费示例；以后变更须按 schema 版本处理。

## 6. 统一品牌与产品口径

### 6.1 三者关系

- **neo-agent**：对外产品与项目统称，用于标题、介绍和团队协作语境。
- **neo-cli**：GitHub 仓库名，用于仓库链接、克隆/源码语境，不在本轮改名。
- **neo**：package/bin 名称和用户实际命令入口，所有命令示例使用 `neo` 或 README 的 `bun run src/index.ts`，不虚构 `neo-agent` 可执行文件。

推荐首次出现：

> **neo-agent 是 neo-cli 仓库中的 Matrix 风格终端编程助手，命令行入口为 `neo`。它通过 Bun 运行，可连接 OpenAI 兼容或 Anthropic Messages 协议的 LLM 网关。**

英文简版：

> **neo-agent is the product name for the terminal coding assistant in the neo-cli repository; its CLI command is `neo`.**

不推荐：“neo-agent 已改名 neo”“neo-cli 是另一个产品”“安装 neo-agent npm 包”“neo-agent 官方 IDE/云服务”。本轮不做仓库、package、bin 的重命名或迁移。

### 6.2 统一价值表达

主口号建议：**“把终端编程、长任务验证与多会话协作放进同一个 CLI。”**

辅助表达必须保留条件：模型判断只是判断；备用链提高恢复机会但不保证成功；结构化事件提高可观测性但不替代测试；worktree 只隔离文件；用户需提供模型网关与密钥。所有对外文案由运营/设计使用 §5.4 的事实表，不自行创造能力形容词。
