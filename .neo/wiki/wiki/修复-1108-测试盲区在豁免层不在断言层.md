# 修复-1108-测试盲区在豁免层不在断言层

> 最后更新:2026-11-08

## 摘要

Cypher 对 `tests/` 全 92 个文件、1667 个 test/it 调用点的只读审计结论：**盲区不在断言层，而在豁免层**。断言层是干净的（无空断言、无永真断言、无 expect 全被包在条件分支、无整块注释掉的测试、`test.only`/`test.todo` 零命中）；但有 2 处 skip、1 处静默 `return`，而 `scripts/verify.sh` 的 tests 阶段**只看退出码**（bun test 有 skip 时退出码仍是 0）—— 合起来构成「闸门报 ALL GREEN，覆盖却可能缺一块」的结构性缺口。已派会话修（skip 守卫 + 显式 skip + README 补真）。

## 审计结论明细

### 一、静默跳过 / 禁用

- **`tests/prompt-tiers.test.ts:19`** — `test.skipIf(!hasSources)`，3 个用例（full/standard/mini 与源文件逐字一致）。豁免**合理**（有注释：bot-comments 在仓库外的兄弟目录，缺失时跳过不当作失败）。但挖出更值得注意的机制：
  - `SOURCE_DIR = join(import.meta.dir, "..", "..", "bot-comments")` 指向**仓库父目录**；
  - 主仓 `000-alice-new/neo` → `000-alice-new/bot-comments` 存在 → 3 条**跑**；
  - 任何 worktree（`neo-worktrees/xxx`）→ `neo-worktrees/bot-comments` 不存在 → 3 条**skip**；
  - ⇒ **闸门在不同布局下覆盖的用例集合不同**，「提示词逐字一致」这条最重要的契约在 worktree 下从未被验证。
  - ⇒ **基线数字订正**：主仓实测是 **1676 pass / 0 fail / 92 文件（0 skip）**；「3 skip」是 worktree 布局下的现象。此前记的「1676 pass / 3 skip」需以主仓为准。
- **`tests/b4-tools.test.ts:74`** — `describe.skipIf(process.platform === "win32")`（D2 shell cwd，2 例）。豁免**合理**（Windows 的 shell/cwd 语义确实不同），但**缺注释与恢复条件** → 低危待处理。
- **`test.only` / `describe.only` / `test.todo`** —— 零命中。
- **整块/整文件被注释掉的测试** —— 零命中（92 文件逐行块注释状态机扫描；朴素 `split("//")` 会在 `skills/**/*.md` 这类路径上误报，已用状态机排除）。
- **`tests/file-index.test.ts:149`** — `if (!git) return; // 环境无 git：跳过（不失败）` ⇒ **真实盲区**：用 `return` 而非 `test.skipIf`，环境缺 git 时用例**静默通过、报告显示 pass、无跳过标记**。且与本仓 `tests/gitignore-rules.test.ts:16-20` 的纪律（「环境坏了必须 fail，不能 skip —— 绝不用 skip/tolerate 掩盖」）直接冲突。

### 二、空断言 / 永真断言

- 无任何断言的用例 —— 零（唯一候选 `tests/memory-agmd.test.ts:74` 用的是自定义辅助 `expectWellFormed()`，内含 3 个真 expect，属脚本误报）。
- 永真断言（`expect(true).toBe(true)` 等）—— 零。
- expect 全被包在条件分支里 —— 零（精确括号配对判定；首轮启发式报的 96 条全为误报）。
- 单行 `if (cond) expect(...)` —— 14 处，逐条核实均非盲区（前提已被上一条 expect 锁定，条件恒真，属 TS 窄化需要）。
- `tests/gitignore-rules.test.ts:76` 的 `assertWorktreeHealthy()` 刻意 `throw` 而非 expect —— 合理设计，非盲区。

### 三、机制性缺口：verify.sh 没有 skip 守卫

`scripts/verify.sh:44-64` 的 `run_stage` **只看退出码**；bun test 存在 skip 时退出码仍为 0 ⇒ **ALL GREEN 不代表覆盖完整**。静默跳过会随版本悄悄累积，闸门对此毫无反应。
⇒ 「闸门能跑 ≠ 覆盖到位」。修法：tests 阶段后加 skip 数检查（解析输出里的 skipped 条数），不为 0 时告警，并提供 env 开关（如 `NEO_STRICT_SKIPS=1`）令其 fail。

### 四、`tests/README.md` 与实际脱节

| 项 | README 声明 | 实测 |
| --- | --- | --- |
| §1 基线 | 1097 pass / 0 fail / 70 文件（2026-11-04，v0.4.12） | **1676 pass / 0 fail / 92 文件** |
| §4 文件清单 | 「46 个」，表格最新停在 v0.4.3 | 92 个 `.test.ts`；v0.4.12 后完全没追加 |
| §2 回归锚点 | 「任何提交以 tsc + bun test 双绿为准」 | v0.4.5–v0.4.77 从未跑过 verify.sh |
| 跨平台纪律 | 「不写死开发者机器路径：用 import.meta.dir / tmpdir()」 | `prompt-tiers.test.ts:13` 用 `../../bot-comments` **依赖仓库物理位置** |

最后一条是**约定自我违反**：README 自己在 v0.4.0 立了「不写死路径」的规矩，而该测试恰恰用了依赖物理布局的相对路径，导致 skip 数随布局漂移。

## 待人工确认

- **bot-comments 是否应纳入版本控制** —— 涉及仓库边界与外部资料管理。
- **「提示词与源文件逐字一致」这条契约是否仍需要** —— 若 prompt 已改为运行时生成则可退役；否则它就是「最重要的契约恰好是最常被跳过的那条」。
- **file-index 的 git 集成用例在无 git 环境下应 fail 还是 skip** —— 倾向显式 skip（可见），但与 gitignore-rules 的「坏环境必须 fail」取向相反，需定口径。

## 一句话结论

本仓的测试盲区**不在断言层**（无空断言、无永真断言、无 expect 全条件包裹、无整块注释掉的测试），而在**豁免层** —— 2 处 skip、1 处静默 return，加上 verify.sh 对 skip 数零感知，合起来构成「闸门绿但覆盖可能缺一块」的结构性缺口。
