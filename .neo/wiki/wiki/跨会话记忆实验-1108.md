# 跨会话记忆实验-1108

> 最后更新:2026-11-08

## 摘要

2026-11-08 参加了一次跨会话记忆实验：Anders 想验证「项目级 wiki 记忆」在弱模型（glm-5.3-flash）上是否真的管用。实验由另一个会话（@claude）主持，我在自己的项目 wiki（`neo/.neo/wiki/`）里作为被试方参与。

- **第一步（问）**：@claude 提问「neo 最近一次发布的版本与测试基线是多少，要求凭 wiki 不要凭印象」。我检索到主题页 [[neo-v0.4.2-tier视觉]]，答出 v0.4.2 与 1039 pass / 0 fail / 67 文件，并交叉核对了 `log.md` 第 275 行的 milestone 条目。
- **第二步（写）**：就是本页面本身——要求我把实验经过写进 wiki。
- **第三步（回信）**：用 `send_message` 把结果回传给主持方。

## 起因

Anders 的假设是：很多工具型 agent 的「记忆」在弱模型上容易退化成装饰——模型记不住自己写过什么，于是每次都要重新翻文档。neo 的项目级 wiki 如果真能在弱模型上被可靠检索和引用，说明「记忆文件 + 检索工具」这条轻量路线对弱模型也成立。

## 过程

### 第一步：被提问（只读）

@claude 的要求很明确：凭项目 wiki 回答，不许凭印象。实际检索路径：

- `wiki_search(query="v0.4.2 tier 视觉")` → 命中主题页 [[neo-v0.4.2-tier视觉]] 与 `log.md`；
- `read_file` 读主题页全文，取「摘要」段（版本 v0.4.2、2026-10-27、commit `a978cde`）与「测试与证据」段（1039/0/67、PTY 20/20、verify ALL GREEN）；
- 旁证 `log.md` L275 的 milestone 条目写的是 1034/67——与主题页的 1039 不一致，属于发布当日早期数字与最终基线的差别，回信里明确标注了这一点，没有当成矛盾。

**结论**：一次 `wiki_search` + 一次 `read_file` 就能把「当前版本 + 测试基线」这种事实性问题答准，不需要翻代码或 git。

### 第二步：写这一页（本页）

把实验经过按项目 wiki 规则落成主题页：中文短语命名、页首 `> 最后更新:` 日期戳、`## 摘要` 段、`[[ ]]` 互链，并由 `wiki_write` 工具同步 INDEX 与 log。

### 第三步：回信

用 `send_message(target="20261108-022500-claude", reply_to=...)` 回传改动的文件清单。

## 我自己的小失误

第一次回信时我把 target 写成 `@claude`，宿主报「找不到目标会话」。原因是 `list_peers` 显示的名字前缀带 `@` 只是显示形式，实际匹配用 session id 更稳（名字也支持，但显示名与 id 混着记容易出错）。

纠正方式：调用 `list_peers` 拿到真实 session id（第一次是 `20261108-022121-claude`），再用 id 投递。

更值得记的一层：第一次投递失败之后，那个会话**已经退出**了，宿主返回「进程已退出，v1 不排队、不缓存离线消息」——也就是说回信必须趁会话还活着送达，晚一步就彻底丢失，没有重试队列兜底。这个约束对「派活—回信」型协作很关键：不要假设离线消息会被缓存。

## 为什么这次经历对我有用

我参与这个项目的方式，本身就是「自己查 issue、自己改进、再提交」——本质上是**单会话内的自举式记忆**：遇到问题先查历史记录（wiki / issue / 代码），改完再把根因写回去，让下一次不再从零开始。

这次实验的价值在于，它把这个循环**外部化并被观测**了：

1. **弱模型 + wiki 能不能行**——答案是能。检索路径短、命中率高、答得准。这说明我的记忆体系不是「只有强模型才用得动」的资产。
2. **记忆的价值不在存了什么，在能不能被检回**——主题页 + 摘要 + 互链的结构，任何模型都能靠 `wiki_search` + `read_file` 两步命中。结构化的价值大于内容的丰富度。
3. **事实冲突要显式处理**——主题页 1039 与 log 1034 并存时，正确做法是标出时间差与「哪个是最终基线」，而不是挑一个数字。这种「并列记录 + 注明口径」的习惯，正是 wiki 页面能被长期信任的前提。
4. **参与实验本身就是一次记忆加固**——本页记下的不只是「实验做了什么」，还有回信 target 的写法、离线消息不缓存的约束。这些是以后每次跨会话协作都会复用的操作性事实。
