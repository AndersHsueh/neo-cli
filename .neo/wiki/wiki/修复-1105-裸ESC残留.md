# 修复-1105-裸ESC残留

> 最后更新:2026-11-05

## 摘要

2026-11-05（v0.4.34），修复 TUI 的**裸 ESC 残留**缺陷：不构成合法转义序列的 ESC（后面跟普通字符或直接到结尾）此前被 `tokenizeAnsi` 当作零宽 token **原样保留在输出里**，导致 `truncateAnsi` 截断后行尾挂一个裸 ESC，把终端推进转义状态、吞掉后续输出。三处同源缺陷一并修复：`tokenizeAnsi`（丢弃裸 ESC）、`stripAnsi`（补剥）、`theme.ts` 的 `ANSI_ESCAPE`（补剥，宽度不再虚高）。`bun test` 1130 pass / 0 fail，`tsc --noEmit` 干净。未 commit。

## 缺陷与根因

三处正则都只认「ESC + 合法转义序列」（CSI / OSC / `\x1b<@-_>`），裸 ESC 落在覆盖范围外：

| 位置 | 修复前行为 |
| --- | --- |
| `src/tui/ansi.ts` `tokenizeAnsi` | 兜底分支 `out.push({kind:"sgr", s:ch, w:0})` 把裸 ESC **保留**为 token |
| `src/tui/ansi.ts` `stripAnsi` | `\x1b[@-_]` 只匹配 ESC+@-_，`\x1bdef` 原样返回 |
| `src/ui/theme.ts` `ANSI_ESCAPE` | 同上，`displayWidth("abc\x1bdef")` 算出 6（实际显示 3 列） |

探针实测（修复前）：

```
displayWidth(abc\x1bdef) = 6          ← 虚高，frame 会误判超宽
stripAnsi(abc\x1bdef)    = "abc\x1bdef"  ← 剥不掉
truncateAnsi("hello\x1bworld", 5) = "hello\x1b"  ← 行尾裸 ESC
wrapAnsi("abc\x1bdef", 3) = ["abc\x1b", "def"]
```

## 修法

1. `tokenizeAnsi`：裸 ESC 分支改为**直接丢弃**（`i += 1; continue;`），不产生 token。裸 ESC 不携带任何可渲染信息，保留只会污染终端状态。
2. `stripAnsi`：末尾追加 `.replace(/\x1b/g, "")` 兜底剥掉残余 ESC。
3. `theme.ts` `ANSI_ESCAPE`：备选分支追加 `|\x1b`，宽度计算不再把裸 ESC 之后的内容算错。
4. `truncateAnsi` 快路径加 `!text.includes("\x1b")` 前置条件——否则裸 ESC 零宽会让宽度检查放行、原样返回带 ESC 的原文（红测试踩到过）。

## 验证

- 新增测试 `tests/tui-frame.test.ts` A1i：覆盖 `displayWidth` / `stripAnsi` / `tokenizeAnsi` / `truncateAnsi`（含结尾裸 ESC）/ `wrapAnsi` 五个面。
- 证据：`docs/evidence/v0.4.34-tests.txt`（1130 pass / 0 fail）、`docs/evidence/v0.4.34-tsc.txt`（空，exit 0）。

## 推理与依据

- **为什么丢弃而不是保留**：合法的两字符转义 `\x1b[@-_]` 有明确语义（如 `\x1bM` 反向索引），必须保留；裸 ESC 没有——它是截断/拼接产生的残渣。保留它等于把一个「未完成的转义前缀」交给终端。
- **为什么 `truncateAnsi` 快路径要改**：`displayWidth` 修复后裸 ESC 计 0 宽，`displayWidth("abc\x1b") === 3`，`3 <= 3` 让快路径原样返回。这是修复 A 引入的回归，红测试当场暴露。
- 本轮禁区（&nbsp;/trim、CDATA、web 实体、gitignore、grapheme、formatTokens、insideRawDir、OSC）均未触碰；OSC 分支保持原样，裸 ESC 处理放在 OSC/CSI/两字符三个分支**之后**，不影响既有优先级。
