# 跨会话消息-v0.2.0

## 摘要

v0.2.0 交付 neo 的跨会话消息：多个前台交互式进程通过 `~/.neo/mailbox/` 文件信箱互发纯文本消息，支持任意会话派活/回信/多跳协作，人可随时进入任意终端叫停补话。没有固定 leader；每个会话维护可查询的状态机与委派台账，发起方每 120s watchdog 检查接活方是否死亡/停滞/跑完不回信；消息在工具间隙（P1）或空闲 tick（P2）注入并自动开 turn。规格为 `docs/cross-session-messaging-prd[done].md`（2026-10-20 两轮裁决后的 v1.2）。

> 最后更新:2026-10-20

## 用法

- 交互式 `neo` 启动即启用信箱；`-p` / 非交互不参与。
- `/rename <name>` 或 `--name <n>` 给会话起名；撞名自动 `-2` 后缀，dead 会话名字可复用。
- 模型工具：`send_message(target, body, reply_to?)`、`list_peers(target?)`；人类命令：`/peers [name]`、`/inbox`、`/inbox release <id>`、`/rename`。
- 回信带任务号：`reply_to` = 原消息 id；宿主按 receipts 自动填 `exec`（开始/结束/ms），发起方台账精确消账，不需要模型自己报时。
- 人工接管：任意终端 ESC 叫停；自动 turn 被 ESC 中止时不回滚历史，人类自己输入的 turn 保留回滚；补话后继续并回信上游。
- 交互 `/resume` 切换 session-id 时信箱身份同步改键；目标已 dead 则接管（按裁决丢弃未读），仍有活进程则拒绝迁移。

## 关键裁决（2026-10-20）

- **对等组网**：任何会话可发起/承接/多跳；`leader` 只是名字，不是进程属性。
- **ESC 裁决 A**：自动 turn 只停不删；人类输入的 turn 保留回滚。
- **失联检测**：watchdog 120s；心跳 15s；120s 无心跳判 dead；working 300s 无进展判 stuck；`outstanding` 区分「在等别人」与「跑完不回信」。
- **身份**：只认当前 session-id；进程没了就没了，未读不补投；投递 at-most-once。
- **-p**：不启用信箱（不建目录、不注册工具、不跑 tick）。
- **自动 turn 上限**：默认 20，每会话独立计数。

## 已知边界

- supervisor / 后台会话 / attach / agent view / 跨机留 v0.3。
- 多跳环靠每会话自动 turn 上限 20 + 发送端限流 + 接收端去重，无全局环检测。
- `reply_to` 缺失时退回「同 target 最早未回」近似；建议回信始终带任务号。
- 真实双终端 + 真实 LLM 的编排验收仍需人工在 TTY 下跑（单测用注入时间与 fake 消息覆盖）。
