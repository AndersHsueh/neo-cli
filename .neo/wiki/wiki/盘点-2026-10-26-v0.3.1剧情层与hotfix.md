## v0.3.1 剧情层（主体交付）

### 随机会话代号

- 池固定 12 个：`neo · Trinity · Morpheus · Cypher · Niobe · Seraph · Oracle · Switch · Tank · Link · Ghost · Keymaker`；
- 优先级：`--name` > resume 旧名 > 池内随机（只避开 running）> 池全占才 `pickUniqueName` 后缀；
- 撞名**换下一个随机候选**，不直接加后缀；`neo` 是普通可寻址名字；
- mailbox 失败：本地随机名只用于标题显示，不落盘/不寻址；
- `/rename` 不变，改名后顶线即时同步。

### Agent 标题 + Neo 动画

- 顶线 `Agent: <代号>`；`Agent:` 固定 dim，普通名 dim，`N E O` 用 Matrix 绿 #00FF41；
- 名字 `neo`：开局 `Mr.Anderson`，每 10–20s 随机切换；切换前 3 帧 ×80ms 字符雨，
  每帧都未收敛、显示宽度锁定目标；busy 后缀 ` · 运行中` 照常；
- `TitleAnimator` 注入 rng/now/setTimeout（fake timer 单测），timer unref，composer start/stop
  统一启停；只重画 live 帧，不动输入 buffer/cursor。

### 为名字池先修 resume

- `--resume si-123` 沿用原 session-id / 会话文件 / 信箱身份；交互 `/resume` 用 `mailbox.adopt()`
  接管目标 name/inbox，退役当前身份；
- running = `.alive` + pid 存活 + 心跳 ≤ `deadAfterMs`（默认 120s）；pid 死或心跳超时 → 立即回收
  残留锁；运行中会话拒绝恢复、`--resume last` 跳过、`/resume` 与 `/sessions` 不列出；
- `--resume si-123 --name X` 改名；cwd 保持当前启动目录并提示；
- 名字解析：`resolvePeer` 同名多命中时优先 running，且名字优先于 session-id 片段（避免 `neo`
  被 base36 id 抢走）。

## 三轮 resume 并发 hotfix（今日最重要的教训）

### v0.3.2：抢锁失败会覆盖存活 profile

- 现象：`createIdentity` 先 `writeProfile` 再抢 `.alive`；两个终端几乎同时 `--resume` 同一会话时，
  失败方在抛 `session_alive` 前已把存活方 profile 的 name/cwd/mode/pid 覆盖。
- 修法：`acquireAlive` → `writeProfile`（失败回滚锁）；`.alive/owner.json` 记录 `{pid, at}`
  识别「锁已建、profile 未写」的启动窗口。
- 回归：`R2h`（同 id 再 createIdentity 抛错后 profile 不变、owner 不被抢）。

### v0.3.3：两个 check-then-act 窗口

1. **index 把 resume 身份失败当“信箱降级”继续跑**：`sess` 已 adopt 原 id，后续 persist 会双写
   同一会话文件且 exit 0。修法：resume 命中时 `createIdentity` 失败 = 致命 `return 2`；只有
   新建会话允许降级。
2. **owner 保护被心跳条件门住**：`startingFresh = !isFinite(heartbeatAge) && ownerFresh`；
   崩溃残留的 state/profile 都是旧文件（age 永远 finite）→ owner 新鲜也判 dead，P2 会接管 P1。
   修法：`running = pidAlive && (heartbeatFresh || ownerFresh)`；无 owner/profile 但心跳新鲜 →
   保守拒绝；pid 死或心跳+owner 都超时 → 回收。
- 回归：`R2i`（owner 新鲜 + 旧心跳不得接管）、`R2j`（无身份 + 新鲜心跳保守拒绝）、R2e/F5
  改为“心跳与 owner 都旧才 takeover”。
- 证据：`docs/evidence/v0.3.3-owner-red.txt`（v0.3.2 `took-over` 写走 `Neo//intruder`；
  v0.3.3 `blocked` 保持 `Trinity//orig`）。

## 今日踩坑与经验

1. **resume 的“身份”必须只有一个来源**：会话文件 id、mailbox profile、memory bridge、UI 标题要
   指向同一个 session-id；任何一处“先写后抢锁/先预检后失败降级”都会变成并发双写。
2. **check-then-act 必须用文件锁内的 owner 元数据兜底**：只靠 profile pid/心跳会在启动窗口失效；
   owner 新鲜应独立成立，不能依赖 `heartbeatAge` 是否缺失。
3. **失败要致命，不要“降级继续”**：新建会话可以没有 mailbox；resume 没有身份就没有写会话文件的
   资格。v0.3.2→v0.3.3 最贵的 bug 就是 continue-on-error。
4. **名字池依赖寻址口径**：dead 会话名不能遮蔽 running；名字匹配要优先于 id 片段；`pickUniqueName`
   与 `takenAliveNames` 必须共用 `sessionLiveness`。
5. **PTY 测试要防随机与动画**：S19 最终改为显式 `--name Trinity` 再 `/rename neo`，busy 窗口
   `slow-800`，S18 先 waitFor 再 waitExit；标题 finder 从 `neo ·` 改为 `Agent:`。
6. **banner 空行在 dock 下要用空格行**：wrapAnsi 丢弃尾部空串，纯空行会消失。
7. **已发布 tag 不移动**：v0.3.1 发布后发现问题，用 v0.3.2/v0.3.3 hotfix 前进，历史保留。
8. **版本双源 + evidence 前缀**：每次 hotfix 都 bump `package.json` / `src/index.ts` / `verify.sh`
   前缀，避免证据文件互相覆盖。
