# 重构-1116：档位纪律抽成共享工具（v0.4.16）

## 摘要

v0.4.13/14/15 连续三次修的是同一类缺陷——`toFixed`/`Math.round` 把档内值进位到档边界（`9_999 → "10.0k"`、`59_950ms → "60.0s"`、`1023.95K → "1024K"`），输出跨档且与下一档撞值。三次各修各的，纪律只写在注释里，`formatElapsed`/`formatDuration` 的 `m:ss` 拼装还各有一份。v0.4.16 抽出 `src/ui/format.ts`（`fixed1`/`fixed1Raw`/`rounded`/`clock`），四个调用点改为复用，**行为零变化**（纯重构）。全量 1093 pass / 0 fail，tsc 干净。

## 关键教训：`fixed1` 的「≥10 转整数」不是通用一位小数语义

第一版把 `fixed1` 直接用在时长秒档，`12_340ms → "12s"`、`59_940ms → "1:00"`，`tests/toollog.test.ts` 两条用例立刻红。

根因：`fixed1` 的降级阈值是 **10**（token/bytes 的档内规则：<10 一位小数、≥10 整数），而时长秒档要一直保留一位小数，升档阈值是 **60**。阈值不同就不能共用一个降级函数。

修法：拆成 `fixed1`（降级到 10）与 `fixed1Raw`（纯 toFixed，不降级），`tests/format.test.ts` F2c 专门钉住两者在 10~60 区间的分歧点。

**通用教训**：抽取「看起来一样」的格式化逻辑时，先确认边界阈值是否相同；阈值不同就是不同函数，硬合并会在边界值上炸。
