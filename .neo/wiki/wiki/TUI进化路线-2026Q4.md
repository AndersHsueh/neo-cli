# TUI进化路线-2026Q4

> 最后更新:2026-10-25

## 摘要

v0.2.3 交付前的两路只读调研（neo 代码核查 + 2026 年终端 agent TUI 横评）给出的路线：neo 的渲染模型（inline + append-only + 终端 scrollback）已经是 2026 年 Claude Code classic / Codex 默认的选择，**不需要换引擎**；后续价值在「输入层 → 常驻状态 → 进程托管」三段。本页是分档路线与不做清单，作为 [[TUI补漏-v0.2.3]] 的下一跳。

## 一、2026 年 TUI 情况的三个事实（决定路线）

1. **inline 是主流默认**：Claude Code 2.1 保留 classic inline 并另开 fullscreen 研究预览（`/tui` 热切、失败自动回退、`Ctrl+O`→`[` 把会话回灌 scrollback 作逃生门）；Codex 也是 inline 默认 + `--no-alt-screen` 可选。纯全屏是 OpenCode(Bubble Tea) / Crush 的选择。
2. **全屏的代价有据可查**：丢 `Cmd+F` 与 tmux copy mode；OpenCode 至今没有会话内搜索（issue #4714，74 👍），社区在要求 REPL 模式（#4355）；Codex 的 `--no-alt-screen` 路线留下了一串 scrollback bug（#10331 / #14277 / #20063）。
3. **底部常驻栏在 inline 下的现行解法**是「底部区整块重绘 + 光标上移 N 行打补丁」（Claude Code 的 TUICommander 逆向结论），代价是 N 随状态行数变化，宽字符/换行错一格就串屏 —— 这是它 bug 多的结构性原因。

## 三、明确不做（附理由）

- **默认全屏 alt-screen**：丢 scrollback，且逃生门成本高（状态迁移 + 失败回退）。
- **statusLine 做成 shell 脚本 + JSON**（Claude/Codex 的路）：代价是外部工具读不懂，被 TUICommander 明确写进文档「custom status lines are never a detection signal」；neo 应做成内部组件 + 另开 `neo agents --json` 机器可读出口。
- **默认鼠标捕获**：破坏终端原生选区和 tmux/OSC 52，Claude 官方称其为「最常见摩擦点」并提供 `CLAUDE_CODE_DISABLE_MOUSE` 逃生门。
- **审批弹窗压在历史之上**：Codex #47865 至今开放（弹窗期间不能滚、不能 `Ctrl+T`），必须让审批叠在可滚动历史之上。
- **音频/桌面通知**（OpenCode 的 attention）：非必需，且有 tmux OSC 兼容成本。

## 四、判断方法（留给下次）

- 任何 TUI 改动先问：**会不会丢已有信息**（覆盖、截断、清屏）？这次 v0.2.3 的 5 项全是这一类。
- TTY-only 行为**必须真 PTY 断言**：`scripts/pty-e2e.ts` 已是仓库内可复用脚本，新增场景优先于新增手工验收。
- 不要凭会话 JSON 推断屏幕行为：v0.2.3 的最大教训是「会话里有 2901 字正文」被误读成「正文没上屏」，实际是流式状态泄漏导致的 `●` 前缀缺失。
