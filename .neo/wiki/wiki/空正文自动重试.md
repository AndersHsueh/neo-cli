# 空正文自动重试

## 摘要

推理模型（glm-5.3-flash 等）偶发只返回 `reasoning_content` 而 `content` 为空的退化响应。neo 在 agent 主循环中加入「区分原因 + 自动重试一次」机制（src/agent.ts）。**v0.4.1 起第二次仍空不再 warn 后静默放弃，而是按 `hadError`/`emptyResponse` 错误收口**，并写入轮次诊断日志与 `session.meta.lastTurn`。

> 最后更新: 2026-10-27

## 触发条件与原因区分

原实现（agent.ts 旧 502-504 行）只打一行 info 并把空 assistant 消息写入历史。现行为：

- `finishReason === "length"` → 「输出预算被思维链耗尽」，提示用户调大 max_tokens（README.md:245 记录过的坑：推理模型思维链本身吃几十 token）。
- 其余（通常 stop）→ 模型把答案全写进思维链通道，content 通道为空（classifier/llm.ts:109 记录过同类现象）。
- reasoning 也为空 → 空响应。

## 重试机制

- 检测到无工具调用且 content 为空：追加一条 user 提示（要求把最终答案作为正文输出）后 `continue`，**至多重试一次**（`nudgeMsg` 非 null 即视为已重试，防死循环）。
- `finishReason === "length"` 时，第一次重试会临时把 `max_tokens` 翻倍（封顶 64k），只作用于重试请求；正文成功或带工具调用后复位。
- 重试成功：摘除提示消息，正常写 assistant 正文。
- **重试仍失败（v0.4.1 起）**：`emptyResponse=true`、`hadError=true`、写明确 `errorMessage`，UI 打印错误并 `onEvent error`；提示消息与临时预算提示都摘除，历史不写空 assistant。
- **不再写入空 assistant 消息**：空回复留在历史里，部分服务端会拒绝该消息序列，对模型自身也是错误示范。
- **循环结束兜底**：若一轮因溢出恢复/迭代上限结束但从未产出最终正文，也同样置 `hadError`（错误：本轮在重试/迭代上限处结束），不再静默 `ok`。

## 关键实现细节

- 重试提示与预算提示共用 `dropTransientMessage`（原 `dropBudgetMessage` 改名），按引用比对摘除。
- 每轮请求前预算提示会注入一条 system 消息，因此重试请求的消息数是 system + user + nudge + 预算提示 = 4 条，测试断言时容易漏算预算提示这条。
- `runSubagent` 的报告提取只认非空 assistant 消息（tools/task.ts），不写空消息的改动对其无副作用；子代理空报告仍返回「子代理未产出任何报告」说明文案。

## 测试

tests/subagent.test.ts「空正文自动重试」区块覆盖：重试成功后提示摘除、重试仍失败按错误收口且历史干净、length 场景针对性提示。`tests/turn-reliability.test.ts`（v0.4.1 新增）用 fakeStream 锁住「连续两轮空 → hadError/emptyResponse + 诊断日志」与「第二次请求放大 max_tokens」。
