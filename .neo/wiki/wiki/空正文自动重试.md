# 空正文自动重试

## 摘要

推理模型（glm-5.3-flash 等）偶发只返回 `reasoning_content` 而 `content` 为空的退化响应。neo 在 agent 主循环中加入「区分原因 + 自动重试一次」机制（src/agent.ts `run()`）。

> 最后更新: 2026-10-18

## 触发条件与原因区分

原实现（agent.ts 旧 502-504 行）只打一行 info 并把空 assistant 消息写入历史。现行为：

- `finishReason === "length"` → 「输出预算被思维链耗尽」，提示用户调大 max_tokens（README.md:245 记录过的坑：推理模型思维链本身吃几十 token）。
- 其余（通常 stop）→ 模型把答案全写进思维链通道，content 通道为空（classifier/llm.ts:109 记录过同类现象）。
- reasoning 也为空 → 空响应。

## 重试机制

- 检测到无工具调用且 content 为空：追加一条 user 提示（要求把最终答案作为正文输出）后 `continue`，**至多重试一次**（`nudgeMsg` 非 null 即视为已重试，防死循环）。
- 重试成功：摘除提示消息，正常写 assistant 正文。
- 重试仍失败：warn 后放弃，提示消息同样摘除。
- **不再写入空 assistant 消息**：空回复留在历史里，部分服务端会拒绝该消息序列，对模型自身也是错误示范。

## 关键实现细节

- 重试提示与预算提示共用 `dropTransientMessage`（原 `dropBudgetMessage` 改名），按引用比对摘除。
- 每轮请求前预算提示会注入一条 system 消息，因此重试请求的消息数是 system + user + nudge + 预算提示 = 4 条，测试断言时容易漏算预算提示这条。
- `runSubagent` 的报告提取只认非空 assistant 消息（tools/task.ts），不写空消息的改动对其无副作用；子代理空报告仍返回「子代理未产出任何报告」说明文案。

## 测试

tests/subagent.test.ts「空正文自动重试」区块 3 条：重试成功后提示摘除、重试仍失败放弃且历史干净、length 场景针对性提示。原「子代理未产出报告」测试因重试消耗第二次调用而补了第二个 step。
