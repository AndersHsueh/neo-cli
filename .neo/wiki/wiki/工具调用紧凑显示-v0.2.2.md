# 工具调用紧凑显示-v0.2.2

## 摘要

v0.2.2 把交互式终端的工具调用显示从「每条 header + 缩进结果块」改为**默认单行原地更新**：`⚡ name args .`，`.`/`..`/`...` 每 350ms 循环表示运行中；下一条工具调用回到行首覆盖上一行；完成后尾标变 `✓`/`✗`（失败附首行错误摘要）。设置 `toolcall_info_details: true` 可恢复旧版详情；非 TTY（`-p` / 管道 / CI）始终保留逐行详情，避免动画控制符污染日志。动机是真实双会话里一次任务连续 7 次 `list_dir`，工具块把关键信息冲散。

> 最后更新:2026-10-20

## 设计

- **一行一个工具调用**：不再为每次调用保留历史行，屏幕空间不随工具调用次数增长。
- **动画只用点号**：`.`, `..`, `...` 三档循环，不用 spinner 字符，避免与「连接中…」spinner 混淆。
- **失败保留摘要**：`✗ 错误: ...` 截断到单行（按显示宽度，CJK 不超宽）；成功不打印正文。
- **输出边界**：模型正文 / spinner / 审批问句出现前自动换行收尾，避免 `●` 与工具行粘连。
- **非 TTY 不紧凑**：动画依赖 `\r` + ANSI 清行；管道/日志场景保留旧版详情，可读性优先。

## 配置

```json
{ "toolcall_info_details": false }
```

默认 `false`（紧凑）；`true` 恢复旧版。兼容连字符写法 `toolcall-info-details`。

## 验证

- `tests/toolcall-display.test.ts`（7 例）：点号循环、✓/✗、长参数 / CJK 错误摘要的显示宽度收敛、配置默认值与别名。
- PTY 渲染实测：紧凑模式最终屏幕只有一行工具行（下一条覆盖上一条），工具结果正文不出现；`toolcall_info_details: true` 时旧版 header + 结果块正常。
- 全量 **530 pass / 0 fail（27 文件）**，tsc 零错误。
- 发布说明：`docs/release-notes/v0.2.2.md`。

## 已知边界

- 紧凑模式下工具错误只保留首行摘要；需要完整错误时打开 `toolcall_info_details`。
- 工具执行期间若有审批/通知输出，当前工具行会先收尾换行，结果状态另起一行。
- 非 TTY 不做紧凑（日志优先）。

## 真实验收（2026-10-20 晚）

两个真实前台进程 `anders` ↔ `huan` 的跨会话验收中，工具调用区域从多行刷屏变为单行覆盖：anders 侧一轮 2 次工具调用只占一行（`⚡ send_message … ✓`、`⚡ list_peers … ✓`），关键对话信息不再被冲散。用户反馈：「现在看起来清爽，又迅速。」完整当日记录见 [[里程碑-1020]]。
