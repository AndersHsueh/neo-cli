# 修复-1107-formatBytes 末档 P 单位没除

> 最后更新:2026-11-07

## 摘要

2026-11-07（v0.4.47）。`formatBytes`（`src/env/render.ts`）在 P 档（末档）**所有 ≥1P 的值都被放大 1024 倍**：`1024**6`（= 1P）→ `"1024P"`、`2*1024**6` → `"2048P"`、`1024**7` → `"1048576P"`。两处叠加：① 循环条件 `i < units.length - 1` 使 v 在 T 档时若 `>= 1024` 就**直接退出**，v 仍是 T 档数值、标签却已是 `P`；② 末档缺「≥10 整数」那一半（`fixed1` 只降级 10.0，不收 1024.0）。修法：末档返回前按 `v < 1024` 判断 v 的来源，决定是否再除一次。`bun test` 1156 pass / 0 fail（3654 expect，+6），`tsc` exit 0。未 commit。

## 推理与依据

### 为什么 v0.4.46 把它误判为「不是缺陷」

v0.4.46 的排除记录写「`1024**6 → "1024P"`，1024 进制下 P 档档宽就是 1024，`1024P` 是档内合法值」。这个推理的**依据是输出本身**，而 `1024**6` 恰好就是 1P —— 那个输出正是缺陷产物。`1024P` 确实合法，但它对应的输入是 `1024**7`。

教训：判断「档内合法值」必须拿**真实单位值**（这里 `c / 1024**6`）做对照，不能拿函数自己的输出反推。本轮探针就是这么做的：

```
1152921504606847000 => 1024P | true P value: 1        ← 缺陷
2305843009213694000 => 2048P | true P value: 2        ← 缺陷
```

### 修法为什么不能一律 `v / 1024`

第一版改动直接写 `return ${fixed1(v / 1024)}${units[i]}`，探针立刻暴露回归：`1024**5`（= 1P）→ `"0.0P"`。因为 v 到末档有**两条路径**：

- 循环因 `i < units.length - 1` 结束：v 已除到 P 档（`1024**6` → v = 1），不该再除；
- 循环因 `Number(text) >= 1024` 结束：v 仍是 T 档的值（`1024**5` → v = 1024），必须除。

判据 `v < 1024`：已除到 P 档的 v 必然 < 1024，否则上一步会继续除。这是**探针先于改动**救回来的一次 —— 只看代码推断会漏掉第二条路径。

### 与 formatTokens 的同构

v0.4.45 修的是 `formatTokens` P 档「漏了整数档那一半」；本轮是 `formatBytes` 同一类缺陷，外加单位换算没落地。两处末档现在口径一致：<10 一位小数，≥10 整数，无处可升。

### 验证

- 红测：改前 `formatBytes(1024**6)` 实际 `"1024P"`，期望 `"1.0P"`
- `bun test`：1156 pass / 0 fail / 71 files，3654 expect（v0.4.46 为 3648，+6 = 本轮新增断言；断言都在同一 `test()` 内，故测试条数不变）
- `bunx tsc --noEmit`：exit 0
- 证据：`docs/evidence/v0.4.47-tests.txt`、`docs/evidence/v0.4.47-full-tests.txt`、`docs/evidence/v0.4.47-tsc.txt`
- 改动文件：`src/env/render.ts`、`tests/env.test.ts`、`docs/release-notes/v0.4.47.md`

### 影响面

`formatBytes` 用于系统提示词「资源」行（内存总量）、`/env` 命令、wiki 环境页的磁盘总量。1P 内存今天不常见，但 NAS / 大容量阵列的磁盘总量进 P 档完全可能，届时 `/env` 会显示差 1024 倍的数字。

### 本轮仍排除的候选

- **末档封顶口径**：`formatBytes(1e300)`、`formatTokens(1e300)`、`clock(1e300)` 仍漏科学计数法。属改口径，需单独决策。
- **C1 控制字符**（`\x9b`/`\x9d`）：需先确认剥除范围口径。
- **三处 ANSI 剥离合并**：属重构。
