# 热键系统 v0.1.2+ — ESC 中止回滚 + Ctrl+C 双击退出

> 最后更新:2026-10-18

## 摘要

补上运行中放弃本轮的能力:按 ESC 取消当前轮并把历史回滚到本轮开始(含 user 消息),面向「输入错了要重来」;Ctrl+C 改为双击退出(模仿 Claude Code),第一次按下底部闪现 2 秒橙色提示 `Press Ctrl+C again to exit`,窗口内再按才退出。新增 `src/hotkeys.ts` 作为用户按键的唯一入口,以后加方向键等热键只需一行 `on("up", ...)`。commit `8c08cdc`,随 v0.1.3 发布(annotated tag 已推 gitee)。

## 1. 行为语义(最终态)

| 按键 | 空闲 | 运行中 |
|---|---|---|
| ESC | 无操作(留给将来) | 取消本轮 + **历史回滚** + 回提示符 |
| Ctrl+C ×1 | 橙色提示 2s | 中断请求(**半截历史保留**) + 橙色提示 2s |
| Ctrl+C ×2(2s 内) | 退出 | 退出 |

**两种中断不同语义,是刻意的**:ESC 回滚(输错了重来,残缺历史不该留下);Ctrl+C 不回滚(跑了几十轮工具的进展不该被误按丢掉)。

## 2. 核心认知:readline 与 raw mode

方案阶段最大的认知修正 —— **readline 在 TTY 上默认就是 terminal 模式,stdin 本就全程处于 raw mode**,行编辑(退格/方向键历史)是 readline 自己在 raw mode 里解析按键实现的。因此:

- 挂 `rl.on("keypress")` 是公开扩展点,**不存在**抢字节流、重复回显的问题
- `ui/console.ts` confirm 注释警告的「另开 raw-mode stdin 监听」指的是 `stdin.on("data")`,keypress 不属于此列
- 转义序列不用自己解析:readline 已解析好,`key.name === "escape"/"up"/...`、`key.ctrl` 直接可用

## 3. 职责划分:信号语义 vs keypress 语义

Ctrl+C/Ctrl+D 走 SIGINT 信号路径,**不经 keypress** —— 否则运行中一次 Ctrl+C 会同时触发信号与 keypress 两路,提示错乱。其余按键(ESC、方向键)走 `HotkeyRouter`。

| 组件 | 职责 |
|---|---|
| `neo/src/hotkeys.ts` `HotkeyRouter` | keypress → 语义键映射(`mapKey`),ctrl/meta 组合不认 |
| `neo/src/hotkeys.ts` `doubleStrike` | 双击确认状态机,窗口超时自动解除武装 |
| `neo/src/index.ts` `onSigint` | Ctrl+C 双击退出,挂 SIGINT 路径 |
| `neo/src/agent.ts` `send(input, {rollbackOnAbort})` | abort 返回前把 `messages.length` 截回本轮开始前 |
| `neo/src/ui/console.ts` `flashNotice` | 橙色闪现,超时清行并重打提示符 |

## 4. 测试基建教训:mock.module 泄漏(实测复现)

第一版 Agent 回滚测试用 `mock.module("../src/llm.ts")` 注入假 `chatStream`,并把 `estimateTokens` mock 成常数 —— 结果**污染了同进程后执行的 `skill-budget.test.ts`**(它真用 `estimateTokens` 算预算),M4 假失败。单文件跑不挂、全量跑才挂,是典型的模块表泄漏症状。

**结论:bun test 单进程共享模块表,`mock.module` 是进程级副作用,不要在共享模块上用。** 正解是给被测类开构造注入点 —— `AgentOptions.chatStream?: typeof chatStream`,缺省回落真实实现。这也顺手让 Agent 变得可测。

另一个测试细节:`AbortSignal` 上没有 `abort()`(在 controller 上),mock 里触发取消要走 `agent.cancel()` 真实路径,别试图直接调 signal 的方法。

## 5. 已知边界

- `escapeCodeTimeout` 未调(保持默认 500ms):独立 ESC 响应稍钝,但方向键序列解析稳。实测若嫌钝再调 50ms
- `flashNotice` 清行用「回车+清行+重打提示符」,2 秒窗口内用户打字可能轻微错位,窗口极短,接受
- 非 TTY(管道/CI)下 `flashNotice` 与 ESC 均自动 no-op
